# 主框架四条独立清单线

2026-10-17 起，四线分别认领 [双项目清单](TWO-PROJECT-WORKLISTS.md) 中不同的主框架条目，不再把同一小功能拆给四线。共同起点为 `3286bfd7526d79b314180022da68df9a7e462956`。插件项目的 PF-01—PF-06 保持独立，由用户协调合流。

| 线 | 独立清单与目标 | 工作树 / 分支 | 独占文件范围 | 交接 |
| --- | --- | --- | --- | --- |
| A | MF-01 主窗口壳、菜单工具栏、窗口/DPI、全局运行模式 | `worktrees/framework-shell` / `codex/framework-shell` | `MainWindow.xaml`、Shell/菜单/工具栏相关 partial 和样式；不改画布、Group、插件配置宿主 | 先沿原始命令入口查事件、状态、后端和资源，再实现可运行的完整命令；不以图标相似冒充功能 |
| B | MF-02 工作流 Tab、节点/连线、画布与小地图 | `worktrees/framework-canvas` / `codex/framework-canvas` | `WorkflowTabs.cs`、画布/手势/连线/小地图相关 partial；共享文档模型需求走请求 | 一项交互必须核对鼠标状态、撤销/保存和实际画布结果 |
| C | MF-04 Group 所有权、内部画布、循环中断累积、流程 IO 与局部变量 | `worktrees/framework-group` / `codex/framework-group` | `Group*.cs`、Group 专项窗口/测试；共享执行器或契约变更先登记 | 以真实节点结果验证 Group 数据与 UI，不把测试节点当工具还原 |
| D | MF-05 图/流程执行、方案存储、原生方案格式研究、事务与释放 | 主工作树 `main` | `SolutionExecutor.cs`、`SolutionStore.cs`、执行/存储专项测试和证据；不改前三线 UI 文件 | 兼容格式必须有原厂样本、原生代码与往返证据；独立格式明确标识 |

MF-03 工具箱装载与插件生命周期需要 PF 清单的元数据契约，由 main 集成时单独认领；MF-06 最终验收由主工作树串行执行，不作为第五条开发线。四线都先读原始反编译/资源/运行证据，记录源码确认、独立实现和未验证原生行为。每线在自己的工作树按完整功能闭合中文提交，主线审查、顺序合入、构建与实际操作验收；跨线共享文件只有一位集成所有者，不能互相改工作树或覆盖在制修改。测试/截图辅助留在 tests，报告写在本线工作树。用户决定何时与插件分支合流。
