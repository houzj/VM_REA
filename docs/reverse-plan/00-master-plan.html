01范围与边界

做什么

  • 全量目录工具身份、分批与逐工具取证动作
  • 框架具名单元的源码、实施、验证三层闭环
  • 入口到执行效果的六段闭合链
  • 共享契约、依赖接力与阶段门禁

不做什么

  • 原厂未取证行为的合理设计填空
  • 真实设备操作与未授权并行派工
  • 不经台账复算的手改页面数字
  • 自动提交、推送或跨工作树合入

完成定义

  • 按具名单元计：源码判据、实施判据、验证判据各有台账证据
  • 整工具完成按源码级重建并通过自审计，人工验收单列
  • 操作级验证记录可复跑；历史记录未在本次复跑的须注明
  • 差分、unknown 与有限 parity 边界必须保留，不抹平

责任边界

框架线拥有工具无关外壳、画布、Group、方案生命周期与共享契约；工具插件线拥有工具专属源码恢复与实现；用户决定优先级、集成时点与手工验收结论。

阶段门 G1–G8 与入口门 E0–E7 的规则原文见门禁与证据页；本页只登记其在总计划中的位置。

02执行规则与计划状态机

  • 先固定原件身份与 SHA-256 / MVID，再取具体类型、成员的反编译源码与 CIL
  • 逐链追踪入口→绑定/命令→状态读写→事件/回调→持久化或执行效果→异常/清理
  • 缺失函数体、资源、ABI 或时序证据时用 REA 补证；仍缺则标 unknown
  • 用户反馈与截图只作差异信号与验收输入，不作实现规格
  • 独立实现与源码确认分开陈列；测试通过不推出原厂 parity
  • 人工主机验收独立，既不阻塞也不计入实施完成度
计划状态机：独立编排，不等于证据四态，也不改写台账三层状态
状态ID判定规则
未开始not_started台账无该卡的取证或实施交付证据
取证中evidence已定位原路径与成员，正在补齐调用链、资源、CIL 或 ABI
实施中implementation依据已确认边界落地本地实现，机制差异单独标注
自审中self_review实现已交付，正在按操作级验证与退出判据复核
已闭done源码、实施、验证判据齐全且自审通过，人工验收另列
阻塞blocked有明确缺少条件，记录阻塞 ID 与解除条件
未知unknown证据不足以判定行为，登记 REA 补证目标
  • not_started → evidence → implementation → self_review → done
  • blocked 与 unknown 为旁路：解除阻塞或补证后回到 evidence，不直接跳 done
  • 任何状态回退必须保留原证据与失败记录，不覆盖历史结论
任务卡中的取证清单、第一动作与退出判据是计划动作（独立编排），不是原厂源码确认结论；不得与证据四态混用。

03阶段门、证据四态与派工入口

阶段门 G1–G8（规则原文见门禁页）
门禁名称规则
G1分母冻结任何页面数字必须来自机器台账；分母或排除规则变化必须提升 schemaVersion 并登记原因。
G2证据四态每个结论标注四态之一；缺失证据标 unknown，不得以用户反馈或截图代替规格。
G3调用链闭环入口→绑定/命令→状态读写→事件/回调→持久化或执行效果→异常/清理，缺一段不算闭合。
G4原生 ABI包装器只改写 RCX 时须检查 RDX/R8/R9 活跃性并记录真实入口寄存器，不采纳伪代码签名推断。
G5独立实现隔离独立实现与源码确认的结论分开陈列，不能从测试通过推出行为等价。
G6整工具计分工具完成按整工具源码级重建 + 自审计，人工验收单列，不参与完成度。
G7操作级验证每单元保留操作级验证记录；历史记录未在本次复跑的须注明未重跑。
G8确定性重跑站点不写 wall-clock；输入哈希与 HEAD 构成 builtFrom，重跑字节一致。

状态判定规则可陈述范围

运行确认在已确认的运行环境或原程序上取得可复核的运行时输出、状态或事件顺序。可以陈述该次运行的可观察结果
