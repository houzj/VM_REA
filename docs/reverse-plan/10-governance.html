01变更控制

  • 统计数字只改账本与生成器，禁止手改 HTML 页面
  • 判断性内容（归层、canonical pass、优先级）只改映射表并写明数据依据
  • 分母或口径变化必须提升 schemaVersion、记录日期与原因，并全站重跑
  • 阶段顺序固定为「先切片后铺开」；S4 之后如需层内并行，必须在 plan-data.json 登记例外
  • 口径冲突只做显式登记，未经用户确认不擅自二选一
HTML 是产物，不是真相源。任何数字改动必须先改台账与生成器，再全站重跑并跑独立校验。

02责任边界

两条工作线 + 用户；跨工作树改动必须走合同请求，不静默合入
#边界
1框架线：WPF 外壳、流程画布、Group、方案生命周期、持久化、调度与框架级数据契约
2工具插件线：工具专属源码恢复与实现，读取全局架构模型并提出具体依赖请求
3用户：决定两条线的任务优先级、集成时点与手工验收结论

03禁止项

  • 禁止修改另一工作树或静默合入未提交改动
  • 禁止把截图/导出辅助代码放进产品程序集
  • 禁止从通过测试直接声称完整 parity
  • 禁止用合理设计填补缺失函数体、资源或 ABI 证据
  • 禁止以目录存在证明插件可加载或功能可用
  • 禁止自动提交或推送代码
本站点生成与校验不自动提交、不自动推送、不修改另一工作树。
