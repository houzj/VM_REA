The source below is a concrete data-flow inventory, not proof of a fully verified signature.

Parent `befdc0` chooses this path when either working dimension<64. Inputs are image/stride, mask/stride, packed source size, angle in radians, packed destination size, then output pointers/scratch storage. It clears the two destination scratch planes, computes cosf/sinf, forms centered inverse coordinates, and scans destination rows by adding cosf/subtracting sinf per x and adding sinf/cosf per y. Source mask selection uses `(int)(coordinate+0.5f)`, whereas image interpolation uses truncation plus a clamped four-by-four neighborhood. A generic bilinear/nearest image warp would not reconstruct this path.

For selected pixels it evaluates the original separable four-sample cubic polynomials in float, adds0.5f, clamps to0..255 and converts to int32 then byte. Polynomial operation grouping is explicit in C; the fourth row is grouped differently from the preceding row expressions, so a generic reassociated polynomial helper is not yet justified. Needed raw PE constants are0x16c6814/6830/6834/6838/683c/6840/6844; only those read from the original should be used. x/y bounds, rounding order and zero-selected outputs must be verified from assembly, not mathematical cubic interpolation intent.

It writes both a destination scratch pixel and a contiguous selected-pixel buffer. Consecutive nonzero mask spans become0x18-byte records: row, start x, end x, selected-buffer offset, byte sum, squared-byte sum. The latter two accumulate int32 first, then are converted and accumulated into double when a span closes. Coordinates are subsequently rebased to the bounding crop. Output stores include cropped scratch pointers, destination stride, crop dimensions, center shift, sums, selected-pixel count and span count. Parent records these relative to the model base, including a0x40-byte per-angle header and selected records; this is the missing bridge between training bytes and search statistics.

The no-span path reads source-record state before a nonzero-span guard near the tail in decompiled C. Whether current caller guarantees a selected span after rotation is not established; do not fabricate a zero record or execute unknown empty-span ABI. This is separate from the earlier required-mask contrast predicate. The large-template>=64 path is inlined in `befdc0` with16.16 coordinate arithmetic; it must not be declared equivalent to this float/cubic path.

Current implementation remains ModelSlots, dot/normalization, limits and normalized1390 pyramid. Angle grouping has a fixed four-table original oracle and a pending production candidate; actual cubic sample/model sparse records and large-template records are not yet implemented. No full trained-model or search equivalence is claimed.
