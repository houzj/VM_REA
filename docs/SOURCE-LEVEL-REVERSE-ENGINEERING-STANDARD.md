# 源码级逆向与复刻标准

本标准适用于插件线后续所有节点。目标是让实现逐项追到原厂源码、XAML/资源和可复核的运行行为，避免按名称、界面截图或“常见做法”推测功能。

## 证据等级

每个结论必须标记为以下一种：

- **原厂源码确认**：反编译源码中的精确类型、成员、分支、调用顺序或常量；记录证据文件、行号/符号和 SHA-256。XAML、XML、模板、图片及其他资源同样记录原始路径和哈希。
- **原厂运行确认**：原厂程序的可复现输入、操作序列、输出/界面状态及采集记录。说明版本、宿主、依赖、输入数据和触发条件。
- **独立实现**：本项目自行实现或抽象的部分，记录实现文件和行为；不得将其写成原厂行为。
- **未确认**：证据缺失、原生依赖不可用、反编译还原不充分或原厂行为尚未复测。明确缺项，不用猜测填补。

用户反馈和截图是差异线索或验收结果，不单独构成行为规格。测试通过仅说明本项目检查通过，不自动升级为原厂源码/运行确认。

## 每个节点的必填审计项

1. **对象身份**：原厂模块 ID、程序集/版本/文件哈希、托管入口、原生入口与依赖；本项目注册状态和对应实现。
2. **配置 UI**：原始 XML/XAML/资源、控件类型、模板 key、字段名与顺序、默认值/范围/格式、绑定路径、可见/启用条件、用户数据回写方式、弹层尺寸与生命周期。每个字段能追到源定义和消费代码。
3. **事件与状态**：初始化、Loaded、选择/编辑/确认/取消、执行/连续执行、复位、关闭、持久化等事件；列出调用链、状态读写、异常和边界。
4. **运行逻辑**：输入/输出类型、参数读取、算法调用及顺序、原生互操作、结果映射、错误码/失败语义、资源释放。不得以 UI 声明推断算法行为。
5. **差异矩阵**：逐条列出源码确认行为、当前实现位置、差异、证据等级、修复状态和验证方式；没有证据的行为写“未知”。
6. **回归与验收**：源事实对应的独立检查、原厂差分检查和人工验收分开记录。记录命令、版本、结果与报告路径；不适用的设备测试明确排除。

## 实施顺序

原生ABI特别规则（2026-10-19原厂补证）：不能从反编译器显示的实参数量推出调用只传了那些参数。函数只改写RCX时，RDX/R8/R9可能原样保留供下游消费；须核对调用前指令、寄存器活性和实际入口寄存器。本次标定板SDK `0x2980` 的硬件断点确认name/value分别从RDX/R8传入算法，推翻旧“一参数导致值未传递”结论。不同函数/板型的参数块偏移也必须逐路径核验，不把未命中断点解释成参数不存在。

先核验原始证据及哈希，再形成源事实表；按差异矩阵实现；对每条有确定性证据的差异增加针对性检查；运行节点专属回归和公共框架回归；最后检查产品注册、实际宿主分发和人工验收状态。修复不能以“视觉相似”替代字段、绑定、触发与生命周期的源码追踪。

新增节点逆向暂停在已实现节点审计闭合之后。若某项因原厂证据不可获得而无法闭合，记录阻塞证据和范围，经审计台账明示后再决定是否继续；不得静默跳项。
