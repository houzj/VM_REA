## 推进与同步顺序

1. 先闭合 PF-001～009 的公共基础链路，以真实“标定加载”插件验证模型→状态→生产模板→文档事务→运行→公共窗口；N 点样本只用于复杂模板覆盖检查，未实现项不能隐藏。
2. 补 PF-010/011/012 的源码、资源和契约；同步主框架的类型系统、复合 I/O、数组索引、ROI、发现与注册实现，明确逐文件负责方后接入，避免两套合同。
3. 优先迁移 N点与 N图像；保留现有算法/原厂运行证据，重新验收配置 UI 和交互，再推进其他标定；坐标系最后。
4. 每个可验收节点先构建、回归、整理差异并启动清晰标记的新程序；用户人工验收后再中文提交和推送本分支。无设备测试，不以模拟服务作为设备证据。

每次同步记录：所属清单 ID、原厂依据、公共签名、共享文件、已实现/未实现边界、实际回归结果、提交标识及主框架确认状态。未提交的在制代码只同步设计和状态，不声称已合并或已可供 cherry-pick。
