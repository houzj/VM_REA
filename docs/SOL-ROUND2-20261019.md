## 新确认的样本结构

8个 `MoudleFrame` 条目均可由以下独立候选解析完整消费。该结论限定这8个样本，尚不是所有版本、加密方案或厂商序列化合同。

- 头0..3均为 `00000005`，其语义未知，不能命名为版本。
- 头4..7作为 BE uint32，等于逐条解析得到的记录数。
- 每条记录前256字节为名称槽；样本名称为 UTF16LE，首NUL结束。其后4字节为 BE uint32 载荷长度，然后为该长度载荷。
- 从偏移8开始按 `next = start + 260 + payloadLength` 迭代，8样本全部精确到 EOF，没有剩余字节、越界或计数不符。
- 此规则闭合外层记录边界，没有闭合 `.mdata` 载荷内部字段。

## 解析操作与证据

本轮专属本地目录 `analysis/full-audit/sol-round2-20261019/`：

- `scan.ps1` 与 `frame-inventory.json`：逐样本原件前后 SHA256、帧 SHA256、名字字节偏移、XML订阅原文。8个原件前后哈希一致。
- `parse-frame-candidate.ps1` 与 `frame-records-candidate.json`：记录级 Offset、Name、PayloadOffset、PayloadLength、Sha256、PrefixHex，以及整帧 Consumed/Length/Error；8样本计数一致且完整消费。
- `evidence-sha256.csv`：本轮生成证据与相关原始源码哈希。

候选算法：先要求帧至少8字节，读取头第二BE整数；逐条先验证剩余>=260，再取256字节名槽与BE长度，验证长度不超过剩余后哈希载荷并推进。最终检查计数及EOF；超限、截断、未知头、异常名称须保持Unsupported或明确差异，不静默修复。根任务可据此增补测试辅助脚本；本子任务没有修改共享脚本。
