# 框架并行任务边界（2026-10-17）

本页仅保留主框架内部可并行任务的历史建议。当前实际四线所有权、工作树及交接见 [主框架四条独立清单线](FRAMEWORK-FOUR-LANE-OWNERSHIP.md)。两个项目的职责以 [双项目任务清单](TWO-PROJECT-WORKLISTS.md) 和 [开发基线](TWO-PROJECT-BASELINE.md) 为准；用户直接协调两个项目。

**2026-10-17 边界更新：**此处原建议仅适用于 main 内部框架任务，不能作为插件线节点公共配置框架的排除规则。用户已授权插件线在自己的 worktree 修改必要共享文件；双方仍并行逆向。最新跨线主责、在制文件锁、交付与合流闸门见 [PLUGIN-FRAMEWORK-BOUNDARY.md](PLUGIN-FRAMEWORK-BOUNDARY.md) 和 [PLUGIN-FRAMEWORK-INTEGRATION-CHECKLIST.md](PLUGIN-FRAMEWORK-INTEGRATION-CHECKLIST.md)。主线不在插件线配置宿主/模板的同一文件上同时开发第二套实现。

| 任务线 | 可独立实施 | 依赖与禁止交叉修改 |
| --- | --- | --- |
| 数据与 Group 运行（当前 main） | Region/Components、复合叶字段、Group输入输出、累积与运行 | 独占共享契约和执行器；统一集成其他线请求 |
| 工作流编辑 | 画布选择/移动/对齐、连线、中点、插入、小地图 | 先确定画布文件所有权；文档模型需求写入 CONTRACT-REQUESTS |
| Shell 与导航 | 工具箱、流程Tab、菜单、窗口尺寸和布局 | 与画布线共享的 MainWindow 文件须先拆分并由 main 合入基线 |
| 原生证据与验收 | 反编译证据索引、资源模板、差异矩阵、独立验收程序 | 不修改产品文件；不覆盖其他线截图、测试输出或验收总表 |

每条开发线使用独立 worktree 和对话；不要在同一个 main 工作目录同时编辑。专属测试和报告写在各自工作树。跨线契约通过 CONTRACT-REQUESTS.md 登记，由文件所有者实现，用户决定集成节点；独立功能闭合后中文提交。原生未确认行为须保留未验证状态。当前两分支并非同一代码基线，不得假定可以直接快进。

启动前先检查未提交改动、明确具体文件列表和依赖提交。本文不表示已经完成主窗口拆分，也不表示已经启动并行开发。
