# 双项目独立逆向清单

更新：2026-10-17。用户决定优先级、验收与合流时点。原生源码证据、托管实现、实际产品操作和原厂同状态差分分别记状态；“测试通过”不能替代后两项。详细状态仍分别由主框架验收表和插件工作树 PF 清单维护，以下清单只指定**唯一主责和接口交接**。

| ID | 主框架 `main` 独立负责 | 与插件线的交接 |
|---|---|---|
| MF-01 | 主窗口壳、菜单/工具栏、状态栏、最大化/DPI、全局运行模式 | 只暴露工具配置入口和状态，不定义工具参数模板 |
| MF-02 | 工作流 Tab、增删复制切换、画布节点/连线/避障/小地图、输入手势 | 使用插件元数据绘制工具节点；工具的内部编辑器由插件线提供 |
| MF-03 | 工具箱外框、目录发现/装载、缺失插件和版本冲突、方案级插件生命周期 | 插件线交付工具清单、分类、图标、工厂与兼容声明；main 不二次实现工具注册规则 |
| MF-04 | Group 所有权、内部画布、循环/中断/累积、流程IO/局部变量及跨流程身份 | 插件线提供真实工具端口、参数/ROI和运行会话；main 验证 Group 消费 |
| MF-05 | 图执行与流程级调度、方案持久化、`.sol`研究、撤销事务、关闭清理 | 插件配置的专属持久化由插件线负责；合同经 FCR 登记后接入主运行链 |
| MF-06 | 最终 WPF 端到端集成、独立发布和框架验收表 | 仅在用户选择集成后执行，不能将插件未提交候选算作 main 完成 |

| ID | 插件项目 `tool-plugins` 独立负责 | 对主框架的接口要求 |
|---|---|---|
| PF-01 | 原生工具目录/程序集/资源和版本清点；逐工具证据、算法、参数和输出 | 输出稳定的模块身份、分类、图标、版本及可用性元数据 |
| PF-02 | **插件公共配置框架**：模型、展示类型、模板目录、普通/专属窗口及交互服务 | 用单一工厂/上下文接 WPF 壳与 Group，不把每个工具做成孤立窗口 |
| PF-03 | 工具参数订阅、动态端口/叶字段、ROI/Fixture控件、输入预览和结果显示 | 需要通用数据或流程来源时提交 FCR；main 负责流程所有权和消费端 |
| PF-04 | 单工具调试、连续/停止、失败/取消/超时、图像列表与显示状态、方案切换清理 | 调用必须携带方案/流程/节点身份；不另建主流程调度器 |
| PF-05 | 图像源作为首个完整样本；随后按依赖推进标定加载、N点等真实工具 | 每工具同时验证公共插件框架能力、实际数据运行和主窗口/Group集成 |
| PF-06 | 插件框架与工具的专项测试、原厂同状态差分、人工验收候选 | 交付中文提交、证据路径、未闭合项和可复验操作，不以单元测试数代替原厂等价 |

**防断层规则：**插件项目每领一个工具任务，先填写“所需插件框架能力、现有/缺失、接口到主框架、实工具验证”；缺框架能力由插件项目在同一功能节点补齐。主框架每新增一个供插件使用的接口，要用真实插件在根流程和Group中验证；缺插件侧实现则标“待集成”，不自行复制工具逻辑。共享文件按 [职责边界](PLUGIN-FRAMEWORK-BOUNDARY.md) 指定单一提交所有者，另一方只提交合同请求和验收案例。
