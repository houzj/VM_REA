R04 生产整链接入候选及 CPU 接缝

仅候选，不修改共享生产。完整补丁 analysis/map-calibration/proposals/r04-source-recognition/r04-production-integration.patch；同目录 integration/ 是每个目标文件完整候选，index记录当前生产base哈希和候选UTF8哈希，prepare_integration.py可重复生成。git apply --check通过，尚未整体编译。禁止直接用首轮PASS168宣称此生产补丁通过。

接线

  • 新增A/B十文件：opening/prelocator/local-feature/circle、fixed tag sampler/quad fit、813ca0 proposal/813020 mapper、组合器、CPU policy/public facade。Opening保留已修正的原汇编按行加法分组与SelectedRefined诊断。
  • Adapter新增FindSource：只跑SourceGridPyramid/FromResult，不要求旧geometry成功；PitchX/Y=NaN、CodeQuadrilaterals为空。既有Find本身保留作为历史独立API，不在新源路径调用它。
  • Map.Solve尾部新增可选execution，未传则由原谓词CPU policy检测；两侧同一record。ROI仍crop→mask稳定压缩→float原点→RebuildForProjectedPoints保留原W/H/重算filtered minima，再原坐标图解码。新路径删除fullimage projective/rotation兼容fallback；源失败不得重试legacy。此删除是否使其他兼容样本退化须单列回归，不能静默恢复fallback。
  • BoardCalibrationOptions新增可选SourceExecution；三个encoded入口使用FindSource和source facade，保留30/140、原序、crop/mask SourceGrid投影，不改普通格点/圆板算法。
  • NImageRuntime.Add尾部新增可选execution，批次实际识别入口才检测CPU，直接源识别所有帧，不新增任意图像旋转重试。状态/序列/输出缓存逻辑不变。
  • 底层真实813ca0窗口序、正反四排列、成功方向/anchor和813020输出顺序由同一组合候选返回；不再orientation==0门、Nearest或world排序。radius2负前缀未知仍明确Unsupported，不以清0伪造原数组前缀。

630120 返回谓词已可实施

复用现有630120.asm与cookie-tail；不采用void C伪签名。family门=(leaf1.EAX&0xf00)>=0x600。class11来自leaf7(0).EBX bit5，class10来自leaf1.ECX&0x18000000判等。低级7/6/5/4/3/2/1依次来自leaf7 ECX bit20/19/9/0、leaf7 EDX bit26/25/23。这里确是leaf7覆盖后的槽，不能按常规ISA名称替换为leaf1。

最后VerifyVersionInfoW输入major6/minor1/SPmajor1、type0x23，三个条件均3；失败降至低级7..0。PE 181611ac0的284字节模板仅Size=284非零，详见r04-axis-source/cpu-os-template.json。早先Windows6.2、leafD、AVX512写入只流向26d..27e，不参与返回值选择；候选仅翻译返回值切片，不复刻无关查询的LastError副作用。

NImageSourceCpuPolicy使用X86Base.CpuId和相同两个WinAPI，无Avx2猜测、无硬编码当前class。只读自有native无图探针CpuPolicyProbe对照原630120：leaf1Eax10751809、leaf1Ecx4275581443、leaf7Ebx563909545、leaf7Ecx4195972、leaf7Edx16、versionAccepted=true，预测11=原11，exit0。原件hash与进程记录在r04-cpu-policy-oracle；没有设备/平台Init。C# selector也已加入下一Opening严格入口，尚待构建。

应用边界： 当前生产候选backend仅CPU11有A/B源码与oracle支持，其他class明确Unsupported；不能作为让其他正常host支持域退化的全局补丁直接应用。主线可审计selector并限定实际CPU11会话接入，其他既有host路由的迁移需对应backend退出证据；不得将其自动fallback伪装源等价。当前主线已明确不应用导致默认正常域全部Unsupported的版本。这里不扩大全部CPU逆向为无限前置任务。

整工具当前具体成员缺口

  1. MapCalibrationPlugin.Descriptor的InputROI1/InputROI2是Region端口，Runtime.Image.Group仅读取RoiGroups/Rois；输入Region→原标量ROIBOX订阅的优先级/adapter尚未闭合，当前直接绑定可能不生效。
  2. MapCalibrationImageSolver.Solve返回Boxes来自RoiDocument；Runtime.ImageResult输出DetectCenterX/Y、DetectWidth/Height/Angle及ROI。原ProcessOutput220b0来自image描述块，尚不能把ROI几何当其原生产者。应针对该块字段取证与双图显示对照。
  3. MapCalibrationPlugin.LastDisplay只在session.Result与Target同时存在显示目标图；等待/失败/文件成功切换后旧frame可见性，不能从SDK结果生命周期直接外推宿主历史输出。
  4. CreateConfiguration已有RoiType_0/1→InputImage1/2、路径/保存、运行/连续/停止、订阅与显示对象控件；缺口是以上实际运行成员，不再把配置整体泛称未实现。
  5. 新A Opening严格C#修正后回归、SourceBoard.SelectedRefined记录，以及完整生产候选在三消费者的有限验证尚未完成。人工验收单列，不阻用户定义的源码+实施+自审完成标准；当前实际实施/验证缺口仍阻整工具闭合。
