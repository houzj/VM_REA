The actual normalization result is not kept as double throughout candidate production. At 180c92d2d the selected dot callback [RSI+120] executes. The value at stack+c8 is loaded as double, added to stack+80 by ADDSD at d52, and sent with the other original double operands to 180c9ad00 at d61. Return XMM0 is converted CVTSD2SS at d79, then stored into the score-map float cell at d89. The following branch compares the original double XMM0 against a float threshold promoted by CVTSS2SD from [RSI+118] at d8e. Therefore substituting the rounded map float for that immediate double threshold comparison is not justified.

Candidate scan 180c937ae reloads a score-map float. COMISS against XMM14 followed by JA takes a separate block at9390c (outside the current explicit span); COMISS against XMM13 followed by JBE skips insertion. The shown insertion path executes SQRTSS at937c4, then calls 180c97e60 at937f2 with XMM3 carrying that single-precision square root. Neither double sqrt nor sqrt-before-map-rounding is source-equivalent to this path. Upper branch9390c and register threshold definitions remain exact local continuation gaps; do not generalize the shown path to all peaks.

Production scalar normalization currently has strict12 original-bit checks; map storage and candidate scanner are not implemented by those checks. Full1390 training/search, layout and remaining candidate/refinement paths remain incomplete. This evidence narrows the required next implementation boundary without adding real-image samples or guessing scoring rules.
