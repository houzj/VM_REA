轮廓匹配共享显示候选请求（只读证据，root落共享）

Producer：Contour专属Runtime/结果快照；Consumers：ToolDisplayGraphics→ToolDisplayImagePresenter及配置ROI lease DrawOverlay；跨项目payload由root记CONTRACT-REQUESTS，C不改Contracts/Framework/Editor。

原件/入口证据

  • 原Contour Display.xml见identity/original-identities.json逐SHA；Feature Match Result Type=rect，CenterX/Y、Width/Height/Angle、Tips/Status均ArrayMatch=true，Mapping分别MatchBoxCenterX/Y、MatchBoxWidth/Height/Angle、MatchStatus。Feature Match Contour Points Type=outlinepoint，OutLineInfo=MatchOutline，Num=MatchOutlineNum，默认IsDisplay=true；InputImage独立image对象。
  • 当前Apps.XmlParser.dll SHA78EC7AE1E5ADEFFF29197099C7109B153A3F75D092B7C3E9DC253D8C1B25A8D1；只读原Object.cs:685–691逐shape index读Width/Height/Angle；714–718读OutLineInfo为IMVS_MODULE_CHUNK_VALUE_EX_Data；930–955 SetBaseProperty同index读CenterXY/Status并给shape各自颜色，Outlinepoint例外保OK/NG两色交给点分数。
  • 当前Apps.Data.dll SHA2AD51C179D4A5CF7E0C0373CD1526DE8A75D53A3EA6CBE3EF73C0C5268E1C55C。专属Apps.Data.Outlinepoint.short-name.il实际FD58 get_OutlineData=OutLineInfo?.GetData() ?? BinaryPointData。第一次ILDASM长类型名导出0bytes保留，只短类名正确取得6526bytes，不把exit0空文件当源码。
  • VMBaseControls.dll SHAD3ED7CE6CCA860AC89D671DC0FE4EE239A97063D18BED94D3AD97595D5D52555。原MultiPointShape.cs:437 UpdateOutlinePointsData消费OutlineData、OK/NG色与opacity；CreatPointK:333–407将byte[]按IMVS_PATMATCH_POINT_INFO解析，Score.Equals(0f)→OK色、Equals(1f)→yellow(FFFF00)、其余→NG色，画2×2屏幕像素实心块，绝非point cross/path连线。碰撞按原整数颜色min比较及clip为旧raster细节，可列显示适配边界，不能捏造原source算法。

已证实际载荷

  • Contour原ProcessOutput23d00：点缓冲每记录0x10=LE floatX +floatY +floatScore +intContourIndex；UpdateMatchResult先保原edge score。发布MatchOutline时asm24879 SHL count,4，2487d将byteLength写第5实参，24882 R9=buffer，R8=0，24896 VM_M_SetPointset。原C漏第5参数，不能将4形参误当count缺失。
  • 原模块对MatchStatus!=1的整条轮廓写score=2f；OK时score经过double*1000/1000后float回写。常量原PE330e0=2.0，332c8=1000.0，原字节与SHA见pointset-constants.json，不能将score当boolStatus直接0NG/1OK。
  • GroupIndex是原结果index，由各轮廓点写+0xc；原raster绘点不使用此字段，但输出协议与其它消费者仍必须保留，不可丢失或按model slot代替。

当前具体缺口

  1. ToolDisplayGraphics.cs:8–12只有每point Color，Width/Height/Angle仅Graphic scalar。Build:43拒绝outlinepoint；其rect在Scalar(Width/Height/Angle/Status)取首项。Geometry.cs:19–20对所有center复用同W/H/A，无法表现正常两结果不同宽高角/状态。
  2. 现PortValue/DataKind没有pointset/typed轮廓值，普通PointArray丢score/group；字符串/Components伪装也不合原semantic。原MatchOutline是pointset筛选类型，不是数值POINT组合。
  3. 两实际显示入口必须一起消费：主Presenter及ToolConfigurationRoiService.DrawOverlay，不能仅Build生成Color/数据后未画，不能以ROI viewport可见冒结果已显示。

最小共享候选（待root审核）

A. rect：ToolDisplayPoint新增nullable实例Width/Height/Angle（及Color对rect有效）；旧Graphic scalar作兼容fallback，Build对每原index投影matched-length W/H/A/Status并保Index/Tips。Geometry/主Presenter/lease按每rect各自尺寸、角度与颜色绘制；不改变path连线原色或point/circle旧几何。只先覆盖原正常等长array与scalar广播，短数组严格复用已证Object读取规则，不能猜补0制造几何。

B. pointset：建议公共append DataKind.PointSet及不可变PointSetValue，成员PointSetPoint(float X,float Y,float Score,int ContourIndex)，构造复制输入、可空零点，拒非有限为明确安全边界；PortValue.PointSet生成owned快照。不是native指针/二进制ABI。tool输出MatchOutline用此值，Build新outlinepoint分支消费该Mapping，保GroupIndex，不把Num的数值当shape实例数。Graph/配置候选树native type映射pointset仅按真实新port声明扩，现其它类型不宽松Coerce。

C. 具体绘制：outlinepoint按Score精确0/1/else选OK/yellow/NG；尺寸为2屏幕像素/当前scale实心方块、opacity源style，不连线也不画十字。主Presenter和lease共同geometry/helper消费，空点集清帧；碰撞/clip和native raster线程顺序未仿真，不写像素等价。

生命周期/兼容与验收

  • Runtime owns本轮结果，在scope存完整immutable snapshot；Graph结果、显示frame只读共享该快照；下一run替换不append旧点，失败是否发布按原Process成功门；close/node reset/dispose清scope和existing ROI registration，不绑定原nativebuffer指针。方案只持久化配置/模板/userdata/style和订阅身份，不持久化临时engine指针/本轮点集。
  • 旧tools未声明PointSet不受类型变化；新增enum append，旧调用Point/Path/Graphic scalar仍可用。根线维护公共contract producer/consumer版本与跨项目采用。
  • 检查1：两个rect中心(10,20)/(80,90)，W/H=(30,40)/(70,20)，angle0/45，Status1/0，验证两实际Drawing树各自变换/尺寸/颜色；scalar与旧point/path回归。
  • 检查2：pointset score0/1/2/0.5分别OK/yellow/NG/NG，组index0/0/1/1保留；不得默认四点NG或普通cross；2×2屏幕块在scale1/2均核。
  • 检查3：成功→空轮廓→恢复、输入数组后改源内存不影响ownedsnapshot；两显示入口消费、样式保存重开、close/reset释放不再画旧帧。
  • 检查4：非法byte长度若提供原binary decoder必须明确拒绝非16倍数；不得危险解引用或静默丢尾冒原厂完整输入等价。当前建议typed producer不让product走opaque native解码。
