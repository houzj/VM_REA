有限边界与必需原件

先前“−1首次写源”确为内部哨兵/剪枝状态链的有限缺口，下节补一个具体callee即可；heap allocator尾字节、全部CPU与任意工作区初值不是本卡源码阶段的无限必需项。

本轮唯一优先callee：8c00f0新增边首次写−1

复用analysis/map-calibration/ghidra/core/1808c00f0.c/.asm。8bdef0伪代码漏第三参数；asm1808be892从当前direction装R8D，1808be8a2调用8c00f0，返回0立即停止扩边。有效签名为(state*, dims*, direction)，不是只有两参。

direction0/1/2/3分别处理上/左/下/右边。它只在对应现边界至少有一个既非−2亦非−1的cell时扩一层；新增边indices写0xffffffff、对应三score写FLT_MAX，必要时移动旧矩阵/score，dims相应增1，返回1；该边没有有效cell则返回0，不凭空加边。Count不因单纯新增空边而增加。

以direction2（下边）这一具体分支为主证：C约197..235从旧末行扫描，条件oldIndex!=-2 && oldIndex!=-1；一旦成立，将新row=oldHeight的全部width槽写−1（成对及奇数尾项均有写），三个score置FLT_MAX，然后height++/return1。asm1808c014d/153核排除−2/−1；新边写−1对应0x1808c02e4等分支指令。−1由此有明确生产写源，先前“本切片seed未写−1”仍正确，但不再是D2整链找不到写源。

8bdef0随后按新边的可用两/三参考点建立预测目标；assigned初值−2，8bf960只把已配对目标改为候选index。未形成目标的新增cell可以保持−1，形成目标但未分配的cell写−2；已分配cell写有效index并修正Count。不能将−1、−2、INT_MIN三种不同层/状态哨兵合并。

8bdef0的cookie-tail确认：填现有孔洞返回1，新增边路径返回2，无进展/失败返回0。8bcff0只对status1做direction--以重试该方向；status2继续下个方向；非0才调用剪枝。该返回值也不是伪代码void。

连接到剪枝flags负写：确认语义与未声称运行

8c0880目标数>0且worstScore>threshold时选择移除cell；其asm1808c0df7符号扩展该cell索引，dfb测试负数只控制是否Count--，e0b仍无条件写flags[index]=0，e16才把cell改−2。因此如果选中cell为−1，地址为F−4；如果−2则F−8。两个write表达式与F前的第二假设ID保留段关系已由上个报告确认。

这并不声称本轮运行达到F−4：是否新增−1cell在特定worst-score/target序列中被选中，属于原厂具体输入与S3确认；没有为触发它新增输入。源码层已经给出生产写源、保留条件、读取谓词及实际写地址，不必追整个heap才能解释该行为。历史probe的prefix−4观测不替代此处的条件链。

搜索次数的符号闭合

813ca0半径r=1然后2；候选row=r..H−r−1，column=1..W−r−1（r2保留负列，不能正规化）。忽略提前成功但保留空范围，候选位置数：

Nr=max(H−2r,0)*max(W−r−1,0)

每个位置先按原整数grid含保留段值统计缺槽、除中心；只有达到门6/17才进入decoder。设通过门的位置集合Er，实际尝试数为对访问前缀中各proposal的成功排列编号或全部失败8之和；一旦成功，余下位置/半径不访问。全失败时逻辑上界8*(N1+N2)，不是每图固定调用数。14×14仅作控制流算术示例：N1=144、N2=110，上界2032；不表示原厂实际安全完成2032次或已采方向1实际调用这么多。

有负列的内存实参/非有限值/decoder失败时机不能用这个数学上界替代，原始radius2地址关系继续保留在padding报告。
