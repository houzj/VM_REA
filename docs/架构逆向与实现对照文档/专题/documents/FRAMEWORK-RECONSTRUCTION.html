已确认的架构差异

原厂普通模块链路为 ModuleParam → AlgorithmTabRoot → ParamsConfigControlBase → ParamsTabUserControl → ParamListView/ParamUserControl → UserTempConverter → DataTemplate。外层 ParamsTabControlBase 是普通参数窗口；ParamsConfigWithRenderControlBase 是另一种组合宿主，不能将其宽屏布局作为所有节点的默认参数窗。

原厂配置模型与执行模块各有职责。AlgorithmTabRoot 承载页签、分组、外部参数、左右底部命令、选中页、窗口尺寸、订阅和 ROI 桥接。NameValueItem 的展示类型、状态和命令驱动模板选择。执行参数的整数、浮点、字符串类型不足以决定控件类型。GroupLinkItem 克隆公共组内容并设置父链；不是丢弃组后手写几个相似字段。

当前 ModuleDescriptor 继续承担执行身份、输入输出及参数校验，这是合理的边界。缺失的是并列的配置模型及其公共宿主合同。IWpfToolEditorFactory 直接返回任意 Window，使插件各自决定页签、尺寸、按钮和调度；宿主又用 ShowDialog() 打开，造成系统性偏差。修复不能只扩大 ModuleDescriptor 或修改几个窗口尺寸。

具体源码、行号、原始资源哈希和确认程度见 docs/plugins/configuration-host-lifecycle-evidence.json；模型和模板的专项清单继续补入本目录。没有执行原厂完整桌面生命周期的部分均保留为源码确认，不冒充运行验证。

重建职责

层次 负责内容 禁止替代方式
执行合同 输入输出、参数值、结果、错误、取消、会话作用域 用 UI 控件替代参数语义
配置模型 原厂节点类型、页签与组顺序、展示键、状态、订阅、操作元数据 从执行类型猜控件，丢弃隐藏/废弃/继承规则
配置适配器 插件特有数据读取、设置、操作及特殊内容扩展 插件自行创建顶层窗口、捏造通用底部命令
公共模板目录 展示键到原厂控件模板的映射及明确覆盖状态 未支持类型回退普通文本框并声称完成
公共配置宿主 窗口所有权、唯一当前实例、尺寸绑定、页签/滚动/固定命令栏 普通参数窗与渲染组合宿主混用
图像/ROI 与订阅桥接 连接当前工作流和图像视图，保持原模型事件及生命周期 每个插件创建另一套图像或订阅系统

NeedPopTip 不能按名字统一解释为操作前确认。原厂清图先执行，再按成功/失败显示消息；重置参数有独立的确认流程。执行按钮、连续执行、生成文件和清除操作必须由各工具的 XML 和命令类型决定。连续自执行原厂有 300 ms 调度和结果回调门控；当前插件里的 1 ms 循环不是等价实现。

实施状态
