当前真实图的可复验结果

tests/CalibrationRotateConsumer.Checks/Program.cs 创建真实 GraphEditorDocument：相机映射两组四点通过 WorkflowSubscription.NumberArrayConstant 进入原端口，执行边连接相机→采样源→旋转；相机 CalibStatus 接旋转 RefreshSignal，采样源连续给出 RotNum=3、X/Y 环形三点与 WorldRotateAngle=120。同一 ModuleExecutionScope 连跑三次，每轮相机重写自身目录内的 36 字节 camera.iwcal，旋转在相机之后刷新并消费该文件。三轮两节点全部 Success/原生码 0，remainCount=2,1,0，前两轮中心 0，第三轮图像中心 (50,50)。文件 SHA-256 E2196EC26DEC21D729B86D14FA52A70AF217D9B4C87D7B40681AF01B66BFC06D。这是当前实现真实图交接，并非原版 VisionEditor 同构整图实跑，也不替代原版同输入数值差分。

独立恢复图仍走 SolutionExecutor/GraphEditorDocument：先删除自身 camera.iwcal，保留相同 FilePath 且 RefreshSignal=1；旋转返回 Failed/E0000008，输出集合为空。写回刚生成的 36 字节文件，在同一 execution scope 再跑则 Success/0、remainCount=2，证明当前刷新重新装载和失败清采样。直接读取不存在的 .iwcal 得 E0000201 且 loaded=false；这是 LoadCalibFile 底层结果，Process 因无有效矩阵另返回 E0000008，不得混为同一码。

命令 dotnet run --project tests/CalibrationRotateConsumer.Checks/CalibrationRotateConsumer.Checks.csproj -c Release 最终退出 0，stdout analysis/joint-audit/pass9-cal-rotate/checks.log。首个构建尝试遇其他并行线共享 VisionPlugins.ImageSource/obj 的 CS2012 写锁，未改进程或文件；错峰重试成功。验证日志保留失败尝试应由协调线另计。当前生产代码未修改，本切片没有足以提出主框架独占修复的差异。

未覆盖与接口判断

  1. 原版平台内 CameraMapping→Rotate 的同构完整图、回调调度和同数据集数值差分未运行；只证两个原件各自文件读写合同与当前整图。相机生产者本轮复用第八轮的原函数证据，不重复宣称其 SDK 所有算例合格。
  2. N 点、映射、平移旋转三份 XML 仅现有产物的消费者直接解析，不等于本轮原件生产者重新执行；短 XML 缓存尾保留与坏 XML 的全部状态组合可依据旧 Rotate 原定点取证，未在这张图中扩大测试。
  3. 旋转输出没有原版直接矩阵端口。旋转由文件取得变换，再输出中心／误差给后继；不能把 CameraMapping 的 CalibStatus 当矩阵、也不能把旋转虚构为标定加载的矩阵生产者。后继若需要中心坐标，应按实际六个输出端口逐个核订阅。
