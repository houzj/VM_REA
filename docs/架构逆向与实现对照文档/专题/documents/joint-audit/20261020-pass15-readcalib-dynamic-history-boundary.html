DynamicVmIO.UpdateDynamciIOInfo(VmIOCollection) 在动态 IO 集合编辑路径识别输入/输出所属模块；ModifyConfig 撤销上下文下调用 RegisterInputIOToIoc 或 RegisterOutputIOToIoc 以及 RegisterSubscribeToIoc，再把当前集合编入 SDK SetModuInputIOInfo/SetModuOutputIOInfo。VmModule.RegisterOutputIOToIoc 保存旧输出 IO 信息表达式；其 IOData_Undo/Redo 在输出侧先 QueryModuleIOBeSubscribed/clone，再 RemoveDynamicOut → SetModuOutputIOInfo → InitDynamicIO(list, Outputs) → Done_IOData。Done_IOData 对 Group/Procedure 先 SetIoParams，若有 clone 再 RecoverSubscribe，随后 UpdatDynamicIO("DynamicOutputParam") 更新配置视图。RecoverSubscribe 根据原保存的模块/输入/输出名取叶并给 RelateIO 赋值，实际缺叶、重名或类型变化的异常/失败如何处理不能靠这段正常路径下结论。

这是显式动态叶编辑的撤销/重做路径，并非任意参数变化的全局通知。第十三、十四轮标定加载文件控件 override→父类 SetParamUnit/PreExecuteRun→ReadData(false) 的已证路径均未出现 DynamicVmIO.UpdateDynamciIOInfo、RegisterOutputIOToIoc 或上述 IOData_Undo/Redo 调用。VmModule.Outputs 仅首次懒加载时初始化输出。因此不能把原版动态叶编辑撤销能尝试订阅恢复，外推成“重选 XML 自动迁移旧 Group 连接”。原 SDK SetParamValue/运行后若以其他回调进入动态叶更新仍未知；解除条件是找到该回调/订阅者的精确原函数体与触发前后 SDK 端口/订阅身份，或自有隔离原机同状态差分。
