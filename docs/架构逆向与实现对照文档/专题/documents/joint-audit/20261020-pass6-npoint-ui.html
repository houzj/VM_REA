打开点表 IMVSNPointCalibModuControl.NPointList.UserControl_Loaded → Init 取 CalibPointTotalNum + RotPointTotalNum；每行五次 GetFloatParamValue 经 IUserStringData 读并转 f3；对象初始化器给 PointList 五属性赋值。PointList 各 setter 在 OwnerParam != null 时逐一向 IUserStringData[字段名+ID] 写，失败则不更新文本。XAML 五个可编辑列均 LostFocus。 NPointConfigurationPointEditor 建行时同样逐格调用 commit。但该 commit 进入 NPointConfiguration.PointValues()，每格克隆全部 32×5 点值后 Apply 整份参数；再 NPointPlugin.Synchronize 扫 32×5 键。实际主窗口 ToolConfigurationHost.Apply 进一步对每格调用 GraphEditorDocument.SetProcedureNodeParameters，后者验证参数并执行完整文档编辑/历史记录。逐格写回语义有原版依据；每格复制整个图文档属于当前独立实现，不能宣称原版同成本。
单格编辑 XAML LostFocus 把新文本送 PointList 对应属性，setter 一次写对应 IUserStringData 键，成功才通知该属性。没有原版整表提交入口。 PointRow.Set 一次 commit、一次属性通知；生产适配器经 PointValues → Apply → Document.SetProcedureNodeParameters；本次 4/9/32 点探针各确认改单格一次 host Apply且文档读回该字段。未观察到循环执行或隐式求解。
原输入→运行结果 本次未重新解析原生 GetProcessInput/ProcessAlg/ProcessOutput；已有专属源审见 docs/plugins/N-POINT-WHOLE-TOOL-SELF-AUDIT.md 和原生追踪。本次确认当前 NPointPlugin.Runtime.ExecuteAsync：手动模式读同步状态中的点数组，按平移/旋转分段构造 NPointPair/NPointRotation，交 NPointSolver.Solve，成功发布数值和 CalibData。 当前源码链已证，原版完整数值等价不由本探针证明。 原输入端口连接到节点、真实运行输出须引用已有专属全链验收，不因本次点表测试计为新闭环。
结果→真实标定消费者 当前 NPointPlugin.Results 发布 DataKind.Calibration 的 CalibData。本轮对 src 的该类型引用搜索没有找到任何工具以 DataKind.Calibration 作为输入；标定加载另从文件发布此类型。 此边未证：不能因生产者有输出便称存在真实下游消费者。 若目标是 N 点 XML 给后续工具使用，应选定具体消费者及端口/文件模式，用原版读取链和真实图执行补证。
保存/重开 原点表 ButtonApply_Click 仅关闭窗口；点 setter 之前已写参数。当前 NPointConfiguration.SaveCalibration 调 Export → NPointFile.Write，配置窗 Apply 写图文档。 本次验证了编辑后图文档内该字段值；没有执行本探针中的保存/重开。既有 N 点专项测试覆盖保存与载入范围，但本次不把它移作“编辑→消费”全链证明。

修复方向及约束： 可在插件配置与图文档之间研究保持原版逐字段 setter/失败副作用的前提下，避免开窗初始化给图编辑器建立 5N 份完整历史快照；但必须先核原版 IUserStringData 写入是否在全部初值相等、失败或重复打开时仍产生可见副作用，并定义图历史/保存的事务语义。仅凭本次成本探针不能直接删除初始化 setter 或合并成一次批写，也不能动在制 tool-plugins。下一步可增加真实主窗口大图历史负载的受控诊断，和原版同字段写入的 getter/setter trace。
