AC01 · CodeManager原默认值 / IsAllAccessUser → Admin或None为true，Tech/Operator不由此判true

source-confirmed：原CodeManager._isAdmin字段初始true；IsAllAccessUser只比较_accessCurUserInfo.curLoginUser是否Admin或None，命中true否则false。实际枚举类型为VM.User.AccessUser（不是按业务名另造UserType），Int32常量None=0、Admin=1、Tech=2、Operator=3。原CIL先读curLoginUser与1作beq，再重读该字段以brtrue区别零/非零；稳定同值时谓词为v==1 || v==0，负数/其它未声明值均false；两次读取不是原子快照，实际交错未知。它没有读取ItemData列表或逐菜单权限表。此处None也为true是所选原程序规则，不能替换成按名称猜测的角色矩阵；本报告不读取任何实际登录用户/权限配置。

待追：不同原版本、真实登录状态、额外授权入口与所有菜单业务内的权限检查尚未知；不据该bool声称任何具体操作对所有角色开放。

AC03 · OnAllAccessCallBack公开delegate字段 → 三个原件的直接CIL访问只有读取/调用，订阅者未定位

source-confirmed：CodeManager声明OnAllAccessCallBack为公开delegate字段，未提供add/remove事件方法。顶层Applications与myLibs的74个.dll/.exe只做字节名候选筛选，命中VisionMaster.exe、VisionMasterMain.dll、VM.User.dll；再对这三个原件完整离线IL输出定位5条该字段指令，均为ldfld，所属方法是两个不同命名空间的SetLoginUser及CodeManager.ResetAccess。所选输出未找到该字段的stfld/stsfld/ldflda赋值/地址写入指令，故本批没有可确认的真实订阅者，不能把Invoke当成已注册了菜单接收者。

AC04 · CodeManager.ResetAccess / 两版SetLoginUser → 字段/IsAdmin通知与回调顺序

source-confirmed：ResetAccess先将角色改None、清相应启用/口令字段，通知LoginUser，再IsAdmin=true，随后OnAllAccessCallBack?.Invoke(IsAdmin)、OnAccessEnableCallBack?.Invoke(false,None)，最后return SaveAccessInfo。两个原SetLoginUser前段均先写角色/计算IsAdmin，再保存/通知回调；本批不展开其操作员前端切换分支。清的是内存字段的原代码定义，未读取或显示个人口令值。没有证明IsAdmin setter会自动调用OnAllAccessCallBack，两个机制须分别看实际调用点。

待追：回调异常可阻断后续调用/保存，选体未提供全事务回滚；真实回调接收者及关闭释放仍未定位，运行模式内部保持deferred。
