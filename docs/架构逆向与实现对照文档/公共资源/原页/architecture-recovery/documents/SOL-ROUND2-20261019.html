范围：只读检查此前选定 VisionMaster4.4.0 安装目录的8个随包 C# .sol；不修改 tool-plugins，不执行 XAML/原生 SDK，不构建，不打开或关闭现有程序。证据类型为随包文件静态字节与已有反编译源码；没有新增原机保存/重开验收。

新确认的样本结构

8个 MoudleFrame 条目均可由以下独立候选解析完整消费。该结论限定这8个样本，尚不是所有版本、加密方案或厂商序列化合同。

  • 头0..3均为 00000005，其语义未知，不能命名为版本。
  • 头4..7作为 BE uint32，等于逐条解析得到的记录数。
  • 每条记录前256字节为名称槽；样本名称为 UTF16LE，首NUL结束。其后4字节为 BE uint32 载荷长度，然后为该长度载荷。
  • 从偏移8开始按 next = start + 260 + payloadLength 迭代，8样本全部精确到 EOF，没有剩余字节、越界或计数不符。
  • 此规则闭合外层记录边界，没有闭合 .mdata 载荷内部字段。

解析操作与证据

本轮专属本地目录 analysis/full-audit/sol-round2-20261019/：

  • scan.ps1 与 frame-inventory.json：逐样本原件前后 SHA256、帧 SHA256、名字字节偏移、XML订阅原文。8个原件前后哈希一致。
  • parse-frame-candidate.ps1 与 frame-records-candidate.json：记录级 Offset、Name、PayloadOffset、PayloadLength、Sha256、PrefixHex，以及整帧 Consumed/Length/Error；8样本计数一致且完整消费。
  • evidence-sha256.csv：本轮生成证据与相关原始源码哈希。

候选算法：先要求帧至少8字节，读取头第二BE整数；逐条先验证剩余>=260，再取256字节名槽与BE长度，验证长度不超过剩余后哈希载荷并推进。最终检查计数及EOF；超限、截断、未知头、异常名称须保持Unsupported或明确差异，不静默修复。根任务可据此增补测试辅助脚本；本子任务没有修改共享脚本。

调用链边界复核

analysis/decompiled/VM.Core/VM.Core/VmSolution.cs::InternalExport（1551–1597）先初始化TempVmSolution，检查并设置 _isSaving，确定密码和路径，再调用 mSolutionManager.SyncSaveSolution(path,text,IntPtr.Zero,0u)，成功后更新密码/路径，异常清保存标记并清空路径后抛出。这里没有托管 MoudleFrame 序列化。

analysis/decompiled/VM.PlatformSDKCS.Audit/VM.PlatformSDKCS/SolutionManager.cs::SyncSaveSolution（305–323）清保存错误与等待标记，调用 ServerSDKAPI.IMVS_SaveSolution，立即非零抛错，清 ModuleManager.ParamSeted，等待完成；仅 SDKMode 再因异步错误抛出。SyncLoadSolution（272–290）同样走原生入口，重置加载标记并等待；SDKMode决定检查标志与最终异步错误处理。托管源码不能解释 MoudleFrame 内部类型号、打包顺序或部分失败恢复。

本轮在 analysis/decompiled/**/*.cs 中查找字面 mdata、MoudleFrame 无命中；仅说明现有托管反编译树中未见该拼写，不证明原生没有结构定义。各种 SetModuleParamBinding 方法同名并不足以证明其内存结构与帧同名记录的字节格式相同。
