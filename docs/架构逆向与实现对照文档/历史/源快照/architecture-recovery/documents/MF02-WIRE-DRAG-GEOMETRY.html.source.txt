<h2 id="原始依据与实现边界">原始依据与实现边界</h2><ul>
<li><strong>源码确认</strong>：<code>analysis/decompiled/VMControls.WPF/VMControls.WPF.Base/Connection.xaml.cs</code> 的 <code>connectionUserControl_MouseMove</code> 在路径变化后设置 <code>PathPoints</code>（约 398–543 行）；<code>PathPointsChanged → OnPathPointsChanged → SetPath</code>（约 274–286 行）每次同时更新折线与箭头（约 754–775 行）。原生 <code>Connection</code> 以一份 <code>Shape</code> 几何绘制并命中，不存在重建程序单独创建的透明 hit Path。</li>
<li><strong>独立宿主适配</strong>：重建画布保留可见 Path、Polygon 箭头和透明命中 Path 三个 WPF 元素。现在 <code>PreviewWireDrag</code> 将同一条钝化后的路径同步到三者；取消时重绘文档原路线，提交时由 <code>SetExecutionPath</code> 记一笔撤销事务。命中 Path 是项目自己的宿主设计，三层同步为恢复原生单几何效果的适配。</li>
<li><strong>未验证原生</strong>：复杂避障、反向端口、极端重叠节点和原 VM 桌面鼠标精确差分未因本批关闭。</li>
</ul>
<h2 id="实际检查">实际检查</h2><p><code>dotnet run --project tests/VisionEditor.CanvasChecks/VisionEditor.CanvasChecks.csproj</code> 创建真实 WPF 主窗口、两个工具节点和连线，拖动中点时检查可见几何与命中几何同源、箭头按当前展示路线重算；检查预览不写模型、取消恢复、提交只产生一次撤销记录、撤销恢复。测试专用截图保存在本工作树忽略的 <code>analysis/full-audit/canvas-wire-midpoint-preview.png</code>；目检确认折线、箭头和中点手柄位置一致。完整 <code>VisionEditor.WpfChecks</code> 另作回归，不能代替原 VM 差分。</p>
