<li><code>analysis/decompiled/VMControls.WPF/VMControls.WPF.Base/ZoomArea.xaml.cs</code> 中 <code>OnPreviewMouseWheel</code> 依次调用 <code>OnHoriScroll</code> 和 <code>OnChangeZoom</code>。</li>
<li><code>OnHoriScroll</code> 仅在 Shift 分支设 <code>e.Handled = true</code>；<code>OnChangeZoom</code> 在 Ctrl 分支推进缩放索引，但不消费事件。两种修饰键并存时两条分支均执行。</li>
<li>本项只确认控件事件处理与路由生命周期；真实 VM 外层控件后续如何处理未消费的滚轮事件，尚未逐窗口验证。</li>
</ul>
<h2 id="本地实现和操作验收">本地实现和操作验收</h2><p><code>WorkflowCanvas.CanvasWheel</code> 保留既有缩放锚点和横滚行为，移除 Ctrl 分支的 <code>Handled</code> 赋值。独立 WPF 检查在 <code>tests/VisionEditor.CanvasWheelRoutingChecks</code>，创建真实窗口，通过 WPF 鼠标预览路由和线程键盘状态依次操作 Ctrl、Shift、Ctrl+Shift、零增量滚轮。它检查 ScrollViewer 收到的事件及其 <code>Handled</code> 状态、缩放刻度、横向偏移、文档修订，以及保存重开后的流程与视口。</p>
<p>本轮截图：<code>analysis/full-audit/canvas-wheel-native-routing.png</code>（仅测试输出，未加入产品程序集）。目检窗口结构、画布、鹰眼和 100% 缩放显示正常。Ctrl 缩放采用鼠标锚点，水平偏移会随缩放变化，这不等于再次触发横向滚动。</p>
<h2 id="尚未验证原生">尚未验证原生</h2><p>原生窗口中 ScrollViewer 之后的父级接收方、不同 DPI/鼠标驱动的 Delta 序列，以及真实 VM 文件重开时的视口持久化行为仍待运行取证。此处不宣称完整原生等价。</p>
