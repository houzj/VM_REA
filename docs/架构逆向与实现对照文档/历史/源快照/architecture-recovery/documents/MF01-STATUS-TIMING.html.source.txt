<li><code>analysis/decompiled/VMControls.WPF/VMControls.WPF.Base/StatusBar.xaml</code> 的 <code>ProcessTemplate</code> 把流程耗时放在 <code>ShowTimeClick</code> 按钮中；<code>TimeTemplate</code> 展示所选项的模块耗时和算法耗时。</li>
<li>对应 <code>StatusBar.xaml.cs</code> 的 <code>ShowTimeClick</code> 先关闭旧窗口，有所选对象且当前画布源为 <code>IVmModuleSet</code> 时显示 <code>ShowTimeDialog</code>；画布源改变会调用 <code>CloseTimeDialog</code>。</li>
<li><code>analysis/decompiled/VMControls.WPF/VMControls.WPF.TimeDialog/ShowTimeDialog.xaml</code> 包含流程耗时总计，以及按模块名称、工具耗时、算法耗时排列的列表。</li>
</ul>
<h2 id="独立实现与运行数据">独立实现与运行数据</h2><ul>
<li>将 WPF 主窗口状态栏的“流程耗时”改为可点击命令，弹出 <code>ShellTimeDialog</code>。窗口从当前流程的 <code>workflowSessions</code> 读取真正执行的 <code>NodeRunRecord.ElapsedMilliseconds</code>；未执行模块显示 <code>0.00</code>，重复点击关闭旧窗口，流程 Tab 切换后关闭陈旧窗口。</li>
<li>现有独立执行器只提供节点总耗时，没有原生 SDK 的独立算法耗时。因此算法列显示“—”，不把总耗时复制成算法耗时或伪称 <code>0.00</code>。流程总耗时按当前记录求和，保持本项目既有状态栏计量方式；原生调度开销另算的精确语义待取证。</li>
<li>UI 由专属 WPF XAML 窗口显示，不引入 WinForms，也不把截图代码放进产品程序集。</li>
</ul>
<h2 id="操作验收及边界">操作验收及边界</h2><p><code>dotnet run --project tests/VisionEditor.ShellChecks/VisionEditor.ShellChecks.csproj -v:q -m:1</code> 创建真实 WPF 窗口，运行一条实际流程，点击状态栏并核对行数、节点耗时和算法未知标识，重复点击和切换流程验证生命周期；专项累计 14 项通过。测试渲染位于本工作树 <code>analysis/full-audit/shell-time-dialog.png</code>，已人工查看排版。此截图是独立程序，不是原生 VM 截图。</p>
<p>真实 VM 的颜色资源、精确像素、流程总耗时与工具/算法拆分、Group 内部选中态及原生调度路径仍未完成差分；本项仅闭合已列交互和独立运行数据，不代表状态栏整体或 VM 时间统计完整复刻。</p>
<p>集成复验发现流程切换关闭耗时窗口时存在关闭重入：选择事件可能在窗口关闭期间再次触发 <code>Close</code>。主线修为先摘除选择监听并清空当前窗口引用，再关闭旧窗口；<code>Closed</code> 回调只清理仍指向自己的引用。主工作区重新运行 Shell 专项检查通过，包括重复打开、流程切换关闭及状态栏缩放复位。此项是 WPF 宿主生命周期修复，不声称原生窗口关闭时序已差分验证。</p>
