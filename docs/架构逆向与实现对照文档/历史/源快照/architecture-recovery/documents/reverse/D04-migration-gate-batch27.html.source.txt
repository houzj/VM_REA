<p><code>src/FrontendDesignMigration</code> 是已落地的纯托管、源码确认的 <code>Root/V4.0 -&gt; V4.4.0</code> 设计 XML 转换分支，并有 18 项自审；它不等价于 CompatibleTool 的完整迁移器，也不构成 <code>.sol/.solx/.gro/.prc</code> 容器读写实现。现有证据明确显示方案保存、加载、版本查询及密码处理最终委托 SDK/native，native 函数体和容器事务语义尚未取得。</p>
<h2 id="d041-迁移">D04.1 迁移</h2><ul>
<li>已确认：<code>DesignConverter</code> 读取 XML，禁止 DTD，使用显式编码，按原 <code>FirstChild</code> 分支处理 Root，执行模板、尺寸、透明画刷、嵌入 SubWindow 的源码确认转换。</li>
<li>已验证：<code>tests/FrontendDesignMigrationChecks13</code> 的 18 项 synthetic 模板断言及 CLI 的拒覆盖行为；这些是托管独立实现的自审，不是原厂迁移器运行差分。</li>
<li>未确认：原厂设计缓冲区如何从 <code>.sol</code> 读取和回写；迁移失败的原子性、旧新配对样本、插件模型/附件/ROI 写回、版本分段实际效果。</li>
<li>因此不新增实现，避免把 XML 分支冒充 <code>.sol</code> 迁移或增加未经证据支持的容器写入器。</li>
</ul>
<h2 id="d042-版本密码兼容">D04.2 版本/密码兼容</h2><p>静态托管证据确认 <code>ProjectManager</code> 查询 <code>IMVS_GetSolutionVersion</code>，CompatibleTool 通过 SDK 的 <code>Load/SaveAs</code>、流程导入和 Group 导出入口工作；<code>NativeMethods</code>/SDK 头仅给出 P/Invoke、<code>__stdcall</code> 声明和参数结构。没有原生函数体、加密/密码校验算法、版本矩阵或“错误密码/取消/升级失败恢复”的可复验样本。因此不能在 main 添加密码校验、版本路由或 fallback 逻辑；任何实现都会是独立兼容猜测。</p>
<h2 id="审计证据">审计证据</h2><ul>
<li>托管迁移与 SDK 边界：<code>docs/COMPATIBLETOOL-VERSION-MIGRATION.md</code>。</li>
<li>已有托管分支实现：<code>docs/reverse/D-frontend-migration-implementation-batch13.md</code>。</li>
<li>既有门槛结论：<code>docs/reverse/D04-version-gate-batch24.md</code>。</li>
<li>源码：<code>src/FrontendDesignMigration/DesignConverter.cs</code>、<code>src/FrontendDesignMigration/Program.cs</code>。</li>
<li>原生 <code>.sol</code> 样本仅观察到 ZIP 头与目录，不能推出全格式/密码协议。</li>
</ul>
<h2 id="解除条件">解除条件</h2><p>需要至少一组同一版本的旧/新 <code>.sol</code>（含正确密码、错误密码、取消和失败输出）、受控原厂 CompatibleTool 运行日志，以及 <code>IMVS_SaveSolution</code>/<code>IMVS_LoadSolution</code> 函数体或可复验 SDK 读写探针。取得前 D04.1/D04.2 保持 partial/blocked，下一轮不应重复静态 XML 门槛。</p>
<p>本轮未访问或修改 <code>tool-plugins</code>。</p>
