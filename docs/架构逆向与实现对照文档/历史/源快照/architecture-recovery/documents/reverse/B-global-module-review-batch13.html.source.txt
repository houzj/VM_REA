<h2 id="原用户入口到执行存储">原用户入口到执行/存储</h2><p><code>analysis/decompiled/VisionMaster.Exe.Audit/VisionMaster.AppMainWindow/TitleMenueItemData.cs::GlobalVariable</code> → <code>VmModuleExtern.GetGlobalVarModule</code>（当前 VmSolution.Modules 中 ID=13000）→ 缺模块时 Assembly.LoadFile 上述 GlobalVariableModuleCs.dll，找 IVmModule 类型，以 VmSolution.Instance 构造，再重取模块 → GlobalVariableDialog.DecorateSource/ShowDialog。不能把局部变量 AddLocalVariableModule 的 type25 路径当成全局创建。</p>
<p>原 GlobalVariableModuleTool : VmModule, IVarModule；object 构造器 base(param,&quot;GlobalVariableModule&quot;) 并创建 VariableManager；InitGlobalIo 先 base 再 GlobalVarHelper.InitGlobalVarOutputIO(IsParastic?HostModule:this)。ReloadModuleData 反向 Dispose 全部 Outputs，再 InitDynamicIO，catch吞异常。恢复来自原数据源动态 IO，不是 main 局部变量列表。</p>
<p><code>Apps.XmlParser.CapabilityAudit/Apps.XmlParser.Variable/VariableManager.cs::AddVar</code> 校验名字、查重复、生成GUID，打包 IMVS_VARIABLE，经 DataSource.Params IUserBytesData[AddVar] 发送原生处理，然后 AddIoByType 并设置索引。类型是 LeafIOTypeEnum 与 CombinationIOTypeEnum、可选扩展的支持集合；包含数组、图像和复合ROI，不是 int/float/string 三标量。</p>
<p><code>GlobalVarHelper.InitGlobalVarOutputIO</code> 从 GetAllVar（VarCount/GlobalValueList）重建动态输出、处理过期输出并恢复索引。修改/删除、改型、分组和绑定也经 Params 原命令。VariableManager.SetRunParamBind 调用目标模块 ParamSubManager.SetModuleParamBinding，类型和能力必须匹配，设置 UserData[@参数] 并调用 ISubInfo.SetInit；旧占用需解绑。不能只在执行前给 Parameters 填一个值替代完整订阅生命周期。</p>
<p>原模块 IVarModule.VarValueReportEnable 使用引用计数：0→1 SetVarReportState(ID,1)，1→0 关报值。VarValueReport 接 List&lt;VmIO&gt;，对 int?/float?/原字符串结果数组转换，发模块事件，再对同名输出 OnVarIOChanged。UI Loaded 创建 VariableManager/GetDataAsync；值上报通过 Dispatcher 更新 Items，并暂时移除自身 ValueChanged handler，避免回写反馈。</p>
<p><code>VM.Core/VmSolution.LoadGlobleModules</code> 通过 native GetAllGlobalModule 还原模块表，已有ID可ReloadModule，缺失走 CreatModuleByInfo/PreAddModuleTo/集合添加。GlobalVariableDialog.LightSave_Click 调原 LightSaveSolutionEx。main自有格式可以显式独立实现，但不能把未恢复的 native .sol 或 .gvar 编码说成已等价。</p>
<h2 id="不实施局部替代的理由及解除条件">不实施局部替代的理由及解除条件</h2><p>main 全局入口仍为 null，ModuleDescriptor没有全局动态模块身份与全类型变量服务。完整 B05.2 需要方案级全局模型、动态输出/双向订阅与改名改型清理、数组/复合支持域、执行读取与写回、事件引用计数/释放、持久恢复的统一合同。它不是只新增独占文件即可闭合的三标量UI；也不能借此在 main 复制插件配置框架。根线明确不做该 subset，本线无产品改动，实施分子增量0。</p>
<p>最小后续是基于现有框架数据类型/订阅合同明确全局服务及完整支持域，主智能独占修改 SolutionDocument、GraphEditorDocument、执行上下文和主入口；插件动态参数目标只消费已交付能力。原支持域未实现的类型不得隐去后把完整单元关闭。人工验证后置不解除上述尚缺的实施。</p>
