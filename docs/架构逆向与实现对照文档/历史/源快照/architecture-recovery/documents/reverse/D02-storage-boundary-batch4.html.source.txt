<h2 id="源码依据和操作范围">源码依据和操作范围</h2><p>完整当前源码可直接审查，因此此独立格式切片不调用 REA 原生工具；原厂其他三线仍按 REA 技能取证。不能从本地 JSON 规则推导原厂 sol 规格。</p>
<ul>
<li><code>src/VisionFramework/SolutionStore.cs::Load</code> 在 JSON 解析前检查文件长度，超过 <code>32*1024*1024</code> 才拒绝；使用默认 JsonDocument 深度限制，遍历所有对象拒绝重复属性，再以 Disallow 反序列化并检查版本及结构。</li>
<li>类型化文档字段拒绝未知成员；<code>NodeDocument.Parameters</code> 的 JsonElement 是不透明 JSON 载荷，但依然经过递归重复属性检查与解析深度限制。未知文档字段和未知插件载荷不是相同策略。</li>
<li><code>SolutionStore.Save</code> 先结构校验、序列化和大小校验，再创建目录及同目录临时文件、Flush(true) 和替换；本轮只验证进程内超限拒绝，不据此声称断电原子性。</li>
<li><code>src/VisionEditor.Core/GraphEditorDocument.cs::Load</code> 成功 Load 后才替换文档、选择、路径和历史；<code>Save</code> 在准备、重定位、写盘成功后才提交编辑器状态。失败准备器的外部副作用不在这一保证之内。</li>
</ul>
<p>探针 <code>tests/VisionEditor.StorageBoundaryChecks</code> 使用真实 main Core/Store，独占 GUID 输出目录，保留所有有效/非法文件及结果，不访问安装原件、设备、tool-plugins。建立两个改名历史并 Undo 一步，使拒绝前同时有 Undo/Redo 和脏状态；逐次核对完整公共状态及 Changed/SolutionReplaced 次数，最后实际 Redo/Undo 验证历史仍可用。</p>
<p>矩阵包括：未来版本、未知流程字段、必填模块版本为空、插件 JSON 深层重复字段、70 层载荷、输入精确 32MiB/多一字节、输出精确 32MiB/多一字节、PrepareSave 产生超大文档、未知插件载荷往返。固定小输入在大文件尾部填空白，区分文件长度限制与实际 JSON 载荷大小；大输出用 ASCII 名称精确控制序列化长度。</p>
