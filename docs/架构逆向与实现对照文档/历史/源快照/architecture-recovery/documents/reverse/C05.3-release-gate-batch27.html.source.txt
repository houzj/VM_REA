<h2 id="源码证据">源码证据</h2><ol>
<li><code>src/VisionFramework/ToolDebugSession.cs</code> 的 <code>Start</code> 使用 <code>CancellationTokenSource.CreateLinkedTokenSource</code>，把调用方取消和会话关闭合并；<code>Execute</code> 的 <code>finally</code> 清除当前 cancellation、恢复 Idle/Disposed，并释放 CTS。<code>StopAsync</code> 取消当前会话并等待其任务，<code>DisposeAsync</code> 置 closing、等待 Stop 后强制 Disposed。这一链已具备托管会话的取消、等待和资源释放契约。</li>
<li><code>src/VisionEditor/ToolEditorHost.cs</code> 的 <code>BindToolEditorLifetime</code> 在窗口 Closing 中取消关闭、等待 <code>context.Session.DisposeAsync()</code>，再移除会话并重新 Close；<code>MainWindow.OnClosing</code> 顺序等待 Group 配置窗口和所有调试会话后才继续关闭。异常只写主窗口状态，不吞掉会话等待。</li>
<li><code>src/VisionEditor/ToolExecutionScope.cs</code> 的 <code>ReplaceExecutionScope</code> 使 owner epoch 失效、解绑旧 scope 事件、取消 activeRun、清理 configuration/workflow 结果并 Dispose 旧 scope，再创建并绑定新 scope。旧 configuration finally 以 owner epoch 保护，不会递减新代计数。</li>
<li>原始托管证据：<code>analysis/decompiled/VM.Core/VM.Core/VmSolution.cs</code> <code>Dispose</code>（约 2439 行）在 SDK 模式通过 <code>DestoryThirdHandle</code> 后 <code>SyncWaitor.Wait</code>，非 SDK 模式执行 <code>base.Dispose</code>、<code>Dispose(false)</code> 并设置 <code>IsDispose</code>；<code>VmProcedure.Dispose</code>（约 1298 行）解绑状态回调、导出撤销数据、断开模块、CommonDispose、移除流程并删除原生 process。原生设备/SDK 回调的具体 owner、ABI 和释放错误仍未由当前证据闭合。</li>
</ol>
