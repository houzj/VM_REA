<p>最新职责：本项目负责插件相关框架的完整任务设计与实现；主项目负责通用工作流/画布/Group/生命周期，用户自行管控两项目。具体能力与交叉文件所有权见 <a href="PLUGIN-DEVELOPMENT-BOUNDARY.html">PLUGIN-DEVELOPMENT-BOUNDARY.md</a>，不按程序集目录一刀切。当前只更新职责文档，保留已有验收候选。</p>
<h2 id="已确认的架构差异">已确认的架构差异</h2><p>原厂普通模块链路为 <code>ModuleParam → AlgorithmTabRoot → ParamsConfigControlBase → ParamsTabUserControl → ParamListView/ParamUserControl → UserTempConverter → DataTemplate</code>。外层 <code>ParamsTabControlBase</code> 是普通参数窗口；<code>ParamsConfigWithRenderControlBase</code> 是另一种组合宿主，不能将其宽屏布局作为所有节点的默认参数窗。</p>
<p>原厂配置模型与执行模块各有职责。<code>AlgorithmTabRoot</code> 承载页签、分组、外部参数、左右底部命令、选中页、窗口尺寸、订阅和 ROI 桥接。<code>NameValueItem</code> 的展示类型、状态和命令驱动模板选择。执行参数的整数、浮点、字符串类型不足以决定控件类型。<code>GroupLinkItem</code> 克隆公共组内容并设置父链；不是丢弃组后手写几个相似字段。</p>
<p>当前 <code>ModuleDescriptor</code> 继续承担执行身份、输入输出及参数校验，这是合理的边界。缺失的是并列的配置模型及其公共宿主合同。<code>IWpfToolEditorFactory</code> 直接返回任意 <code>Window</code>，使插件各自决定页签、尺寸、按钮和调度；宿主又用 <code>ShowDialog()</code> 打开，造成系统性偏差。修复不能只扩大 <code>ModuleDescriptor</code> 或修改几个窗口尺寸。</p>
<p>具体源码、行号、原始资源哈希和确认程度见 <code>docs/plugins/configuration-host-lifecycle-evidence.json</code>；模型和模板的专项清单继续补入本目录。没有执行原厂完整桌面生命周期的部分均保留为源码确认，不冒充运行验证。</p>

<p><code>NeedPopTip</code> 不能按名字统一解释为操作前确认。原厂清图先执行，再按成功/失败显示消息；重置参数有独立的确认流程。执行按钮、连续执行、生成文件和清除操作必须由各工具的 XML 和命令类型决定。连续自执行原厂有 300 ms 调度和结果回调门控；当前插件里的 1 ms 循环不是等价实现。</p>
<h2 id="实施状态">实施状态</h2><ul>
<li>已完成普通参数窗口生命周期的首个公共切片：同一节点重用当前窗口，换节点关闭旧窗，设置主窗口所有权，非模态 <code>Show()</code>，关闭释放身份，方案切换与宿主关闭清理。11 项离屏 WPF 生命周期检查通过；它们不是完整模板验证。</li>
<li>已新增并列配置模型提供器，宿主优先使用公共 ModelWindow；标定加载已真实接入模型、生产模板、订阅/运行和文件通知服务。其余旧窗口工厂仍属于过渡状态，不能因此获得 UI 闭合认定。图像源正在迁移；N点复杂内容仍有明确缺口。</li>
<li>普通配置、带渲染配置、专属控件、订阅、自动执行和公共显示仍需逐项迁移与跨节点回归。尚未把旧窗口机械缩小作为框架修复。</li>
