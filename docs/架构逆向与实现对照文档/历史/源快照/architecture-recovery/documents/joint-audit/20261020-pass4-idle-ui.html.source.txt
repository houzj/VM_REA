<li>取证基线：<code>main</code> <code>31f0dee5f345e6c73cf2e2d3e14d91987b049547</code>，工作区另有主线在制文件；本轮只写 <code>tests/WorkflowIdleUi.Checks/</code>、本文和忽略目录 <code>analysis/joint-audit/idle-ui/</code>，未触碰主线源码、插件工作树、用户窗口或用户进程。</li>
<li><strong>实测发现</strong>：自有离屏 WPF <code>MainWindow</code> 在真实 <code>ImageSource → ImageBinary</code> 流程成功后，空闲 1.5 秒期间持续收到 Dispatcher 心跳；刷新、节点选择、流程切换、文档保存和关闭在本探针中均未出现长停顿。随后打开当前二值化配置窗口，完整宿主调用同步占用 UI 线程 <strong>1.54–5.95 秒</strong>（不同受控运行），明确可造成临时“未响应”。即使 64×64 小图，禁用 dump 的打开仍为 <strong>3.94 秒</strong>。关闭约 <strong>0.30–0.47 秒</strong>。这仅证明当前重建版的离屏配置打开热点；用户那次看似空闲后的永久卡死<strong>未复现、根因未定位</strong>。</li>
<li>分段工厂探针使用简化 <code>ToolEditorContext</code>：64×64 时 <code>ImageBinaryWindow</code> 构造 <strong>292 ms</strong>，随后 <code>Window.Show()</code> <strong>2599 ms</strong>，关闭 <strong>430 ms</strong>；长段主要在 <code>Show</code> 触发的 WPF 加载/布局/呈现调用中，但简化上下文与完整 <code>OpenToolConfiguration</code> 不同，<strong>不能进一步归咎某个绑定、资源或 ROI 子步骤</strong>。未做任何插件窗口性能修复。</li>
</ul>
<h2 id="源码调用链与边界">源码调用链与边界</h2><p><code>src/VisionEditor/WorkflowExecution.cs</code> 的 <code>StartRunCore → RunCore</code> 在 <code>Task.Run</code> 内启动 <code>SolutionExecutor.RunAsync</code>，完成后 UI 延续段将 <code>ExecutionSessionResult</code> 写入 <code>workflowSessions</code>、刷新结果。<code>src/VisionEditor/WorkflowTabs.cs</code> 的 <code>RefreshAll</code>、<code>SelectWorkflowNode</code>、<code>SelectWorkflow</code> 是本探针分段入口。双击节点走 <code>src/VisionEditor/MainWindow.xaml.cs</code> 的 <code>OpenNode → OpenToolConfiguration</code>；<code>src/VisionEditor/ToolConfigurationHost.cs</code> 在 UI 线程创建上下文，接 <code>ConnectToolEditorServices</code> 与 <code>ConnectConfigurationRoi</code>，再由 <code>IWpfToolEditorFactory.CreateWpfEditor</code> 构造窗口。<code>src/VisionPluginContracts/ToolConfigurationWindowHost.cs</code> 的 <code>Open</code> 同步执行 <code>create()</code>、设置 <code>Owner</code>、<code>window.Show()</code>、<code>Changed → RefreshAll</code>；<code>Close</code> 同步调用 <code>Current.Close()</code>，Closed 事件再次 <code>Changed → RefreshAll</code>。<code>src/VisionPlugins.ImageBinary/ImageBinaryPlugin.cs</code> 工厂创建 <code>ImageBinaryWindow</code>；其构造函数在 <code>src/VisionPlugins.ImageBinary/ImageBinaryWindow.xaml.cs</code> 初始化资源、ROI、图像、多个参数页和控件。上述是当前实现的路径，不代表原厂的性能或线程行为。</p>
<p>原厂入口边仍按前轮已取证路径 <code>VmProcedureDecorator.RunOnceCommandExe → VmProcedure.Run(null,bIsWait:false) → ProcessManager.SyncExecuteOnce → IMVS_ExecuteOnce_V30</code> 保留；<code>bIsWait:false</code> 只排除托管等待，原生调用持续时间未测。本轮无原厂 UI 堆栈，不拿重建版计时推断原厂挂起原因。</p>
<h2 id="可复验探针与观测">可复验探针与观测</h2><p><code>tests/WorkflowIdleUi.Checks/Program.cs</code> 的自有窗口位于 <code>(-20000,-20000)</code>，禁自动相机发现；内存构造 GrayImage，通过真实 ImageSource 提交并运行二值化，确认节点 <code>Success</code>。<code>DispatcherTimer</code> 每 20 ms 记录心跳；每个同步 UI 操作前后分段计时，段间泵 Dispatcher。后台 watchdog 只监视自有测试 PID，心跳缺失 &gt;1 秒留事件，可选 <code>--dump</code> 生成 <code>MiniDumpWithThreadInfo</code>，自有进程总时限 20 秒。保存使用 <code>GraphEditorDocument.Save</code> 到审计目录，避免主窗口最近文件副作用。详见 <code>analysis/joint-audit/idle-ui/preflight.md</code>。</p>
<p>从仓库根目录执行 <code>dotnet run --project tests/WorkflowIdleUi.Checks/WorkflowIdleUi.Checks.csproj -c Release -- no-dump-2048 2048</code>；小图将末尾两个参数改为 <code>no-dump-64 64</code>；简化拆段运行 <code>-- split-64 64 --factory-split</code>。测试预期在心跳超 1 秒时退出码 1 并保留分段日志；不要把它当编译或方案执行失败。</p>
