<h2 id="源码边与原版限度">源码边与原版限度</h2><p>当前 <code>MainWindow.StartRunCore → RunCore</code>（<code>src/VisionEditor/WorkflowExecution.cs:19–59</code>）先在 Dispatcher 捕获 <code>Progress&lt;ExecutionEvent&gt;</code>，然后 <code>Task.Run</code> 把 <code>SolutionExecutor.RunAsync</code> 移到后台；完成、<code>IsCurrentExecutionOwner</code>、结果/历史发布、<code>FinishWorkflowRun</code> 回 Dispatcher。<code>MainWindow.DrainWorkflowBeforeClose</code>（<code>src/VisionEditor/MainWindow.xaml.cs:88–106</code>）在运行中第一次关闭时取消流程并等待 <code>activeRun</code> 清空，再发第二次关闭；<code>OnClosed</code>（<code>WorkflowExecution.cs:91–99</code>）失效 owner、取消并释放 scope。<code>ModuleExecutionScope.Dispose</code> 在租约退出后释放资源；其 <code>Stopping</code> 令牌须在关闭前捕获，不能在已释放的 CTS 上再读取属性。</p>
<p>原版 UI <code>VMControls.WPF.DataForUI.VmProcedureDecorator.RunOnceCommandExe</code> 调 <code>VmProcedure.Run(null,bIsWait:false)</code>；原 <code>VM.PlatformSDKCS.ProcessManager.SyncExecuteOnce</code>（<code>analysis/decompiled/VM.PlatformSDKCS.Audit/VM.PlatformSDKCS/ProcessManager.cs:277–299</code>，SHA-256 <code>06FEE7C7B5387FEA086ABE5073BE5DD2606AD121D9BC64B0AB9335BACE100414</code>）先调 <code>ServerSDKAPI.IMVS_ExecuteOnce_V30</code>，只在 <code>bIsWait=true</code> 时调用 <code>SyncWaitor.PrecisionWait</code>。这证实原 UI 命令<strong>不在托管层等待流程完成</strong>；原生 P/Invoke 本身返回前的耗时和实际线程/回调仍未知。当前 <code>Task.Run</code> 是本地宿主响应性实现，不冒称原版线程拓扑逐指令一致。</p>

<p>J12 仍缺：用户同构方案/图像及 EXE 身份、空闲触发时序、真实卡住时 UI 线程栈；相机/文件夹事件、Group、其他已接入插件在工作线程上的 UI 亲和副作用未由本夹具覆盖。下一探针应在自有受控实例固定这些输入并在超阈值心跳间隔捕获该进程线程栈；原厂 <code>IMVS_ExecuteOnce_V30</code> 的本地线程/回调时序需另取原生指令或受控差分。不要用本地测试通过给原厂行为或全部插件打等价标签。</p>
