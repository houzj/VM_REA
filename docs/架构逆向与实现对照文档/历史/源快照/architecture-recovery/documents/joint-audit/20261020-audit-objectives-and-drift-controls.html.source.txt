<p><strong>本轮完成口径：</strong> 逐项核原版资源/源码/必要原生指令、当前插件 UI 与后台实现、算法的已取分支，以及框架接入、真实载荷、结果/错误、Group 与保存重开。先复用共同链，再查十项独有边。找不到原始函数体、安装运行态或同条件差分时，记录精确未知与解除条件；仅有“已记录未知”不能冒充源码已取得、算法等价或整工具联合审核完成。人工/设备验收后置。主框架 41/96 的实施指标只在实施单元真正修改并自审核后改变，不用审核报告数代替。</p>
<p>已接入工具按<a href="20261020-architecture-chain-groups.html">架构链路聚合分组</a>执行：共享框架边只审一次；18 个工具与 Group 各有唯一差异归属，跨组交付引用证据而不重复审核。分组不改变下列 J01–J12 的证据门。</p>

<p>日期：2026-10-20。审查基线为 main <code>120611182c8908334298ba47eb9244bb1f9b6307</code> 加已明列的未提交工作区；不得将工作区状态称为已交付基线。本文是<strong>审核规则和任务清单</strong>，不改变既有 <code>framework-reverse-plan.json</code> 的 96 个框架实施单元，也不改变用户对人工验收后置的要求。</p>
<h2 id="1-审核目标和固定范围">1. 审核目标和固定范围</h2><p>目标不是检查单个窗口是否像原版，而是对每个已接入工具建立一条可追溯的链：</p>
<p><code>原厂模块/资源身份 → 工具发现与实例化 → 配置模板及事件 → 输入候选/连接/订阅 → 真实数据形状 → SelfRun/全流程/Group → 输出与显示 → 失败/取消/释放 → 保存/重开/撤销</code>。</p>
<p>每条边同时核 <strong>原版证据、当前实现、可复验操作</strong>，缺一项就保留开放状态。原厂证据必须到类型/成员/资源/分支；原生反编译歧义要核调用前后指令、ABI 与异常路径。截图只指出待审状态。当前源码恰好能运行、测试通过、某个数值夹具相同，都不能把未知原厂行为改写成“已复刻”。</p>

<h2 id="4-每轮审核的固定工作包与退出门槛">4. 每轮审核的固定工作包与退出门槛</h2><p><strong>第 1 包：排除误判。</strong> 固定当前 EXE/方案/样图身份，建立受控无响应诊断，取得 UI 线程停顿点；并复验二值化 RGB/Gray 图执行与直接运行两种错误路径。退出物：事件/堆栈/计时（若未重现，明确未重现条件），以及已保存的输入类型探针。当前只有事件和类型探针，卡死原因<strong>未关闭</strong>。</p>
<p><strong>第 2 包：原版共同合同。</strong> 获取候选/连接/像素格式、SelfRun 上游准备、输出清理的原方法体或受控差分；以 ImageSource→Binary→实际下游为首条链，同时用 N 点复杂配置/Group 与一个非图像节点检验规则通用性。退出物：J04–J10 的逐边矩阵，不得以 XML 声明替代运行边。</p>
<p><strong>第 3 包：按工具簇推广。</strong> 已接入的图像源/二值化、十个标定、位置修正、分支、多图/缓存/光源按实际依赖分组；每个工具先做 J01–J05 静态与类型检查，再做 J06–J11 完整链。设备不可用时明确隔离设备分支，不能把无设备模拟当原机证明。未接入目录只做证据/依赖清点，待用户指定实施范围。</p>
<p><strong>第 4 包：闭环和防回归。</strong> 对已确认差异按所有权实施最小改动，保留失败样本；同一实际方案做根流程/Group、Undo/Redo、保存重开、失败/取消/关闭；主线串行构建与检查。每个改动须指出所修 J-ID 和原始分支。自审核通过的框架具名单元才增加 96 分母的实施进度；联合审核本身不抬进度。</p>
<p>每包开始先固定 1–3 个<strong>能改变状态的具体问题</strong>及退出证据；结束公布已关闭/未关闭 J-ID、真正新增的实施单元、当前 41/96 基数、阻塞解除条件。若原生 provider 不可用，继续托管 CIL/资源/调用者/受控探针等独立可做部分，但不得用新增报告数量替代问题关闭。</p>
<h2 id="5-防止越逆越偏的强制复核">5. 防止“越逆越偏”的强制复核</h2><ol>
<li><strong>反向可证伪。</strong> 每个推断都列一个会推翻它的输入/状态。比如“原厂自动灰度化”必须能被 RGB 输出、输入格式字段、原生校验分支和输出像素验证；缺其一只写假设。</li>
<li><strong>保留负例和旧失败。</strong> 新测试通过不覆盖旧失败；身份变更、依赖变更、代码重构后按受影响调用边重跑，不复制旧日志充当前基线。</li>
<li><strong>原版与兼容层分栏。</strong> 原厂 <code>InputImage</code>、本地 <code>Image</code>、原厂 <code>.sol</code>、本地 JSON、SDK SelfRun、本地缓存自运行分别列名，禁止同名化后宣称等价。</li>
<li><strong>证据修订机制。</strong> 当新 CIL/汇编/原机差分推翻旧结论，记录旧主张、反证、受影响实现/测试/文档，撤销相关完成状态；原生 ABI 尤其不能凭反编译器展示的实参数量断言丢参。</li>
<li><strong>所有权约束。</strong> 主线审框架合同、调度、Group、存储和集成；插件线审工具算法与公共插件配置。跨线字段/端口/生命周期修改先登记 producer、consumer、payload、生命周期、兼容和接受证据，指定唯一写入者；<code>tool-plugins</code> 在制文件保持不动。</li>
<li><strong>操作证据不混层。</strong> 源码确认、当前产品自测、SDK 探针、原厂桌面差分、人工验收分别标记。离屏窗口不能算用户桌面手验；安全拒绝未知 native 行为不是算法复刻。</li>
</ol>
<p>最终可交付的“完整审核”应是一张每工具×J01–J12 矩阵、原始证据索引、差异/FCR、可复验探针与失败库、实施提交和剩余未知清单。只有所选范围内所有目标的证据门满足、差异已实施并自审，才能宣称该范围闭合；人工验收继续单列，不计实施百分比。</p>
