<h2 id="原版窗口与-setter-链">原版窗口与 setter 链</h2><p>原安装 <code>IMVSNPointCalibModu.dll</code> SHA-256 <code>F8E07023A816C55FF07906E8889F45B93658F59CE88F040AD2204A70922F4839</code>。托管反编译位于只读 <code>worktrees/tool-plugins/analysis/full-audit/n-point-calibration/managed/control/IMVSNPointCalibModuControl/</code>：<code>NPointList.xaml.cs</code> SHA <code>B972D12AF77B27DC3A19E00629C77F3BED58D3FD7A266DD0AA28050A281B5A46</code>，<code>PointList.cs</code> SHA <code>A396060C73DBF56B1A7FB7849A4BCD17FE5CBC3D04AD8356F68D4B3B1C9B3813</code>，<code>NPointList.xaml</code> SHA <code>92945CE0D5ED92F98F12187A0EB92F1673516760B894F0CD52F89FC2C7341D79</code>。<code>EditButton_Calib</code> 的 XML 内嵌 <code>IMVSNPointCalibModuControl.NPointList</code>；原 <code>UserControl_Loaded</code> 调 <code>Init</code> 并把窗口高改为 399。</p>
<p>原 <code>NPointList.Init</code> 先读 <code>CalibPointTotalNum+RotPointTotalNum</code>，逐行对 <code>ImagePointX/Y</code>、<code>WorldPointX/Y</code>、<code>DeltaAngle</code> 各读取并 <code>float.Parse(...).ToString(&quot;f3&quot;)</code>，构造 <code>PointList</code> 时依序赋五个属性。五 setter 仅在文本变化时向 <code>((IUserStringData)OwnerParam)[属性名+ID]</code> 写<strong>该单字段</strong>；失败时不更新显示 backing field，成功后才发 <code>PropertyChanged</code>。默认 backing 为 <code>&quot;0&quot;</code>，因此默认数值格式化 <code>&quot;0.000&quot;</code> 仍是一次属性变化；默认 9+3 行可有 60 次<strong>原版单叶 setter 写入</strong>。不能把“打开时 60 次 setter”本身称为当前实现特有 bug。</p>
<p>原原生 <code>CIMVSNPointCalibModu::SetParam</code> RVA <code>0x3e560</code> 的 C 体 <code>worktrees/tool-plugins/analysis/full-audit/n-point-calibration/native/18003e560.c</code> SHA <code>D28D9DD6D9618EEE3F877223FA8148F9BB3A3CBB5721061919BBFB55DBDDA95B</code>，按五种参数名前缀和尾部索引进入对应处理；Ghidra 对若干 <code>sscanf_s</code> 目的地址未可靠还原，此处只把它作为单叶 native 调用分支证据，不声称精确内部矩阵偏移。</p>
<h2 id="当前产品的额外放大路径">当前产品的额外放大路径</h2><p>当前 <code>NPointConfigurationPointEditor</code> ctor 也按行五字段调用 <code>commit(i,a,formatted)</code>，单格 setter 调一次 <code>commit</code>，这一层与原托管 setter 粒度一致。差异在 <code>NPointConfiguration.CreateConfiguration</code> 所供回调：<strong>每一次单叶提交</strong>都执行 <code>PointValues()</code>，从 <code>Snapshot(Current())</code> 复制全部 32×5=160 点叶为新的 JSON 参数字典，再覆盖一个字段；随后 <code>Apply(next)</code> 把整个字典交 <code>ToolEditorContext.Apply</code> 并调用 <code>UpdateConfiguration</code>，后者 <code>Synchronize</code> 又扫描全部 160 点叶与完整参数字典。</p>
<p>主窗口 <code>ToolConfigurationHost.OpenToolConfiguration</code> 的 <code>Apply</code> 调 <code>GraphEditorDocument.SetProcedureNodeParameters</code> 并记执行 scope 参数；该图方法验证/复制整份参数，<code>Edit</code> 执行完整方案复制/结构验证、<code>RecordEditHistory</code>、递增 revision、同步触发 <code>Changed</code>。此配置宿主没有用 <code>ExecuteConfigurationEdit</code> 包住 N 点窗口。<code>MainWindow.xaml.cs</code> 的 <code>doc.Changed</code> 回调每次调用 <code>RefreshAll</code>；<code>WorkflowTabs.RefreshAll</code> 进一步 <code>GraphValidator.Validate</code>、<code>RenderGraph</code>、<code>RefreshRight</code>，而 <code>WorkflowCanvas.RenderGraph</code> 清空并重建图层。因此默认 12 行窗口初始化的 60 次单叶 setter，在当前宿主成为 <strong>60 次整节点/方案编辑、历史记录和主窗口刷新</strong>；单格实际编辑也走一次该整链。此为源码可证的性能放大点，不是已经量到的原厂/当前时延比，也不能单凭它断定任何一次系统“未响应”的唯一原因。</p>
<p>安全的修复方向仅限主框架对参数批量落盘/Changed 合并或配置操作历史合并，同时保持原单叶 setter 成功/失败、格式化、即时回写及结果可见时序；插件项目拥有点表和配置回调。具体跨项目合同应先列 FCR，不能在 main 另造点表配置框架，也不能把五个原 setter 错改为一次 native 批量写入。用户桌面卡顿需要另做交互桌面同机时序，当前受控 API 计数是机制证据。</p>
<h2 id="受控同-api-探针与边界">受控同 API 探针与边界</h2><p><code>tests/CalibrationNPointEditChain.Checks/Program.cs</code> 在 STA 构建当前真实 <code>NPointConfigurationPointEditor</code>，以产品回调同构算法写入真实 <code>GraphEditorDocument.SetProcedureNodeParameters</code>，对单格编辑执行 Undo/Redo，再保存/重开图并通过 <code>SolutionExecutor</code> 运行 N 点→文件→标定加载链。没有自动点击用户交互桌面，也没有创建/关闭他任务窗口；因此不声称已做 MainWindow 实体交互验收。探针的 GraphEditorDocument Changed 次数是确定可复验的内核计数；MainWindow 每次 Changed 的处理路径来自上述产品源码。</p>
