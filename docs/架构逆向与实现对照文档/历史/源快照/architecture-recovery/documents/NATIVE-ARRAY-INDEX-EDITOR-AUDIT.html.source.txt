<p><code>DeleteTextBox</code> 的 <code>Delete</code> 清空整个文本（<code>DeleteTextBox.xaml.cs:50-61</code>），且数字模式拦非数字输入、关闭粘贴命令（<code>96-114</code>）。索引所用 <code>ButtonSelecter_sub</code> 模板并未启用 <code>IsNumberOnly</code>，因此其正文容许 <code>模块.端口</code> 路径。<code>ClearBetweenBracket</code> 的去括号代码存在边界可疑处（<code>IndexOf</code> 返回 -1 时的算术），不宜复制潜在缺陷；应通过实际 VM 差分确认边界结果。</p>
<h2 id="与现有-group-交互的差异">与现有 Group 交互的差异</h2><p><code>src/VisionEditor/GroupConfigurationControls.cs:32-46</code> 使用独立的来源按钮、数字 TextBox、宽 26 的 <code>…</code> 索引按钮和模态 <code>WorkflowSourcePicker</code>。可选择前置的标量整数，也可键入非负整数，<code>GroupOperand.IndexSource</code> 保存结构化引用；<code>src/VisionFramework/GroupBreak.cs:5-34</code> 将运行时整数解析为数组索引。这是已接通的独立实现，但不是原生的 <code>模块.端口[索引]</code> 单文本框、32 宽订阅侧按钮、180×180 正文 Popup / 240×480 独立窗双模式状态机。</p>
<p>当前界面 <code>selected?.Array==true</code> 才出现索引行；原生来源一选中数组即可形成 <code>[]</code>，用户将光标放入括号才弹索引树。当前常量要求非负 int，而原生 <code>GetBindIndex</code> 接受 <code>MathHelper.IsNumber</code>，具体负数、小数如何与数组运行逻辑配合还未验证。框架约束应保留，除非原生运行差分证实其他值有效。</p>
<h2 id="可实施接口与缺口">可实施接口与缺口</h2><ol>
<li><strong>无需插件契约即可闭合的 Group 操作</strong>：给 Group 数组操作数提供 <code>来源路径[整数索引]</code> 编辑显示；用现有 <code>WorkflowSourceOption</code> 筛前置 <code>DataKind.Integer</code>、标量来源；正文索引树只选择整数叶和“清空索引订阅”；源切换保留既有索引；光标触发正文 180×180 树；独立窗 240×480 在主来源/索引树之间切换。提交时仍写现有 <code>GroupOperand.Source</code>、<code>Index</code> / <code>IndexSource</code>，由既有 <code>GroupBreak</code> 验证和执行。</li>
<li>建议隔离 UI 状态模型：<code>CurrentText</code>、<code>Caret</code>、<code>HasFocus</code>、<code>IsInlineIndexOpen</code>、<code>IsSourceOpen</code>、<code>IsDetachedOpen</code>、<code>DetachedMode=Source|Index</code>、<code>SelectedReference</code>。单独纯函数检测光标是否在同一对 <code>[]</code> 内及安全替换内容。索引源列表刷新在进入括号和开启 Popup 时发生，防止历史节点残留。</li>
<li><strong>数据缺口</strong>：原生完整 <code>GetFrontFilterTree</code> 的 Holder 分组、全局变量、层级、翻译名、远端路径与 VM 内部元素生命周期依赖原生模块树；框架只可用现有节点/流程变量引用填充同形树。Group 的前置标量整数筛选符合当前运行约束，但不能称为全插件通用索引树。</li>
<li>原生数组索引 UI 没有在本次运行的 VM 里做同状态截图和点击差分；源码确认的是模板/命令静态结构，视觉像素、Popup 定位、负数/小数实际运行仍待验证。专用 <code>ButtonSelecterConfig_sub</code> 在 <code>paramusercontroldatatemplate.xaml:2625-2690</code> 也有同类双 Popup，但宽度/偏移有所变化，应按具体宿主模板选择，不能全局共用一个尺寸。</li>
</ol>
<p>建议闭合验收：添加两路数组来源和前置整数来源，选第一路后填常量索引，切换第二路确认索引保留；把光标移入/移出括号验证 180×180 索引树开关；选择整数叶、清空索引来源并改回常量；在独立窗打开时验证主树/索引树切换；保存重开执行 Group 两轮并确认订阅源更新后的数组元素及越界报告。该测试只证明托管实现行为，VM 原生运行差分仍单独记录。</p>
