<h2 id="原厂链与当前差异">原厂链与当前差异</h2><p>原厂 <code>VM.Core/VmModule.cs:1809</code> 设置模块专用 AlgorithmTab.xml 路径；<code>VmModuleExtern.GetParamRoot</code> 缓存 <code>ModuleParam.Data</code> 中的 AlgorithmTabRoot。<code>ParamsConfigControlBase.xaml.cs:217–249</code> 加载模块控件程序集、获取同一模型并按语言选择尺寸。<code>AlgorithmTabRoot</code> 默认中文宽 420、英文宽 680、高 500；本模块 XML 未覆写这些值。这是源模型逻辑尺寸，不能据此声称操作系统 DPI 或外框像素已一致。</p>
<p>共同基线中的 NPointPlugin <code>CreateWpfEditor</code> 直接创建 NPointWindow（本轮迁移前状态）。该窗口手工创建并反复清空重建页签、数值框、订阅按钮和表格，绕开 XML 模型、源模板以及通用操作路由。换字体或边距无法恢复被绕开的模型语义。迁移应使用公共配置 Session，并为原厂自定义叶提供显式工厂，保留同一模型的触发、初始化、子模型和生命周期。</p>
<p>原厂实际有效页签为基本参数、运行参数、结果显示。结果显示不是算法输出字符串：XML 1057 链接 <code>TextDisplayGroup</code>。安装 <code>Module(sp)/Group.xml:2767</code> 起将文本内容、OK/NG 颜色、字号、透明度桥接到 Show Text 显示对象及其 Feature。<code>BridgeItemBase.BindingPathA</code> 为 <code>BridgeObjA.&lt;PropertyName&gt;A</code>，GetParamUnit/SetParamUnit 都是空操作；不得把这些值当算法参数保存。StringConfig 还在光标位置插入源树引用，不能以普通 String 替代完整行为。</p>
<h2 id="自定义编辑和文件操作">自定义编辑和文件操作</h2><p><code>RotPointTotalNum</code> 是 <code>EditButton_Calib : Integer</code>，模板将 <code>Integer_Sub</code> 与 32×32 原厂编辑图标并排；按钮执行 <code>EditDialogA.ClickCommand</code>。XML 的嵌套 EditDialog 创建 <code>IMVSNPointCalibModuControl.NPointList</code>。OpenDialog 缓存内容实例、设置父模型和 IOwner，再 ShowDialog；并非独立的“标定点”新行。XML 对话框初值为 493×700，但原厂 NPointList Loaded 主动将 Owner.Height 改为 399，因此 493×399 是有源码依据的运行覆盖，不能仅据 XML 700 判定错误。</p>
<p>OpenFileForCalibDialog 允许选择尚不存在的标定文件：CheckFileExists=false、CheckPathExists=true。选择后先 CurValue=null，再写路径，以便同路径也触发；随后验证扩展名及父目录，调用 SetParamUnit，成功通知并 PreExecuteRun。它还延迟创建 string ButtonSelecter 子模型，登记初始化、绑定触发及 <code>@ComName</code> 用户模式，隐藏时按删除订阅规则清绑定。普通存在文件浏览器不等价。</p>
<p>SaveFileDialog 的 DisplayType=Command 只是外观复用；点击实际保存路径到 <code>IUserStringData[Name]</code>，然后查找 CalibPathName 并 GetParamUnit 刷新。它使用模块级历史目录、本地 SaveFileDialog 和原厂字面后缀校验。不能把已有 OpenFile 服务接上就声明完成保存行为。远程 FTP/目录行为仍需单独标为未验证。</p>
<h2 id="页脚与物理坐标条件">页脚与物理坐标条件</h2><p>原厂 XML 左侧只有 Reset；右侧是 ClearPoint、SaveFile、ExecuteOnce。不存在手写窗口中的连续执行、执行、确定组合。<strong>NeedPopTip=true 不是操作前 Yes/No 确认</strong>：BottomCommand.ClearCalibPoint 直接写 <code>owner.Params[&quot;Clear&quot;]=&quot;0&quot;</code>，成功后显示 Lang_ClearCalibPointSuc，异常显示 Lang_ClearCalibPointErr，均为普通通知。SaveFile 路由查找 SaveCalibPath.DoSaveFile。</p>
<p>HidePhysicInfoOperation 要求 CalibPointGet=0、WorldRotateAngle 无绑定；按点输入时 PhyPoint 无绑定，按坐标输入时 PhyPointX、PhyPointY 都无绑定，才显示物理坐标参数。原厂 GetOriginalValue 固定 true，ReOperate 恢复 true；每次匹配触发先全部回滚再执行，初始化 Setter 也会执行。公共规则实现位于 <code>src/VisionPlugins.Calibration/NPointPhysicalVisibilityRule.cs</code>，注册由提供器完成。规则不凭 Caption 解析绑定，缺节点给出诊断。</p>
<p>Category.CustomVisibleA 自身只赋值并通知；不能简单认定隐藏 Category 自动删除所有绑定。数值或文件等支持订阅的具体叶子，在自身 CustomVisibleA setter 内结合父 Category.IsDeleteSubscribeA 与本身 IsDeleteSubscribeA 决定清订阅。该分层必须保留。</p>
<h2 id="注释陷阱与验收边界">注释陷阱与验收边界</h2><p>文本检索能找到 Ransac、DistThreshold、SampleRatio，但这些声明处于 XML 注释内；ElementTree 解析后 WeightFun 只有 Least Squares、Huber、Tukey 三项。<strong>不要据 rg 结果把描述符上限从 3 扩到 4，也不要增添原厂未启用控件。</strong> JSON 中 effectiveWeightFunctions 明确记录有效条目。</p>
<p>已有 <code>n-point-ui-evidence.json</code> 是原厂托管控件及 XML 解析器在合成模型下的受控运行，不是完整原生模块，也不是实际 VM 桌面。此轮架构结论为原厂静态证据与独立实现审计；后续必须通过真实产品提供器打开节点、运行实际输入、验证文件和显示桥、再由用户手工验收。自动测试通过不代表完整 VM 等价。</p>
<h2 id="显示坐标订阅的托管投影">显示坐标订阅的托管投影</h2><p>后续原厂源码追踪确认 GetSelectedDisplayFilterOperation 会先找模块输入/输出（含 <code>%name%</code> 结果别名），再回退 Show Text 对应 Feature：Mapping=NULL 时读 Feature.Value，否则读映射 IO 的 ModulePathName。SetResultIOToModuleOperation 则创建/复用隐藏的 IsResultShow 动态输出，设置 RelateIO、RelateIndex 和 Value，最后设置 Show Text Feature.Mapping 并 InitVmIOs。常量和索引也由该路径解释。这与算法输入订阅是不同通道。</p>
<p>新增公共 <code>ToolConfigurationDisplaySubscriptions</code> 是上述语义的<strong>独立托管投影</strong>：用 Display domain、DisplayoutputPositionX/Y 目的身份，保存显式 output/constant DTO 到 DisplayInputBindings 参数；不向工作流输入添加订阅，因此订阅本节点输出不会制造算法自环。枚举仅根流程显式执行祖先及 self 的 scalar int/float 输出；不猜测 Caption，不接受数组、索引、全局、跨流程或远程输入。Bind 后必须读回一致才报告成功。实际缓存无匹配值时将已绑定坐标回落 0 并给诊断，避免旧成功坐标伪装为当前值；未绑定坐标保留显示设置默认值。</p>
<p><code>tests/VisionConfiguration.DisplaySubscriptionChecks</code> 的 27 项检查已通过，覆盖持久化往返、自输出无算法自环、只读应用失败、清除、缺缓存、流程切换、节点删除与不支持边界。窗口关闭后同流程同 ID 的拒写仍由宿主已有 ConfigurationActive 保护；该服务不能凭回调参数独立推断窗口生命周期。原厂 native 动态 IO ABI、索引/全局/远程映射和实际 VM 桌面行为未由这些测试建立。</p>
<h2 id="本轮实现与验证状态">本轮实现与验证状态</h2><p>生产入口现已迁移到 <code>IToolConfigurationProvider</code> 和公共 <code>ToolConfigurationModelWindow</code>，工厂兼容入口也返回同一宿主。使用原厂 AlgorithmTab/Group，而非手工重建三页。原厂点编辑、独立物理坐标显隐、保存文件和复位确认均通过服务接入。路径叶已提升为 <code>VisionPluginContracts.ToolConfigurationCalibrationPathControls</code>，N 点包装保留兼容。</p>
<p>本轮已完成的独立验证：NPoint.ConfigurationChecks 53项，NPoint.ConfigurationControlChecks 25项，VisionEditor.Core.Checks 122项，实际主窗口 WpfChecks 458项（含拖入 N 点节点并打开公共420×500三页窗口）。这些结果确认独立实现和真实宿主接线，不构成原厂桌面像素验收或完整原生一致结论。后续公共框架变更仍须最终回归。</p>
