First .pdata fragment sizes remain partial ABI coverage, not full assembly proof.</p>
<p>Training <code>befdc0</code> fills a float angle table for each level, then <code>c978c0</code> groups entries close to successive90-degree offsets into records of five int32: count plus up to four angle indices. Single-angle input writes count1/index0/groupCount1. Otherwise it clears a byte visited array, computes a float tolerance from first/last angles and count with two original constants, marks each representative, searches forward against tolerance, and limits a group to four. Exact constant bytes and unordered comparisons remain prerequisites to a product translation; no typical angle tolerance is substituted.</p>
<p>For each group the original trainer chooses <code>bf2610</code> if either working dimension&lt;64; otherwise the large path is inlined in <code>befdc0</code>. <code>bf2610</code> is now recovered: actual20-argument surface, cosf/sinf, fixed-point coordinate transforms, mask-dependent selected pixels, statistics and sparse records. It cannot be replaced by the previously reconstructed generic quadrilateral warp. The parent records relative header+0x40 and model offsets; completion writes actual trained level count atmodel+0x24, supplied fixpoint bits at+0x14, model pointer through param11 and used length through param10. Return type recovery for success/failure still requires extended instructions because decompiler labels the large trainer void.</p>
<p>Search <code>b7d5e0</code> initializes temporary records from original PE data, copies current0x98 config, chooses actual level count, then calls <code>b7a1b0</code> workspace setup and <code>c9ad40</code> model preparation (these remain direct missing bodies). Its successful path is <code>c9ae70</code> on image, optional <code>c9ae70</code> on mask then <code>c9aab0</code>, followed by <strong>the same c97090</strong> with min-area32/version1390/image-selector0, then <code>b7a600</code> starting atlevelCount-1. This joins training and search pyramid representation; the candidate pyramid is infrastructure, not full search.</p>
<p><code>c9ae70</code> has eight arguments: source pointer/stride/packed source size, destination pointer/stride/packed output size, top and left offsets. It copies source into the interior, repeats first/last pixel across left/right margins, then repeats first/last completed row above/below. Current caller passes top20 and left20. <code>c9aab0</code> walks the output dimensions and zeroes each image byte when corresponding mask byte==0; nonzero mask retains original image byte. Applying mask before replicated border, using zero border instead of replication, or independently rebuilding a guessed ROI would change this path.</p>
<p><code>c9ae00</code> compares a current counter from c9ae30 with start and unsigned timeout, returns1000001E when elapsed exceeds timeout; exact counter units/source require c9ae30 before a runtime timeout translation. SDK10880 confirms StartParamsControl and active ChooseSpareModelIndex handling, while normal other keys forward to original MVD_Algorithm_SetValueByString and throw its error. Full key mapping/type/range is not established merely by this forwarding body.</p>
<p>Next bounded dependencies are c978c0 tolerance PE constants/actual predicates, bf2610 exact twenty arguments and selected-pixel writes, and b7a1b0/c9ad40 current-model preparation. Do not expand older model versions or declare parity from current oracle leaves. Product remains incomplete: full training/search, native model persistence, output arrays/status/display and registered runtime still need implementation/self-review.</p>
<h2 id="subsequent-source-corrections-and-closed-local-predicates">Subsequent source corrections and closed local predicates</h2><p>Original c978c0 constants are now raw-PE confirmed1f and0.5f; its complete368-byte assembly has been read. Four fixed pure-leaf angle tables completed in original native code with index outputs saved at <code>angle-native/oracle.json</code>, SHA7F9BB2AC7A6A515E727C47283EDB155C0CACD81A1A7027ACFE29AE2D59329244, manifestE391DB44826C5A853DE6D4CE05CA310BDC994FA27AFF4BFCFD3194F04825BDFA. They are scalar group tables, not proof that the current caller generates every tested table. Current trainer itself clips endpoint with the ordered float expression <code>(360f+start)-step</code> before the repeated <code>angle+=step</code> loop. Full-cycle endpoint duplication and mathematical integer-count replacement must not be inferred. Entry assembly befec5/cf/d5 uses MOVSS to load start/end/step; decompiler casts from its inferred int pointer are not integer conversions.</p>
<p><code>c9ad40</code> naming corrected: it is <strong>candidate result capacity/configuration allocation</strong>, not model parsing. It copies the supplied result configuration, computes a count cap as min(unsigned-shifted sign-extended signed-int32(width<em>height), sign-extended int32(MaxNum&lt;&lt;4)), allocates align128(capacity</em>0x3c), initializes activeCount0, and returns1000002B for null allocation. Current normal positive bounded dimensions do not establish bad-overflow parity. <code>c97870</code> expands both dimensions by40. <code>b7a1b0</code> partitions the passed workspace into image, mask and1390 pyramid plus worker buffers; it is not a second model deserializer. Two direct size/layout callees remain <code>c939c0</code> and <code>c99330</code>; no arbitrary binary header assumptions have been implemented from this partial surface.</p>
<p>bf2610 complete explicit asm and actual befdc0 success/failure returns are now documented separately in <code>GRAY-MATCH-SMALL-TEMPLATE-RECORD-SOURCE.md</code> (SHA2B651AABF10F0F9677EB0B0D26AE5ED2EA6EF194139A9D991F78B69FCFCA9105).
