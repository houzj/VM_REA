<p>调用 <code>DestroyShapeInstance</code> 的原 PE thunk 为 <code>18000e1f4</code>，字节 <code>ff2546210000</code> → IAT <code>180010340</code> → <code>MVDShapeCpp.dll!DestroyShapeInstance</code>。原头文件声明接收一个 <code>IMvdShape*</code> 并返回 int；反编译显示的 <code>func_e1f4()</code> 无参是漏参，实际 asm 中 RCX 是所销毁的旧字段值。返回 int 未用于判定 setter 成败；不能假设 destroy 报错会阻止覆盖旧指针。</p>
<p><code>1c00</code> 检查 incoming非null且输出临时指针当前为0，否则抛错误 <code>0x80100006</code>。调用 incoming虚表+0x18取type，仅接受5/6/10；其他类型抛 <code>0x80100001</code>。原 <code>MVD_ShapeParamDefine.h</code> 将它们映射为 Rectangle/Circle/AnnularSector。随后调用 incoming虚表+0x88，将 RAX 写给输出临时指针。</p>
<p>原 <code>MVDShapeCpp.h</code> 基类槽顺序为 destructor、operator=、operator==、GetShapeType…IsValid；三个支持的派生接口新增类型专属 operator=/operator==，其后 Clone 位于+0x88。原头文件将 Clone 定义为深拷贝接口，失败抛异常。这里源码确认 <strong>调用 Clone 并保存其返回值、由 SDK 对其执行 destroy</strong>；未取三个具体 Shape 类的 Clone 函数体，不能额外声称已验证全部字段深复制/分配布局。</p>
<p>clone/类型检查抛异常发生在 destroy old 之前，所以从可见的 setter 顺序看旧字段与标志尚未被替换。若一个实现违背接口返回null而不抛异常，此 setter 无额外非null断言：仍可能销毁旧值、写标志1并存null；此为静态分支边界，未构造或运行非标准 shape。</p>
<p>getter返回内部存储指针，不再clone。因此“相同指针无操作”是与 stored 比较；连续传同一外部原始shape通常仍会重新调用Clone，不能把它等同于输入内容相同缓存命中。Clone是否返回同地址这一非标准情形未运行，不将接口约定替代具体对象证据。</p>
<h2 id="析构链与释放对象">析构链与释放对象</h2><p><code>19c0</code> 调用 <code>19f0(this)</code>；若 deleting标志bit0为1，再经 <code>18000e250</code> 调用 <code>MSVCR90.dll!operator delete(void*)</code> 释放参数对象本身（导入修饰名 <code>??3@YAXPEAX@Z</code>）。</p>
<p><code>19f0</code> 将vptr回写双图类型，按字段顺序：source image +0x10只清0；source ROI +0x18非0则DestroyShapeInstance后清0；source region image +0x20只清0；target image +0x28只清0；target ROI +0x30非0则DestroyShapeInstance后清0；回写基类vptr；target region image +0x38只清0。本析构没有对四个image字段调用destroy，不能把ROI持有策略扩展到image字段。</p>
<p><code>32a0</code> 基本参数析构对 this+0x10（双图参数）及+0x18（双文件参数）各自调用虚表槽0，EDX=1，然后清成员。由双图槽0接19c0→19f0，ROI释放可连到基本参数对象析构；模块何时触发SDK整个工具销毁/重建另属后续生命周期。</p>
<h2 id="对模块与产品的有限含义">对模块与产品的有限含义</h2><p>模块 <code>ProcessAlg</code> 发现某侧ROI向量为空时跳过setter；SDK setter本身支持传null清理，这两条路径不同。只有确认同一SDK参数对象持续使用、且中间无其他clear/reset时，“跳过setter”才会保留此前ROI；本切片不据单一函数断言整个模块必然保留缓存。</p>
<p>产品位置仍为 <code>MapCalibrationPlugin</code> 的两组ROI、<code>MapCalibrationImageSolver</code> 的值式ROI输入；现有托管clone/裁剪不是上述所有权链的原证据。无需把SDK内部裸指针生命周期复制到托管实现，也未提出共享补丁。</p>
