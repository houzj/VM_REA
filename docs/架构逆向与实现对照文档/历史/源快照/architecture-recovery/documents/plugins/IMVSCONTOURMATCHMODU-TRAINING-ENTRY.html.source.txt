<h2 id="actual-ui-dispatch-and-ownership-corrected-by-current-net-il">Actual UI dispatch and ownership (corrected by current .NET IL)</h2><p>Current Contour Control overrides CreatePatE→dynamic CreateDipolePyramid. Passive current class IL is <code>proposals/implementation/CContourPattern.current.il</code> SHA256 <code>5E87CE09A85A3E5578F4F493D54A8329E40F1ECD8EEDE78C9611D8F03D9FF4B6</code>; <code>PMAlignPatternModule.current.il</code> SHA256 <code>BD880C20365BB95B73220669B40F0F6DD16A64B6B5999C4E8D931BB92DAAE9FC</code>.</p>
<p>Actual C# Train at RVA23a8 clears RunStatus, BuildPreCondition checks image/creates module as needed, chooses explicit RegionImage or the managed preprocess-mask tool, sets PMAlignPatternModule InputImage/InputMask/BasicParam, calls TrainPattern, stores returned managed model bytes and length, obtains pattern data and outlines, then sets RunStatus1. <p>PMAlignPatternModule.InitModule creates MvdAlgorithm type512/200h. <p>Raw Ghidra5cc70/bff710 C incorrectly ends at security-cookie calls and prints void. <code>ExportContourTrainingReturn.java</code> clears only those flow overrides, disassembles after-cookie epilogs, fixes function bodies and annotates uint returns from the concrete caller&#39;s EAX checks. <h2 id="automatic-pyramid-finite-child-bodies-and-concrete-call-abi">Automatic-pyramid finite child bodies and concrete call ABI</h2><p>Six required bodies are now available with original instruction/call exports: bdf580, bdf300, d30860, d2ca40, d2f870, d2e870. <p>Correction: bdf580 is <strong>ROI row copy, not downsampling</strong>. It offsets source by roi.y*stride+roi.x, copies roi.width bytes per row, advances source by input stride and destination by roi.width, repeats roi.height. A pyramid-related caller does not make this helper a resize. bdf300 repeatedly ceiling-halves packed width/height, starting level1, while area&gt;=caller threshold and both dimensions&gt;6; d2aeb0 passes threshold32 and separately caps resulting level count at8. d30860 partitions/sizes aligned scratch roles; it is not an image kernel itself.</p>
<p>Actual be2070 call at be30d1..be3114 supplies d2aeb0 arguments as follows: RCX=RSI cropped image, EDX=EBX integer row stride, R8=RDI cropped mask, R9=[rsp+1f0] packed dimensions; stack+20=&amp;[rsp+e10], +28=&amp;[rsp+f50], +30=[rsp+168], +38=[rsp+170]. <p>The large children d2f870/d2e870/d2ca40 remain necessary numerical source, not generic edge detector placeholders. Their inferred parameter signatures likewise need register/stack mapping. <h2 id="automatic-estimator-return-and-mixed-result-layout-assembly-closure">Automatic estimator return and mixed result layout (assembly closure)</h2><p>The phrase four outputs is corrected: there are four stack <strong>arguments</strong>, not four independent result buffers.
