<h2 id="证据与已确认行为">证据与已确认行为</h2><ul>
<li>安装路径：<code>D:/Program Files/VisionMaster4.4.0/Applications/Module(sp)/x64/Collection/ImageAcquisitionModule</code>。原生 DLL SHA256：<code>bba5912a1f97d3721ad45eb8b955e89cd6f71327e116511f5e2037224b81bea2</code>。</li>
<li>托管与 UI 反编译输出在当前 <code>analysis/full-audit/image-acquisition/managed</code>、<code>control</code>。原生 Ghidra 反编译在 <code>native</code>，与 REA 元数据观测分开标识。REA 原生 provider 未配置，未将 CLI Ghidra 输出冒充 REA Evidence。</li>
<li>原厂构造默认值由算法 XML 覆盖为相机模式 2；间隔 1000，数量 4，等待光源 10，CameraID=-1。UI XML 的间隔初值 0 不代表实际参数默认值；原厂运行和用户桌面截图均确认 1000。</li>
<li><code>18000d6c0</code> Process：本地数量来自 ImageCount；相机数量来自 ImageConfigList，不受本地数量 3～8 限制。无相机/无配置返回 e0000001。</li>
<li><code>180010a80</code> ProcessLocalImage：逐槽解码、发布后推进列表游标并循环；一张源图片可填充多个槽。空列表 e0000203，已登记文件丢失 e0000201；失败位置游标保留，已完成槽位保留，后续槽位为空。</li>
<li><code>1800120c0</code>：逐槽 Image/Width/Height/PixelFormat 与对应角度；double 角度转换为 float32 输出。没有对应配置则角度 0。</li>
<li><code>18000e0a0</code> SetParam：AddImage 允许重复；ClearImage 清空并重置游标；配置二进制为 0x358 字节，8 项 ×104 字节加头/保留，Serial 从1开始映射为0基槽位。</li>
<li><code>180011a90</code>：每个相机配置按序触发光源、等待 DelayAfterTriggerLight、取帧、重置本地光源配置，再补足间隔；取帧内部失败不阻止后续配置。正向物理丢帧/丢包尚未制造验证。</li>
<li><code>ImageAcquisitionParam.SetImageDirPath</code> 是递归追加 SDK API；UI <code>OpenFileForAcquisition.AddImageByDir</code> 是按路径长度、字符串排序，只进入一层子目录，目录切换先清空旧列表。两者不能混为一种语义。</li>
<li>原厂 UI 资源 <code>datatemplate/paramusercontroldatatemplate.xaml</code>：相机模式额外曝光、增益、光源、触发时间0..65535、通道1..6、亮度0..255；两模式都有分布角-180..180、照射角0..90；最多8项，允许删空。</li>
</ul>

<h2 id="实现与边界">实现与边界</h2><p>当前复用已有独立图像解码器，新增多图采集插件、专用配置窗口、54个展平输出和会话状态。当前 VMX JSON 参数与嵌入资源是独立格式，不冒充原厂二进制兼容。原厂相机逐槽失败不阻止后续配置；独立实现同样继续，累计GetCameraFailCount，在没有最终查询错误的情况下返回成功和NativeErrorCode=0，保留有效槽位。空槽位以未发布可选图像端口表示，不能伪造上一帧。</p>
<p>公共服务与宿主调整记录于 <code>docs/CONTRACT-REQUESTS.md</code>。设备测试按用户最新指令排除；设备字段范围、保存重载、模块协议和宿主接入已在代码及自动验证中覆盖；原厂未定义的解码器损坏输入行为不按未初始化内存复刻。</p>
<p>原厂内嵌保存对照已成功：当前新建方案另存到自己的SOL，删除两张源图片后重载，四槽输出成功。</p>
<p>相机曝光/增益由1800111e0按 %.3f 格式化，输入保留double直到格式化；图像源原来的float输入路径保持不变。设备范围从真实SDK读取。宿主为多图插件显示8个不同图像输出选项，禁用单图运行/切换控制，避免错误写入无关参数。</p>
<h2 id="代码范围收尾">代码范围收尾</h2><ul>
<li>光源调用由 AcquisitionLightProtocolService 编码，指令 LightDeviceParamSetTrigger，748字节，触发时长位于+24、首通道位于+28。不能直接套用缺少触发时长字段的旧托管744字节结构。原生GetLightChannel只支持1..4；UI允许的5/6保持原厂不启用通道的行为。CompleteAsync只清理暂存状态，不凭空增加物理关闭命令。</li>
<li>光源失败按原厂路径保留诊断并继续取图；取消仍清理暂存状态。全局光源资源目录和具体驱动通过IAcquisitionLightModuleTransport注入，与原厂调用全局模块的边界一致；本交付不宣称完成清单中的另一个光源工具或任意串口/网口驱动。</li>
<li>数量、增删上限、显隐、订阅入口、目录手动输入与浏览差异、SDK递归追加、会话游标、数组槽位、错误恢复、内嵌重载及8路宿主预览均有自动检查。目录权限探测使用唯一临时文件，避免覆盖原厂固定test.txt同名用户文件。</li>
<li>原厂探针默认不执行设备测试分支；历史相机分支仅保留为显式-ProbeCamera选项。用户排除设备测试后未再运行设备探针，历史记录单独保留，不计入本批代码测试数量。</li>
</ul>
