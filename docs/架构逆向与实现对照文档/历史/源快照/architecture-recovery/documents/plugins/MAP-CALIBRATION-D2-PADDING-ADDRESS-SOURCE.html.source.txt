<h2 id="负列的确切读取">负列的确切读取</h2><p>813ca0汇编180813e83为每一行候选初始化ESI=1（column），radius独立从1增2；180813fa2将实际列EDX符号扩展到R15，fa5取row pointer，fa9/fb3比较<code>[rowPtr+column*8]</code>及<code>+4</code>两个int与INT_MIN。没有在实际读取前夹取负列。</p>
<p>因此radius2、候选column1的缺槽窗口包含column−1。首次该候选centerRow2时，窗口读row0..4、column−1..3（排除中心cell）；row pointer索引仍非负。以下令整数格网基址B、实际格宽w：</p>
<pre><code>rowPtr[j]=B+j*w*8
address(row=j,column=−1)=B+(j*w−1)*8
j=0: B−8
j&gt;0: rowPtr[j−1]+(w−1)*8
</code></pre>
<p>即只有row0访问B之前8字节；其他负列项读到<strong>上一行最后cell</strong>，不是每行独立prefix。r1首成功会提前返回，已采direction1图像并未证明执行过这些r2读取；本轮不主动触发它们。</p>
<h2 id="两板型row-pointer没有每行padding">两板型row pointer没有每行padding</h2><p>HIK7的80e690从context[9]取整数row table、context[11]取整数payload base；HIK9的80bcd0使用同样context字段。两者都用<code>rowPtr[next]=rowPtr[current]+actualWidth*8</code>构表，首指针直接为context[11]，没有额外+8或+一行偏移。HIK7 asm18080f00f/f014加载context+50/+58，随后对应两套payload；int grid的初始化只覆盖实际w*h个cell。</p>
<p>整数grid双int哨兵首次写入仍在两wrapper的填槽循环；并没有另一个“column−1列全INT_MIN”的初始化循环。不能从row table的128对齐推导每个row有哨兵边框。</p>

<p>关键汇编812090的180812251/265写两row table；278→27f→286→28d依次按Q加地址，写context[12]/[10]/[13]/[11]。故：</p>
<p><code>B−8 = context[13]+Q−8</code></p>
<p>它属于<strong>前一个整数ID输出列表的保留段尾8字节</strong>，不是专门给grid左边界分配的哨兵。若Ncap*8已128对齐，正好是该列表声明容量最后一对int；否则它可能是该列表之后的对齐padding。两者均没有在812090中写INT_MIN的保证。</p>
<p>原始容量Ncap与当前有效点数count、实际格宽高w/h必须分开：有效列表只写/复制count对；当前grid只初始化w*h槽。未写到的保留段尾可含先前workspace内容，不能假设0、INT_MIN或其他值。</p>
<h2 id="能核与仍未知的分配边界">能核与仍未知的分配边界</h2><p>812090可核分区相对地址、原始配置容量、对齐保留长度及所需总长度输出指针；816650/7e3f50汇编确认workspace由caller传入并继续转发，无该层新分配。7d3e90 C显示上层总工作区及多个输出/可选缓存指针参与scratch选择；该处复杂指针表达尚未全部用汇编核对，当前不把它简化为某个固定malloc偏移。</p>
<p>因而本轮<strong>不知道实际SDK heap allocation起址/总分配字节、S到heap起址偏移、B−8当次具体8字节内容或是否被更上层清过</strong>。分区布局表足以定位相邻保留段，不足以宣称原厂有安全语义padding、任意allocation上下文都相同，或该逻辑负列等同heap外读。没有用托管新数组清0填这些未知。</p>
<p>地址推导JSON含两个明确标为算术示例的布局：cap300×300/w14时R2432、Q720000，B−8落列表最后声明pair；cap13×13/w7时Q1408、原始1352字节，B−8落对齐尾padding。它们不是被动采到的SDK实参或内存值。</p>
