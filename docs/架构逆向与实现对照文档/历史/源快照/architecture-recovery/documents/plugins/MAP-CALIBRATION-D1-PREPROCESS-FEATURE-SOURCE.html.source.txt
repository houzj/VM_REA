<h2 id="85c8a0-的输入workspace与输出">85c8a0 的输入、workspace与输出</h2><p>实际caller为86ff00：warp后的灰图是source，source stride为W，输出图位于其workspace+6400。canvas为 <code>W=H=16m</code>，m由前轮源码约束为2..8；因此W为32..128，窗口 <code>kw=kh=W/4=4m</code>，为8..32。offset=0、mode=0，均由 <code>180870407..18087045c</code> 的栈参数组装确定，不从“通常的自适应阈值”猜得。</p>
<p>85c840/8a48e0给出大小：<code>align128(WH)+align128(2WH)</code>。86ff00先以160×160计算上界大小；处理时85c8a0再按实际W/H切分：均值byte图放scratch起点，2字节中间区域放 <code>scratch+align128(WH)</code>。所见wrapper使用caller提供的缓冲区和栈，不自行分配/释放堆内存；不能把这个结论推广到尚未完全追完的全SDK会话。</p>
<p>85c8a0先调用8a5e30生成局部均值图M，再8a8040比较source S与M。mode0按有符号整数比较：</p>
<p><code>output = S &lt; M + offset ? 0 : 255</code>。</p>
<p>这里offset为0，<strong>S==M写255</strong>。输出逐行按各自stride前进；正尺寸外无有效像素循环，没有额外“空输入报错”的状态契约可补。mode1为 <code>S &gt; M-offset ? 0 : 255</code>；mode2/3分别为比较目标相等/不等时写255，其余mode回到mode0式。当前decoder只消费mode0，其余模式只是取得源码，不据此声明产品支持。</p>
<p>8a8040在原Ghidra分析中被拆为入口及808c/811d/8132/81c3/81ce/82bf/82ca/83d4/83e3等块。初次入口汇编只有20行，不能当作全部函数。补取后，mode0实际比较可定位 <code>1808a8443..1808a845b</code>：加载M，加offset，加载S，JL写0，否则255；公共恢复寄存器与RET在83b6/83d4。拆块的异常函数签名不作为新的ABI。</p>

<p>实际汇编保留packed尺寸、窗口和workspace栈参数并尾跳；伪代码把两条向量路径显示为四参数调用不代表窗口/尺寸丢失。两个向量体也有小宽度退回8a4a40，但当前decoder W&gt;=32，不满足其 <code>&lt;17</code> 或 <code>&lt;9</code> 门槛。</p>
<p>普通路径源码先按窗口高度累加byte到ushort中间值，再水平方向滑动求和；边缘扩展通过对称的反向索引实现，不是简单复制最近边缘像素。归一化为float乘 <code>1/(kw*kh)</code>，普通标量边缘显式加/减0.5后截断到整数byte。逐索引递推在原始C/汇编保留，尚未发布一个可替代原厂核的数学重排实现。</p>
<p>两个向量入口在 <code>kw*kh*255 &lt; 65536 &amp;&amp; kw &lt; 6</code> 时使用small-kernel归一化8e3e20/8e6120，否则8e4010/8e62d0。当前decoder kw&gt;=8，所以<strong>实际合法域必走后两个large-kernel子体</strong>；不能只核small-kernel就代表这条decoder路径。</p>
<p>新取得的汇编表明，large-kernel内部向量转换使用CVTPS2DQ/VCVTPS2DQ，与标量的显式0.5后CVTT不是相同指令序列。进一步追踪发现它们有完整的rounding状态生命周期：</p>
<ol>
<li><strong>先</strong>计算float <code>1/area</code>（8e4010在1808e4046，8e62d0在1808e62f8）；</li>
<li>STMXCSR保存旧值，再以 <code>&amp;0xffff9fff</code> 清rounding位并LDMXCSR，内部向量转换处于nearest模式；</li>
<li>结束读取当前MXCSR，恢复旧值的 <code>&amp;0x6000</code> rounding位，其他当前位保留。</li>
</ol>
<p>因此不能说“向量转换任意依赖调用者rounding模式”；同样也不能说“整个核完全不依赖入口环境”，因为reciprocal计算发生在清位之前。恢复的是rounding位，不是把全部MXCSR覆盖回原快照。源码可确定两种转换序列不同，<strong>没有运行证据表明当前真实图像恰触发不同输出，也没有根据不同指令自行断言像素差幅度</strong>。下一最小S3问题若有必要，应是指定sum/area tie与MXCSR状态的定点微核，不是增加一批最终图像样本。</p>
<h2 id="870b90-的前定位与检测门">870b90 的前定位与检测门</h2><p>80ac20每个局部窗口调用870b90。870b90先调用6eea70，只有写出的pre-status==1才继续6a3a70；失败直接退出，不假装保留中心有效。6eea70也读取630120：类号7/10/11使用72b170，其余普通路径。两条都有明确缩小因子d（配置slot3），工作尺寸为W/d、H/d；任一小于3，pre-status写0，坐标不写。</p>
<p>普通路径将两个半径范围参数除以d并限制范围，比例输入除255、峰值比例乘0.01。d==1有整数分数图支路，d&gt;=2先缩小图像后用float分数图支路；72b170相应分派到75fbc0或75da20→75f130。6ee680/6ee560已取体：以严格 <code>new &gt; max</code> 更新峰位置，所以有限普通数值的并列最大值保留遍历中先到的点；达到 <code>threshold&lt;=max</code> 才成功并写坐标。最终前定位坐标乘d回到源图；失败只写status0，不推导所有原有坐标被清零。</p>
<p>分数图生成下级仍未完全恢复，因此本轮不将前定位命名为某个特定圆检测/Hough实现，不拿当前NImageFiducials替代其分数含义。</p>

<h2 id="70f4e0-到拟合输出及剩余叶体">70f4e0 到拟合输出及剩余叶体</h2><p>70f4e0使用caller workspace切片和栈缓冲，配置I2决定最多1或3轮。它构造由sin/cos与初始中心/半径界形成的径向位置，逐角调用684b50；只收status==1且坐标处于图像边界内的点。带可选诊断列表与无列表有不同写入分支。有效点少于3，或少于I15+3时，center/radius及诊断标量清0，mask/residual区域也清理并写失败status；不是“用已有三点补齐”。</p>
<p>满足点数后调用70d280。此wrapper伪代码显示无参数，但汇编保留RCX/RDX/R8，保存原R9 status指针，并把后续栈参数重新排列后调用70d2e0；后者EAX写到原status指针。70d2e0已补体，明确拟合输出为centerX、centerY、radius，残差为 <code>sqrt((x-cx)^2+(y-cy)^2)-radius</code>，有效mask点超过2时输出RMS。退化初拟合失败会清模型、误差、residual/mask并返回0；输出正常模型主要返回1，某些迭代/半径约束分支返回2。不能把其0/1/2与6a3a70参数错误码混用。</p>
<p>70f4e0写回拟合中心/半径，检查半径范围并可能改status为2；status0立即收尾，其他status在轮数允许时继续迭代。最终status、中心/半径与可选诊断逐层返给870b90/80ac20。80ac20另按其拟合半径（第四切片已确认，接受区间[15,21]）区间判定四个局部标记是否齐全，不能仅以6a3a70返回0采纳它们。</p>
<p>684b50内部仍按630120分派到6c9d90或普通边缘链704de0→68ad10/68ae00→68aec0→68a2f0→68b930→6911c0/691450。70d2e0的完整体已取得，但1227行的迭代、退化、采样与各参数模式尚未全部逐条核汇编。这是下一源码切片的精确边界，不以“常见边缘/圆拟合”补足。</p>
<h2 id="生命周期与继续条件">生命周期与继续条件</h2><p>本轮可定位的wrapper和主要worker采用caller拥有的workspace/栈；未发现它们直接调用堆分配/释放。均值归一化子体正常返回恢复rounding位；没有建立异常中断后的恢复契约，不能称“任何失败都完全恢复环境”。CPUID查询调用系统API；本轮只静态取体，不做设备或桌面操作。</p>
<p>下一步按源码缺口分两条有限任务：</p>
