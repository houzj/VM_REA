<h2 id="原厂源码及调用链">原厂源码及调用链</h2><ol>
<li>XML <code>AlgorithmTab.xml</code> 中两项默认值是 Low=20、High=40。资源 SHA-256：<code>76c9cd661a359216041b902cce8fae115566726707e749cc42c0bb9722bcbf91</code>。</li>
<li>原厂模块 <code>IMVSCalibBoardCalibModu.dll</code> 的 <code>SetParam @ RVA 0x20d40</code> 将两个名称纳入识别分支。对于这两个名称，局部别名保持为空；反编译调用 SDK 工具对象 <code>this+0x15d98</code> 的 vtable <code>+0x60</code> 时只传入参数名，没有把 <code>SetParam</code> 的值字符串作为该虚调用实参。原厂模块导出 <code>GetParam</code> 在同一探针实例中则回显存储的值。因此，模块配置存储已被设置，不等价于已证明算法工具句柄收到阈值值。</li>
<li>SDK 工厂 <code>CreateCalibBoardCalibToolInstance</code> 建立对象 vtable；<code>+0x60</code> 对应 SDK 函数 <code>FUN_180002980</code>。其反编译只读取工具对象 <code>+0x28</code> 算法句柄并调用外部 <code>MVD_Algorithm_SetValueByString(handle)</code>。该函数体不消费传入参数名/值。外部导入函数对句柄内部状态的副作用没有在当前探针中暴露。</li>
<li>核心算法函数 <code>FUN_1807dda50</code> 会读取输入结构 <code>+0x24/+0x28/+0x2c</code> 参与边缘阈值分类，但当前模块探针只能观测算法结果与模块输出，不能读取该私有结构入口字节。因此尚无可证的 XML 名称/值 → SDK 参数名/句柄/阈值槽位映射。</li>
</ol>
<p><code>GetParam</code> 的原厂导出 ABI 由实际 DLL 导出名确认：<code>?GetParam@CIMVSCalibBoardCalibModu@@UEAAHPEBDPEADHPEAH@Z</code>。SetParam 是 <code>?SetParam@CIMVSCalibBoardCalibModu@@UEAAHPEBD0H@Z</code>。</p>

<h2 id="边界与下一步证据">边界与下一步证据</h2><p>尚不能判断阈值是否在其他图案、不同板型或非默认算法模式下改变判定。输出不变只是这个 99 点棋盘样本的结果，不证明内部阈值槽未变；模块 <code>GetParam</code> 也只证明其可查询配置值。继续闭合需要在同一原厂模块实例中使用一组已由原厂 SDK 结果证明对 Low/High 敏感的图像/板型，同时在原厂 SDK 算法入口读取 <code>+0x24/+0x28/+0x2c</code>，并跟踪 <code>MVD_Algorithm_SetValueByString</code> 的具体句柄副作用。当前并无满足该映射的原厂接口或运行 trace，故保留未知，不增加产品映射或放宽测试容差。</p>
