<h2 id="本轮修正与验证">本轮修正与验证</h2><p>原厂 module XML 已强制 <code>ModuRunTime</code> 输出，但 Map 插件先前成功的文件模式、单图等待、双图结果与Teach缓存结果都没有该输出，GraphExecutor也不会把 <code>NodeRunRecord.ElapsedMilliseconds</code> 注入插件端口。现在 Map descriptor 将其标为必需，所有正常返回（成功或失败）由 <code>Runtime.ExecuteAsync</code> 外围统一附加执行耗时，确保各种提前返回都不会漏掉。SDK <code>ModuleResultManager.SetModuleResult</code> 直接复制原生结果结构 <code>fModuleTime</code>，壳层资源确认显示单位为 ms；但 <code>VM_M_SetFloat</code> 文档只描述一般 float 输出，不能据此定位 <code>fModuleTime</code> 的写入者。当前实现取值采用毫秒 <code>double</code>，区间为插件入口到模式处理完成；原厂区间和未执行语义尚无直接证据，Stopwatch 仅是独立替代实现。</p>
<p>本轮追查源文件（哈希均为 SHA256）：<code>VM.PlatformSDKCS.Audit/VM.PlatformSDKCS/ModuleResultManager.cs</code> <code>FD3960EE308FB739729AF43589035D628544BB5B26941BE5EB6F3250A41739E7</code>（第 15–18 行设置错误码、执行次数及 <code>fModuleTime</code>；后续按结果属性名反射映射输出）；<code>CModuleResultBase.cs</code> <code>3295ED4E4CC9DB4D7EDA35281C9195E1E1E842CCAEFA2BF7186A1B5D15469092</code>（第 14–27 行属性注释、默认 0）；<code>ProcedureResult.cs</code> <code>DCBCFC9E2BB9D1110C35D8527B1C6CE620AAE4A979624F857FC5A4AC600866AA</code>（第 37–49 行查询 <code>fModuleTime</code>，无结果返回 0）；SDK <code>VmModuleBase.h</code> <code>4AC3FC2368E710DC9040E46F5B308A1DBADACAE1AC67745F26153AE25145C9E7</code>（第 342–351 行 <code>VM_M_SetFloat</code> 是具名 float 结果写接口，没有描述计时）；<code>zh-cn.xaml</code> <code>C3AD9209618D7B36FA3F59C6AF2103FB2DEFB7066A03804E8DE80E992471610E</code>（第 1737 行将该结果资源化为“耗时（ms）”）。Map XML SHA256 <code>228BF45A24691C0D13C2201E516941F20E6B1E5352478CCB60ED01C774B4F5F</code>，第 87 行为必需 float 声明。</p>

<h2 id="仍需的最小原厂证据">仍需的最小原厂证据</h2><ol>
<li>原厂普通配置窗口分别打开 Image、File、Teach enabled 状态；一组包含两路 ImageSource 候选/当前绑定和两个 ROI 面板，另一组展示 WeightFun 与 WeightFactor 实际显隐、Reset 后状态。这样区分 XML 原始声明与桌面模板运行结果。</li>
<li>原厂结果窗口在一组成功双图运行后截取文字、三组点显示的开关、ROI/Coordinate System 对象；同时保存输出列表/结果面板中对应字段值。重点查 <code>CalibOriPoint*</code> 是否存在动态输出、坐标对象是否实际显示。</li>
<li>要闭合 <code>ModuRunTime</code> 数值语义，最小新增原厂 trace 为同一 Map 模块进程的一次成功运行、一次带错误码的已运行结果和一次未运行/无结果查询：记录模块 <code>Process</code>/调度入口与返回的单调时钟时间戳、返回码、<code>IMVS_MODULE_RESULT_INFO_LIST_EX.fModuleTime</code>、<code>nErrorCode</code>，并记录 <code>QueryModuleOneResult</code> 是否有值。若要精确定位计时边界，还需原生 <code>fModuleTime</code> 生成函数或可将模块处理开始/结束函数与该值相关联的调用栈。现有 <code>VM_M_SetFloat</code> 头文件声明和 UI 单位资源不能提供这些时点。原厂 Map trace 当前未记录该字段；本轮未调整 Stopwatch 行为。</li>
</ol>
