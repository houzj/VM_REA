<h2 id="已有原厂模块回放">已有原厂模块回放</h2><p>回放来自 <code>tests/MapCalibration.NativeProbe/ModuleRuntimeProbe.cpp</code> 与 <code>ModuleImageRuntimeProbe.cpp</code>，加载安装目录原厂 Map 模块及算法 SDK，模块 DLL 代码保持不变；<code>ModuleHost.hpp</code> 仅替换模块 IO/runtime imports。记录首行明确标注 <code>platformRuntime:false</code>。因此这些 trace 是原厂模块在受控 IO host 下的回放，不等同完整 VisionMaster 平台运行。</p>
<ul>
<li>File trace：<code>analysis/map-calibration/native/module-runtime-results.jsonl</code>，SHA-256 <code>F3B19E9265C4D79AC6936C267E6D2129468A44E6BAA2BDCB18EC01B65CC51A23</code>。初次有效文件运行输出状态 1/1、SDK <code>GetResult</code> 有值。将 A 文件缩成两值后 Refresh 返回 <code>0xE0000018</code>，本轮 <code>writes=[]</code>，SDK <code>GetResult</code> 仍有先前结果；下一次不刷新仍运行当前缓存并写 1/1，SDK 读回矩阵变成 <code>[8388608,0,0,0,0,0,0,0,0]</code>，不再是先前单位矩阵。该数值很可能受原生部分填充/未初始化缓存影响，不将其作为稳定输出规范；可以确认的是失败读取改变了后续算法所见状态。恢复有效文件刷新又得到有效结果。之后将两侧置零，算法运行返回 <code>0x10103002</code>，模块写状态 0/0 且 SDK <code>GetResult</code> 为空；后续恢复有效文件可再次得到结果。该序列直接证明“刷新失败”和“算法运行失败”对旧结果的影响不同。</li>

<h2 id="与当前-map-实现的逐项对照">与当前 Map 实现的逐项对照</h2><ul>
<li><code>MapCalibrationFileSession.SetInputPath</code> 将 parser 返回的 <code>Replacement</code> 即使在失败时也写入矩阵缓存；仅成功时更新路径。这对应原厂 <code>ReadFileMatrix</code> 可以先替换缓冲区、而 <code>SetParam</code> 只有成功后才提交 SDK 文件参数与路径的顺序。现有 <code>MapCalibration.FileChecks</code> 已逐项比较 reader 错误码及替换矩阵，未发现新差异。</li>
<li><code>MapCalibrationFileSession.Run</code> 在进入算法运行前清理 <code>LastResult</code>；输入 Refresh 的 setter 失败则提前返回、不调用 <code>Run</code>，因此保留先前结果。这与 file trace 中失败刷新不写出、SDK <code>GetResult</code> 仍有旧结果，以及后续算法失败输出 0/0 且 <code>GetResult</code> 为空的路径一致。</li>
<li><code>MapCalibrationPlugin</code> 分别用节点级 file session 和 image session 保存状态。InputType 分派不删除另一个模式的 session，模式切换本身不重置状态；原厂 <code>ResetMember</code> 由 <code>Init</code> 及 <code>DeInit</code>（尾跳）进入；当前静态调用链未发现单纯模式切换时进入该清理链。已有 image trace 覆盖了 File→Image 切换的无矩阵失败和新帧等待，但没有覆盖待处理半帧跨模式留存；静态源码两边都未见切换时重置，行为方向一致。</li>
<li>Image 单帧/Teach 触发的状态输出与既有 harness 对照一致。Image 完整算法失败后算法 <code>GetResult</code> 是否仍保留更早的成功结果没有在现存 Image trace 中逐步读取，当前证据不足以把壳层显示的旧结果与模块本轮 output writes 等同起来。</li>
</ul>
<p>本轮没有证据支持修改 Map 专属实现。现有 file 缓存和错误阶段代码按原厂已证实顺序保留。不要把 <code>writes=[]</code> 等同于 VisionMaster 全平台 UI 必然清空/保留旧动态端口：probe 的 IO host 不模拟平台输出存储策略。</p>
