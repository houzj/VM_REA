<h2 id="可共享的代码边界">可共享的代码边界</h2><ol>
<li><strong>标定结果不能仅表示为单个矩阵。</strong> 标定加载 XML 明确包含 <code>CalibMatrix</code>（float 数组）、<code>RotCenterImage</code>/<code>RotCenterWorld</code> 等 POSTURE 组合；其 SDK <code>ReadCalibFileResult.cs</code> 公布 <code>List&lt;float&gt; CalibMatrix</code>。平移旋转声明还包括图像/物理点数组、旋转中心、方向、图像和世界误差、比例和平移旋转参数。矩阵维度、行列顺序、坐标约定、单位尚未在本专项恢复，不能从 List&lt;float&gt; 推断为固定 3×3。</li>
<li><strong>加载器支持运行时结果结构。</strong> <code>ReadCalibFileModuControl/Apps.XmlParser.ParamTab/ReadFileConfigData.cs</code> 的 <code>ReadData(bool needAddoutput=false)</code> 从 <code>((IUserBytesData)vmModule.Params)[$&quot;Get{NameA}&quot;]</code> 取得 UTF-8 文本；本工具 XML 的控件名为 <code>CalibInputParam</code>。<code>AnalyzeString</code> 先以 <code>;</code> 分类型段，再以 <code>#</code> 分类型和正文、<code>$</code> 分条目、<code>,</code> 分名称和值，姿态内部以 <code>~</code> 分 X/Y/R。类型分支为 <code>int</code>、<code>float</code>、<code>string</code>、<code>CalibPointList</code>、<code>CalibPointF</code>、<code>FloatList</code>。这是原生返回给 UI 的参数描述协议，<strong>不是磁盘 XML 的序列化格式</strong>。</li>
<li><code>ReadData(true)</code> 倒序删除模块现有 <code>DynamicVmIO</code> 和 <code>Combination</code> 后，通过 <code>IOutput.AddOutput</code> 重建输出；<code>ReadData()</code> 默认不重建。不能仅依据读取显示调用，就声称执行图的输出结构已更新。<code>OpenFileDialog4ReadFile.ValueChangedCmdExecute</code> 先调用基类，再调用其私有 <code>ReadData()</code>，由后者调用该显示读取方法。</li>
<li><strong>平移旋转专属点表可复用交互基础，但字段不能照抄 N点。</strong> <code>TranslationCalibModuControl/TranslationCalibModuControl/NPointList.xaml.cs</code> 的 <code>Init</code> 读取 <code>CalibPointTotalNum + RotPointTotalNum</code> 行，每行 <code>ImagePointX/Y</code>、<code>WorldPointX/Y</code>、<code>DeltaAngle</code>；展示采用当前文化 <code>float.Parse(...).ToString(&quot;f3&quot;)</code>。<code>GetPointListText</code> 验证五个 float，按五列、空格及 CRLF 导出；<code>GetPointListByText</code> 按 CRLF/空格拆分，仅处理现有数量范围。导入异常、缺列处理及浮点文化需要后续受控运行对照，不能用一个宽松 CSV 导入器代替。</li>
<li><strong>专属 UI 与公共编辑器分开。</strong> 本范围实际存在 <code>ReadCalibFileModuControl.dll</code> 和 <code>TranslationCalibModuControl.dll</code>；其余五项安装目录没有同名前缀 Control.dll，主要配置在 AlgorithmTab XML。它们仍使用 <code>OpenFileForCalibDialog</code>、<code>ImageViewConfig</code>、点组合选择器、ROI 及条件显示等公共控件。不能把无专属 Control.dll 理解成没有 UI，也不能只复制面板截图而省略图像/ROI 交互。</li>
</ol>
<h2 id="建议接口准备及后续顺序">建议接口准备及后续顺序</h2><p>主线负责在 CONTRACT-REQUESTS.md 统一登记和落地，避免多代理并行修改公共合同：</p>
<ul>
<li>标定结果载体需显式携带模型种类、矩阵系数及其约定、点/姿态数组、误差和状态；在原生验证前允许未知维度，不预先固化单位或矩阵顺序。</li>
<li>标定文件服务要区分 <code>.xml</code>、<code>.iwcal</code>、<code>.iccal</code> 及点表 <code>.txt</code>；读写原子性、刷新、方案内缓存矩阵与文件外部变更要由运行证据确定。ReadCalibFile 的 <code>SaveCalibDataEnable</code> 是明确独立参数。</li>
<li>点表配置需要行增删/采样、不同字段集、导入导出、订阅写入与撤销生命周期；UI 点和姿态组合与独立 X/Y 分量订阅均在 XML 中存在。</li>
<li>动态加载结果需要配置变更后端口重建、订阅失效检查和方案持久化，而不能只提供任意字符串字典。</li>
</ul>
<p>保持用户最高优先级 <strong>N点标定 → N图像标定</strong>。建议之后先推进共享 <code>MVDNPointCalibCpp</code> 的平移旋转和旋转，再做标定加载的读写互通，接着标定板、相机映射、映射、畸变；坐标系最后。这是基于依赖的建议，不是已确认的执行先决关系。标定加载的文件结构调查可提前作为 N点保存加载的验证辅助，但不能以本静态清单宣称格式兼容。</p>
<h2 id="未验证范围">未验证范围</h2><p>本专项没有运行原厂算法、采集原厂 UI、核对像素或标定数值、读写真实标定文件、验证设备。原生求解、退化条件、误差定义、矩阵系数顺序、刷新与缓存策略、跨工具文件互通仍待各工具的受控运行证据。此报告仅闭合并行依赖清点，不构成七项工具实现完成或原生等价声明。</p>
