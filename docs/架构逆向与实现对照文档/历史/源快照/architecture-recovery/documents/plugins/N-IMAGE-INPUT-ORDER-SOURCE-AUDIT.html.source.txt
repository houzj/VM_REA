<p>20d76/7a/7e将三个Count槽清0；20d82..20dfa分别把Count槽地址置[RSP+20]（Win64第5参），R9置value槽，R8D=0，调用MovePhysicalPointX、MovePhysicalPointY、RotateAngle三个GetFloat。三次均执行，未据EAX状态短路。随后检查三个Count，任一0就把三个motion值一起改为原sequence自动生成值。不能把GetFloat显示签名的四参当没有Count，也不能把类型为int的源静默当成功float读。正常树源可为数组，实际读取index0。</p>
<p>21011..2103b在实际链表插入图像并增加frameCount。21097..210bc先要求count非0且count&gt;=translationCount+rotationCount；不满足即跳过修正输入和ProcessAlg。210be再检查this+160d0(HomoFixEnable)。只有满批且启用才按PicPointX→PicPointY→PhysicalPointX→PhysicalPointY读取，均index0，各返回EAX成功才继续下一项；失败仍在append之后，随后ProcessOutput输出当前计数。四修正读复用一个Count槽，但该caller只判断返回码，不把Count作为第二成功条件。源成员写入位置为this+160d4/d8/dc/e0。</p>
<p>当前产品确认两处实施缺口：NImagePlugin.Number/Point只读物化scalar，不消费scope/read callback/数组首项；修正输入在每帧开始就读取并在未满批时判缺源失败。已有NImageModuleChecks“第1/9帧缺修正就失败”断言来自当前实现，不能覆盖原条件；必须改为普通未满批成功、末帧才失败且Count已增加，并保留原日志。旧数值求解、原37输出和完整float逆矩阵不因此失效。</p>
