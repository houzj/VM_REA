<p>资源与三个存在的自定义Control.dll元数据只读审计见 <code>analysis/translation/audit-20261019/path-controls.json</code>：NPoint、NImage、Translation Control.dll均没有文件控件派生/同全名覆盖；Board/Map/Rotate安装目录无专属Control.dll。Translation控制扩展实际只定义EditButton_Calib及点表，不覆写此文件控件。Distortion由根线独立核的第七资源与控制身份补入其跨工具报告，不在此伪称本线读取过。</p>
<p>ValueChangedCmdExecute 284–345完整顺序：</p>
<ol>
<li>CurValueA为null直接返回；取本地化FilterName，<code>Split(&#39;|&#39;)</code>，按第二段<code>;</code>拆patterns，使用 <code>text.EndsWith(pattern.Substring(1))</code>，即当前文化且区分大小写。没有通过则错误消息并返回，<strong>不SetParam</strong>。</li>
<li><code>/root</code>分支取最后<code>/</code>前缀并调用FtpCheckFileName。当前公共本地policy明确Unsupported，不用本地Directory.Exists冒充远端。其它分支只找最后反斜杠<code>\\</code>截前缀，若无反斜杠则检查原串；Directory.Exists失败返回。不能代数替换成Path.GetDirectoryName/绝对化。</li>
<li>校验后SetParamUnit失败显示模块错误、成功显示Lang_SetSuc再PreExecuteRun。保留CurValue尝试值与OldValue/模块参数的区别；宿主Apply拒绝事务回滚另列为独立适配。</li>
</ol>
<p>DoOpenFile本地273–278在 <code>CurValueA=null; path=(CurValueA=selected)</code> 之后<strong>无条件</strong>记默认目录；Remote245–250同样。校验失败仅return，不阻止随后history。文件选择同值仍通过null→path强制重试；普通文本同值不变不重试、不写picker history。不能根据尝试值与文档值相等推断已成功，也不能把history条件擅改为只成功才写。</p>
<p>根线拟采用State可选ParameterWriteValidator委托；七provider仅接同一公共helper并保自身通知。helper严格检查实际标签/Filter，不按moduleId硬编码，不拦Loader派生OpenFileDialog4ReadFile，也不拦Map两个base输入。AlgorithmReset直接backend adapter，不经过UI前置门，保持原空默认写入语义。候选与专属测试位于 analysis/translation/proposals/path-policy 和 tests/TranslationCalibration.PathPolicyChecks；尚未验证前不预报通过。</p>
