<h2 id="原厂证据与调用条件">原厂证据与调用条件</h2><p>原厂运行二进制身份见 <code>docs/plugins/map-calibration-evidence.json</code>：<code>MVD_Algorithm.dll</code>，52686848 bytes，SHA-256 <code>85d17ecc87d52e9a62d8bb86c8d5208ac999bcd31ec6d0806453f8165733f549</code>。映射模块身份为 <code>IMVSMapCalibModu.dll</code>，250880 bytes，SHA-256 <code>658d63e2c4e2378e7eb1776d27b966990c0d0e01e29ca57ed82fe9acc740fde8</code>。原始文件位于本机 VisionMaster 4.4.0 安装目录；本文引用 Ghidra 对算法二进制的反编译结果 <code>analysis/map-calibration/ghidra/core/1807e4360.c</code>、<code>1807e3f50.c</code>、<code>1807d3e90.c</code>。</p>
<p>反编译符号给出的可确认顺序是 <code>7d3ae0</code> 输入/参数包装 → <code>7d3e90</code> 图像拟合调用 → <code>7e3f50</code> 图像候选处理配置及尺寸重试 → <code>7e4360</code> 候选几何与失败后的重检。<code>7e4360</code> 的可见条件：</p>
<ol>
<li>候选个数 <code>*param_8</code> 必须大于 3；否则函数不进入拟合/重检。</li>
<li>先把候选坐标转换为 float，调用 <code>7ff3c0</code> 做初次几何拟合；只有该调用返回 1 且输出标志也为 1，才计算角度/几何差异。</li>
<li>计算出的归一化差异达到全局阈值 <code>_DAT_181628c24</code> 后，才按 <code>param_11[2]</code> 进入特殊检测器分派。分派值 1–9 分别调用 <code>7dce20</code>、<code>7dd6c0</code>、<code>7dda50</code>、<code>7dde30</code>、<code>806ed0</code>、<code>7de3b0</code>、<code>7df4f0</code>、<code>7dec40</code>、<code>7e0480</code>；未知值走 <code>7dce20</code>。其中 case 5 的 <code>7e4360</code> 调用 <code>806ed0</code> 时传入常量 <code>0x700000007</code>。</li>
<li>重检输出只有在两维均满足 <code>2 &lt;= count &lt;= 300</code> 时才复制回输出点集及尺寸（反编译表达式为 <code>(count - 2U) &lt; 299</code>）。</li>
</ol>
<p><code>7e3f50</code> 另有尺寸参数调整路径，条件为参数结构偏移 <code>+0x44</code> 的整数值等于 1；其输出维度候选受 <code>[2,300]</code> 检查，并在构造后以 <code>[3,300]</code> 的范围搜索设置。这是图像处理参数重试条件，现有反编译没有把它证明为“旋转”或“透视”开关。<code>param_11[2]</code> 的符号内含义可确定为 <code>7e4360</code> 的特殊检测分派键；还没有源码/调用数据把其 1–9 的每个值可靠映射到公开 <code>CalibBoardType</code> 数字或某个 projective/rotated 名称。</p>
<p>SDK managed 参数定义 <code>analysis/full-audit/calibration-dependencies/decompiled/IMVSMapCalibModuCs/IMVSMapCalibModuCs/MapCalibParam.cs</code> 公开板型 6、7、8、9 和自由度 <code>HomoFreedom</code>：1 Perspective、2 Affine、3 Similarity。这个自由度控制的是映射拟合模型。当前没有证据表明它启用上述 <code>7e4360</code> 的特殊图像检测分派，不能把两者混为一谈。</p>
<h2 id="当前共享实现及差异">当前共享实现及差异</h2><p>Map 产品入口 <code>src/VisionPlugins.MapCalibration/MapCalibrationImageSolver.cs</code> 的 <code>DetectImage</code> 先运行 <code>NImageSourceLatticeAdapter.Find</code>，如果 lattice 存在则用 <code>RecognizeLattice</code> 尝试解码；任一阶段失败就调用 <code>NImageBoardRecognition.Find</code>。共享识别顺序为 upright → projective → rotated（<code>src/VisionPlugins.Calibration/NImageDetectedBoard.cs</code>）。因此兼容分支的实际启用条件是 source lattice 未能产生可解码结果，而不是原厂已确认的“候选数 &gt; 3、7ff3c0 初拟合通过且残差超过阈值”。</p>
<p>共享 projective 分支另有独立边界：<code>NImageProjectiveLattice.Find</code> 要求图像宽高至少 64、估计 pitch 至少 8、原始候选至少 4、连通分量至少 16；recognized board 需有至少一个可解码 opening/tag。共享 rotated 分支估算梯度角，再按 <code>0,+0.25,-0.25,+0.5,-0.5</code> 度偏移尝试旋转图像、双线性重采样并运行 orthogonal detector；角度绝对值小于 <code>0.001</code> 弧度时直接走 orthogonal 路径。这些是当前独立实现的实际条件，不是从原厂推导出的边界。</p>
<p>故当前共享分支没有逐条件复现原厂特殊重检：原厂重检以前置几何拟合的输出状态与残差判据开启，当前共享 fallback 以前置 lattice/tag 流程失败开启；原厂按内部 selector 分发 1–9 检测器，当前实现先透视 lattice 搜索、再旋转归一化；两边也没有可证明一一对应的参数/模式映射。它目前只是保留的 independent compatibility route。</p>
<h2 id="既有运行证据与缺口">既有运行证据与缺口</h2><p>找到一条直接涉及该符号的既有 SDK 阶段报告：<code>analysis/map-calibration/image-detector-stage-trace/comparison.json</code> 明确写出 <code>refinement7e4360Called: false</code>，范围说明是“此 SDK fixture/options；native 80e690/80bcd0 已返回最终点”。其 <code>stage-trace.jsonl</code> 有4个返回记录：board 7 两组、board 9 两组，每组168点；<code>comparison.json</code> 记录2016个对照字段2016相同。它证明这些特定 fixture/options 的最终返回没有调用 <code>7e4360</code> refinement 分支。它不能证明分支永远不触发，且不能用于推导旋转/透视兼容行为。</p>
<p>这条阶段日志只记录 <code>phase/stage/sequence/board/count/points</code>，没有候选预拟合结果、拟合旗标、残差、<code>_DAT_181628c24</code> 的运行值、selector <code>param_11[2]</code> 或 detector 分派目标。因此它未建立 selector→公开板型映射，也未命中任何 <code>7e4360</code> 特殊 detector。原厂资源 <code>analysis/map-calibration/native/default-config.xml</code> 把 <code>HomoFreedom</code> 的公开值定义为1 Perspective、2 Affine、3 Similarity；parser 导出的 <code>analysis/map-calibration/parser/model/IMVSMapCalibModuAlgorithmTab.xml</code> 把公开 <code>CalibBoardType</code> 定义为7、6、9、8。两份资源均未定义 <code>param_11[2]</code>，也没有把它映射到 <code>HomoFreedom</code>；只能确认拟合自由度和板类型是两个公开参数，不能从同值或名称猜内部 selector。</p>
<p>其余 <code>docs/plugins/MAP-CALIBRATION-DELIVERY.md</code>、<code>docs/plugins/MAP-CALIBRATION-IMAGE-COMPARISON.md</code> 的 SDK 回放覆盖板型6–9、有限原图/裁图、默认和 filter2 等已记录调用，source-grid 接入回放用于确认这些覆盖样本的点/映射输出。它们没有补出 detector selector 或成对的独立透视/旋转输入。因此现有记录没有建立 selector→板型映射，也没有证据表明 projective/rotated 原厂重检已命中；无法比较该分支与共享实现的输出点数边界。</p>
