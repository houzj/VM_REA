<h2 id="原厂来源">原厂来源</h2><p>安装目录 <code>D:/Program Files/VisionMaster4.4.0/Applications/Module(sp)/x64/Calibration/ReadCalibFileModu</code> 共 13 个文件，身份、长度、SHA-256、10 个输入、输出声明与 13 个配置控件见 <a href="../../../plugins/read-calib-file-definition.json">声明清单</a>。主 DLL 为 110592 字节，SHA-256 <code>86b8b112aded58de27a41a5ede6ec6b41117d7db8d0c5934647fa9514e6fa403</code>。</p>
<p>托管源码在本工作树 <code>analysis/full-audit/calibration-dependencies/decompiled/ReadCalibFileModuControl</code> 与 <code>ReadCalibFileModuCs</code>。REA 静态托管检查 <code>ev_ca66bc7e6c4cc7a9571f53344daf7263f2ee1dc9fa37fd17dc18320bb536c94d</code> 证明 Control.dll 身份；原生 DLL 用 REA 打开确认 PE/x64/SHA-256，原生反编译由独立 Ghidra 数据库完成。REA 原生 provider 未配置，使用现有本地 Ghidra，没有修改其共享连接设置。数据库与导出位于本工作树 <code>analysis/full-audit/read-calib-file/ghidra-project</code>、<code>native</code>，未打开其他任务数据库。</p>

<h2 id="真实运行与文件语义">真实运行与文件语义</h2><p><a href="../../../plugins/read-calib-file-evidence.json">运行证据</a> 保存完整事件顺序、输入、getter 返回、逐次输出及 XML fixture 原文/哈希。当前包含 32 次原厂 Process、17 次 LoadFile，以及实际 LoadModuleData 的 FileData 缓存加载。入口为 <code>tests/NativeEvidence/Invoke-OriginalReadCalibFileProbe.ps1</code>；构造和方法 RVA 均源确认，仅在自有实例的 ModuleFrame IAT 输入/输出/运行信息位置装入合成服务，校验原始目标并恢复，不修改算法、授权、安装文件或其他进程。</p>
<ul>
<li>默认无文件、文件不存在、XML 格式错误之后 Process 仍返回 0；没有结果时输出 ModuStatus=0。文件读取本身返回 <code>0xe0000201</code>，不能把它改成每次 Process 失败。</li>
<li>XML 外层根名不限 CalibInfo。已解析文档再清除旧参数集合，缺少 CalibOutputParam 返回 <code>0xe0000017</code>；文件打不开或 XML 语法错误在清除前返回，保留旧结果。</li>
<li>新增受控刷新序列：先加载有动态输出的 <code>rich.xml</code>，再把同一路径替换为语法正确但缺少 <code>CalibOutputParam</code> 的 XML 并发送 RefreshSignal。原厂 LoadFile 源码在解析文件成功后、检查该 section 前先清空旧集合；本轮只写 <code>ModuStatus=0</code>，而 <code>GetCalibInputParam</code> 已更新为新文件的 <code>AfterRefreshInput=77</code>。插件解析器同样发布新输入参数并清除旧动态输出；这是源代码与真实模块受控运行共同确认的清旧边界。</li>
<li>输入参数识别 int、float、string、CalibPointList；输出识别 int、float、string、FloatList、CalibPointF。标量数值按原厂前缀扫描，未知类型忽略。</li>
<li>FloatList 的坏数值会保留前一个成功解析的 float。CalibPointF 按 XML 子节点顺序发布其实际节点名；X/Y 的负值照常发布，第三项 R 只有 <code>&gt;=-990</code> 才发布。第四项使 LoadFile 返回 <code>0xe0000207</code>，已解析的前三项仍可输出；两项姿态也接受。</li>
<li>ModuStatus 表示已加载的输出集合是否非空，数值不是标定矩阵有效性的重新判断。CalibMatrix 作为任意长度 float 数组发布；恰好 9 个有限值时额外提供独立框架的类型化 CalibData。</li>
<li>文件只在配置变化或 RefreshSignal 非零时重读。磁盘变化本身不刷新；刷新失败保留上次结果。九个 <code>*1</code> 姿态输入仅覆盖本次对应分量，不改变缓存文件，不保留到下一次运行。</li>
<li>FilePath 参数本身变化经原厂 <code>SetParam</code>（RVA <code>0xd120</code>）立即调用 <code>LoadFile</code>（RVA <code>0xab50</code>），无须 RefreshSignal：同一实例从 <code>same-schema-a.xml</code>（<code>Dynamic=42</code>）设为 <code>minimum.xml</code> 后，没有刷新输入的下一次 Process 已只写 <code>CalibMatrix×9</code> 与 <code>ModuStatus=1</code>，旧 Dynamic 被移除。设为不存在的路径时，LoadFile 在清集合之前因无法打开文件早退；受控实例仍报告旧 FilePath、<code>LiveInput=10</code>，无刷新 Process 仍写旧 <code>Dynamic=42</code>。这覆盖参数路径切换成功立即加载、失败保留两种分支。</li>
<li>若方案通过 FileData 恢复内容且没有 FilePath，非零 RefreshSignal 仍会走原厂 <code>Process</code>（RVA <code>0xc520</code>）到虚表 <code>SetParam(&quot;FilePath&quot;, storedPath, storedLength)</code> 的分支；空路径长度为 0，原厂 <code>SetParam</code>（RVA <code>0xd120</code>）清空路径及已载入输入/输出集合。自有实例受控运行 <code>scheme-file-data-cache</code> 后紧接 <code>scheme-cache-refresh-signal</code>，后者只输出 <code>ModuStatus=0</code>，没有缓存 XML 中的动态端口值。插件执行器现按此清空恢复缓存状态与动态描述。该边界由原厂反编译和自有实例运行共同确认；不表示真实平台会话桌面路径已验证。</li>
<li>SaveCalibDataEnable=True 时方案包含加载的 FileData，False 时不保存该块。最新 SaveModuleData 探针实际记录：启用时有 FileData、DynamicInData、DynamicOutData 三条记录，FileData 为原始 XML 6987 字节；关闭时只剩两条动态 IO 记录；重新启用后 FileData 再次出现。加载缓存可以没有源文件或 FilePath。DynamicInData/OutData 原始 XML 始终独立保存。独立方案采用 JSON 参数 CachedFileData 表达同样的生命周期，没有冒用原生二进制方案格式。</li>
</ul>
<p>原厂输入参数展示协议是 <code>类型#名称,值$;</code>，点用 <code>X~Y~R</code>。该协议用于 GetCalibInputParam 与原厂 ReadFileConfigData，并非磁盘 XML 格式。GetCalibOutputParam 在该 getter 内没有生成内容的分支。</p>
<h2 id="额外结果与共享接口">额外结果与共享接口</h2><p><a href="../../../plugins/read-calib-file-extra-io.json">额外 IO 规格</a> 附带最小原厂 XML、真实 int/float 数组、600 字符字符串、未绑定与 float getter 回退事件。只选择 Output/Items 中 Others 包含精确子串 <code>IsResultShow=t</code> 或 <code>IsResultShow=T</code> 的项，ValueType 对 int/float/string 不区分大小写。数值按 getter 实际数量发布，string 只读首项；float getter 返回非零才尝试 int getter。</p>
<p>额外展示最后覆盖输出；未绑定不写，已有文件结果保留，不继承上次运行的额外值。独立隐藏参数 DynamicOutData 保留原始 XML，DescribeNode 从该参数生成同名输入/输出。int/float 数组以 NumberArray 承载，int 数组逐项保持 32 位整数语义。</p>
<p>节点初始描述仍从持久化 OutputSchema 与 DynamicOutData 构建，不在 GetDescriptor 中读磁盘。标定加载显式声明 SupportsDynamicOutputs；Refresh 后模块按本轮真实 Data 返回 UpdatedDescriptor。GraphExecutor 只接受 ID/version、输入、参数和显示能力不变而 Outputs 更新的描述，以新描述校验输出，并在消费前重新校验动态源的每条连接。改名或类型/基数不兼容的旧连线让下游以 DynamicConnectionInvalid 失败；ExecutionEvent 与 ExecutionSessionResult 提供实际描述供宿主刷新端口视图。不会自动改写已保存流程或猜测重连。工作流变量、接口、显示及参数订阅继续要求稳定 schema。固定输出节点的原验证分支不变。</p>
<p>远程文件对话框由 ToolEditorContext.IsRemoteMode 传入现有 ConfigurationFileRequest.Remote；现有 IToolConfigurationFileService provider 收到 module key、当前 FilePath、原厂 XML filter 与 Remote 标记。默认 WPF service 在 Remote=true 时显式 Unsupported；配置注入 mock 已验证参数传递、选择首项提交与运行，但没有真实 FTP backend、SDK 句柄或远端服务器，所以远程 native 仍未实测。</p>
<p>本工具 Display.xml 的活动对象仅为 Data Record/datarecord，将 <code>Module Status:{0}</code> 映射 ModuStatus；Show Text 被注释，AlgorithmTab 没有 TextDisplayGroup。通用文字叠加服务使用主线与旋转工具的 <a href="../../../plugins/rotate-calibration-display-contract.json">显示合同证据</a>，本窗口不添加原厂未声明的文字叠加选项。</p>
<h2 id="界面与验证边界">界面与验证边界</h2><p>原厂 ReadFileConfigData.AnalyzeString、ReadFilePanel、原始 DataTemplate 实际执行并渲染，保留全类型、无效条目、空值和原厂模块实际 GetCalibInputParam 文本四个场景。原厂模板需要正常注册 UserTempConverter 的扩展字典；未注册时的空布局截图不作为有效 UI 证据。最终截图与加载依赖哈希进入运行清单，明确不是平台桌面操作。</p>
<p>独立配置窗口覆盖原厂文件、刷新订阅、方案存矩阵、三组姿态订阅、只读三列点表与参数文本，使用同线公共主题。中文字段名来自原厂实际 GetLang 结果。截图辅助均位于 tests，产品程序集没有截图代码。</p>
<p><code>tests/ReadCalibFile.PluginChecks</code> 按原始事件逐条比较错误码、输出存在性、类型、数组和值，覆盖缓存保存重载、磁盘变化、刷新失败、方案作用域、坏 OutputSchema/DynamicOutData 的图验证，以及专属 WPF 渲染；新增真实 GraphExecutor 刷新后的新描述事件、匹配连线成功和改名/改型旧连线阻断。旧索引的 825 项是 2026-10-18 旧事件集下的断言总数；中间证据版为 810 项，当前 FilePath 对照证据加入后为 846 项。此计数按输出的端口和值逐项递增，随 trace 场景的输出数量变化，不是覆盖率百分比；旧案里 <code>changed-file-no-refresh</code> 执行大型 rich 文件，新案拆成单 Dynamic 同 schema 与矩阵 schema 变化，所以总数不能单独作为增减覆盖的指标。当前最新专属回归 846 项、公共配置检查 48 项、通用执行器检查 68 项通过。最新原厂运行有 154 个事件，含 32 次 Process、17 次 LoadFile；验证索引记录最新证据、文件哈希和检查数。WPF 实际 MainWindow 集成另覆盖动态端口名/类型/基数/必需性、运行值、静态卡片兼容和旧连线阻断。独立产品 WPF 宿主已消费 ExecutionEvent 与 ExecutionSessionResult 刷新当前节点运行态端口视图；不会改写保存的节点/连线。CMD 用户验收及完整集成回归待主控安排。用户确认通过后才进行中文提交和推送。</p>
<p>原厂异常 XML 可能导致空指针/不定行为；独立读取器返回可诊断错误，不复刻内存故障。框架拒绝非有限数值发布，报告兼容性错误，不把 NaN 改为 0。有限场景通过不构成任意文件、全部平台状态或逐像素界面等价的证明。</p>
<h2 id="公共配置模型迁移待手动验收">公共配置模型迁移（待手动验收）</h2><p>标定加载现提供 <code>IToolConfigurationProvider</code>，原厂 AlgorithmTab/Group 以内嵌资源解析，统一宿主创建窗口；专属代码仅适配文件选择、只读数据面板、参数和typed操作。旧专属Window仅兼容保留，不作为新架构验收证据。独立配置检查48项、受控原厂执行/真实动态连接回归825项通过，详见 <code>tests/ReadCalibFile.ConfigurationChecks/README.md</code>；通用执行器专项另68项通过。默认打开目录历史与通知已接公共服务；Remote 文件选择只完成上下文、请求参数与 mock provider 路径，真实 FTP 服务缺失并未验证。CMD 用户验收及集成全回归由主控统一安排，用户手动验收前不提交推送。</p>
