<h2 id="已接通的产品行为">已接通的产品行为</h2><ul>
<li>Group运行参数“编辑”打开独立双栏配置器，含类型/文本筛选、模块批量勾选、类别选中/新增/重命名/排序/删除、参数勾选/名称/排序/删除、多关联与同步。运行页显示分组参数，管理控件移入配置器。</li>
<li>去除ROI表格适配器，改为图像坐标中的矩形、圆、圆环、多边形图形编辑，支持移动、角点尺寸、矩形旋转、圆/环半径、多边形顶点、撤点、复制/删除、缩放/平移/全屏、数值校验、保存及取消回滚。参数区按原生默认折叠。图形绘制和事件桥接是独立WPF实现，并非原厂控件直接运行。</li>
<li>ROI预览读取该工具唯一的图像输入绑定或其唯一图像输出；不会从其他节点任取图像。NodeDebugExecutor.ResolveInput只读连接/订阅/流程输入，不执行生产者；缺失、失败、重复或类型不符均拒绝。</li>
<li>Group内部真实图像源工具通过既有IWpfToolEditorFactory创建专用窗口，宿主提供内部流程的参数应用、独立执行、结果缓存与关闭清理；流程保持在父级。没有以通用参数窗替代图像源专用窗口。</li>
<li>实际验证路径：Group内图像源→专用窗口修改InitialSN=17→关闭→Group独立运行→真实BMP宽度1296、节点SNCode=17。此为已集成插件现有能力验证，未合并插件工作线后续提交，也未验证相机硬件。</li>
</ul>

<li>当前ROI契约只有矩形、圆、圆环、多边形。原生扇形、卡尺、线、点、矩阵圆、3D及屏蔽模式未提供；图形控件的全部边/旋转手柄、归一化坐标、夹取和原生事件状态机尚未完全等价。</li>

<li>关联选择仍使用现有来源树，未完成原生DynamicRunParamRelationModulesConfigWin全部布局；输入代理/历史未分组数据为已有独立兼容行为。</li>
<li>没有本轮真实VM对照截图或差分运行记录。生成截图全部来自本项目测试渲染；图像中的BMP是固定样图。WPF检查通过不能证明原生UI/算法完全一致。</li>
</ol>

<h2 id="源码级调用与数据链复核group-运行参数-roiselecter2026-10-18">源码级调用与数据链复核：Group 运行参数 ROISelecter（2026-10-18）</h2><p>为避免将同名模板当成一个控件，本轮逐项核实了这些原始调用链：</p>
<ol>
<li><code>analysis/decompiled/Apps.XmlParser.CapabilityAudit/Apps.XmlParser.ParamTab/ROISelecter.cs</code> 显式实现 <code>IGroupRunParam.DisplayForGroupType =&gt; &quot;RoiConfigControl&quot;</code>。<code>analysis/decompiled/Apps.XmlUI/styles/paramusercontroldatatemplate.xaml</code> 的 <code>RoiConfigControl</code> 模板把当前参数对象绑定到 <code>RoiSelectControl</code>，图像宽高由参数宿主传入，<code>CanUpdateROI</code> 以 <code>OneWayToSource</code> 绑定回 <code>IROISelecter</code>；它没有另外储存一份 ROI 数据。</li>
<li><code>analysis/decompiled/DynamicObjectConfigControl/DynamicObjectConfigControl.XmlData.Extern/DynamicExtern.cs::GetSupportDisplayForGroupData</code> 对 <code>ROISelecter</code> 返回 <code>ROISelecterForGroupDecorate</code>。<code>analysis/decompiled/DynamicObjectConfigControl/Apps.XmlParser.DateForDisplayInGroup/ROISelecterForGroupDecorate.cs</code> 声明支持 <code>ROISelecter_GroupControl</code>；<code>DynamicObjectConfigControl/datatemplate/paramusercontroldatatemplate.xaml</code> 将该 key 映射到 <code>ModuleROIConfigControl</code>。故 <code>RoiConfigControl</code>（参数模板）与 <code>ROISelecter_GroupControl</code>（Group 装饰视图）是不同路由。</li>
<li><code>DynamicObjectConfigControl/Apps.XmlParser.ParamTab/GroupRunParam.cs::SelectedCommandExecute</code> 先调用 <code>Owner.GetFirstParamRelationModule(dynamicItem.NameA)</code> 定位关联模块；随后对 <code>IGroupRunParam</code> 调用 <code>GetSupportDisplayForGroupData()</code>，无专属结果时才创建 <code>CommonParamDecorate</code>，最终触发 <code>OnUpdateDecorateEvent</code>。<code>DynamicObjectConfigControl/DynamicObjectConfigControl/DynamicParamsTabControl.xaml.cs::AlgorithmTabRoot</code> 订阅事件并替换 <code>ImageDecorate</code>。行模板将 <code>CloneSource</code> 与 <code>IGroupRunParam.DisplayForGroupType</code> 交给 <code>ParamUserControl.ExternDisplayType</code>。这是源码确认的绑定/命令链，不是从截图推断。</li>
<li><code>ROISelecterForGroupDecorate.InitSource</code> 把 <code>IsStateForDrawROI</code> 设为 false 并调用 <code>SelectNone</code>；其 <code>ROIList</code> 直接转发 <code>DecorateSource.ROIList</code>。<code>ImageSource</code> 懒加载 <code>ModuleSource</code> 的 IMAGE 输入关系。选中、删除、粘贴及能力查询分别转发到 <code>IROISelecter.DoRoiSelect/DoRoiDeleted/DoRoiPaste/CanDeleted/CanCopy</code>；可见状态命令按状态选中或清空旧 ROI。<code>ROISelecter.UpdateROI</code> 仅在 <code>CustomVisible &amp;&amp; CanUpdateROI</code> 时读工具参数缓冲，按 ROI 类型更新现有模型。<code>IGroupRunParamWithMultiParams.GetAllData/SetAllData</code> 另用 <code>ROIDataStore</code> 携带参数字节、图像尺寸和可选序号；这不是普通单值写回。</li>
<li><code>DynamicObjectConfigControl/DynamicObjectConfigControl/ModuleROIConfigControl.xaml</code> 是 Group 装饰模板，声明 1150×600：左栏为 ROI 选择与运行控制，右侧 <code>RenderControlBase</code> 绑定 <code>ModuleSource</code>、原始 ROI 集合、选择/删除/复制/粘贴及尺寸事件。<code>Apps.XmlUI/Apps.XmlUI.ParamTabControl.DisplayForGroupControl/ROIConfigControl.xaml</code> 则声明 1000×600、左 380px、右侧 <code>ImageViewBox</code> 与缩放/1:1/全屏按钮。两份源码对应不同路由，不能拼作一套外观规格。</li>
<li><code>ROISelecterForGroupDecorate.RoiCopyCommandExecute</code> 的原始方法体为空；但 <code>VMBaseControls/ImageViewBox.xaml.cs::CanCopyRoi/CopyRoi</code> 已确认 <code>RoiCopyCommand</code> 只作 <code>CanExecute</code> 能力门控，真正复制由图像控件 <code>IROIClone.Clone()</code> 并保存私有粘贴对象完成；<code>PasteROI</code> 再将对象加入 ROI 列表并调用 <code>RoiPasteCommand</code>。因此不能把代理的空 execute 补成第二次复制，也不能把“execute 空”误判成整个复制功能无效。</li>
</ol>
<p>边界结论：Group 运行参数装饰器及 ROI 参数模板属于插件面向工具的公共 UI/模板能力，已由 FCR-018 登记为插件线生产、主框架消费。main 保持 Group 参数选择、运行代理、执行和数据事务责任，不在主线再建第二套插件编辑器。主线 <code>GroupComplexEditor</code>/<code>GroupRoiEditor</code> 是 <code>ParameterEditorDefinition</code> 的独立托管实现，不能充当原生 ROISelecter 的替身，也未证明会写回 VM 的 <code>CurValueA</code> 二进制协议。接通需要真实 ROI 插件先声明 ROI 种类、数量、坐标空间、图像来源、多字段/序号、应用/取消和运行会话。</p>
<p>仍未确认：装饰器首次展示的精确触发动作；Group SelfRun 各轮 ROI 参数字节刷新顺序；派生 ROISelecter 在模式/最大数量/隐藏时的具体差异。这些未用独立实现或截图外观代替原生证据。</p>

<h2 id="2026-10-19-fcr-022-undo-服务加载边界与本地历史粒度">2026-10-19 FCR-022 undo 服务加载边界与本地历史粒度</h2><p><strong>VM 服务证据边界。</strong> Group 运行参数入口 <code>analysis/decompiled/DynamicObjectConfigControl/Apps.XmlParser.ParamTab/GroupRunParam.cs::ConfigCommandExecute</code> 在调用模态编辑器前后显式执行 <code>Ioc.Get&lt;IUnRedoService&gt;()?.SetForbidRecord(true/false)</code>。另一个独立调用点是 <code>analysis/decompiled/VM.Core/VM.Core/VmModuleSet.cs::CreateLinkModule</code>：在 <code>CreatModuleByInfo</code>、<code>PreAddModuleTo</code> 和记录到 <code>_preGenerateModules</code> 期间设置 true，之后设置 false。两个可见调用点都没有 <code>try/finally</code>，且 false 是固定值而非读回先前状态；这是调用方源码形态，不能据此判断栈实现或异常后的状态。</p>
<p>实现通过应用配置动态装载：<code>analysis/decompiled/VisionMaster.Exe.Audit/app.config</code> 的 <code>UnRedoServiceImplement</code> 值为 <code>myLibs\\VM.UnRedo.dll</code>；<code>VisionMaster/App.cs</code> 从 <code>AppDomain.CurrentDomain.BaseDirectory</code> 拼接该值，<code>Assembly.LoadFrom</code>，再按 <code>IUnRedoService</code> 接口筛选类型并 <code>Ioc.Set</code>。提供的反编译树没有该 DLL、接口声明或实现类型源文件（路径检查未找到 DLL，树内 <code>rg --files</code> 也无 <code>VM.UnRedo</code> 文件）。因此 nested forbid 是否引用计数、是否全局/线程/调用作用域、服务是否维护 undo 栈、是否有异常恢复均为<strong>未知</strong>，不得称 VM 已验证抑制生效。</p>
<p><strong>当前本地历史边界（静态源确认）。</strong> <code>SubprogramCallHost.cs::CreateBoundGroupWindow</code> 为 Group 配置器提供的保存委托逐次调用 <code>doc.SetWorkflowConfiguration(Body().Id, configuration)</code>；<code>GroupRunConfigurationWindow.cs::Change</code> 在每个配置事件后立即调用此委托。<code>GraphEditorDocument.cs::SetWorkflowConfiguration</code> 相等检查后通过 <code>Edit</code> 写回；<code>Edit</code> 每次压入 <code>Capture()</code> 的完整方案快照、清空 redo、提交新文档并增加 <code>Revision</code>，<code>Undo/Restore</code> 按完整方案快照恢复。由此每次不同的即时配置写入都形成单独历史项；确认或 X 关闭不会合并或回滚。此前 F-15 测试只验确认/X 后配置保留和实际运行结果，没有连续 Undo/Redo 历史边界断言；该粒度虽由代码确定，仍标记为<strong>未完成操作级验收</strong>。</p>
