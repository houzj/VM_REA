<h2 id="不重复逆向的执行规则">不重复逆向的执行规则</h2><ol>
<li>每个新工具先在插件线清单登记原生二进制/资源、参数/UI展示键、执行与结果；用 NFI ID 指向所需公共能力。若已有共享实现，只补工具适配器，不再写公共模板副本。</li>
<li>公共配置框架证据由插件线集中维护；主线只审查与流程、Group、ROI、数据端口、导航集成有关的交界。主线对同一 <code>ButtonSelecter</code>/模板所做的既有局部实现记为过渡子集，合流时逐状态比较，不简单累计完成率。</li>
<li>交叉类型或入口先写契约差异：调用方、数据形状、生命周期、旧方案兼容、源码位置及验收样例。指定<strong>一个</strong>共享文件提交所有者；另一线提交证据和测试需求，等提交后再合。</li>
<li>主线按 NFI-01→05→07→08→09→10 的依赖顺序合流；ROI/数据形状 NFI-06 要在真实工具消费前先定形。插件线可继续独立取证和算法，不把未合公共代码视为主程序能力。</li>
<li>插件线每个工具任务必须同时列出依赖的插件公共框架能力、缺口和实际主窗口/Group消费结果；主线每个供插件使用的新接口必须用至少一个真实工具复验。不能出现“工具功能已实现但公共节点框架未接”或“框架接口已做但真实工具未消费”却宣称闭合。</li>
</ol>
