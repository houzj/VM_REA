# A01.3 Group SDK 桥接入口

`CollectionManager` 和 `ModuleManager` 的源码证据写入 `analysis/full-audit/batch1-20261107/A01/source-group-sdk-bridge-evidence.json`。

- 嵌套 Group 的托管 `ImportGroup(nProcessID,nGroupID,path,password,nIdAllocateWay)` 直接调用 `IMVS_ImportGroupModule`。任何非零返回码立即包装为 `VmException`。
- 独立 Group 使用 `IMVS_ImportIndependentGroup(handle,100000u,path,password,0u,ref IMVS_MODULE_INFO)`，返回模块信息结构，随后由 `VmSolution` 创建托管 `IMVSGroup`。
- SDK 同时暴露 `IMVS_SyncImportGroupModule`，但当前 `VmSolution.internalImportGroup` 使用的是异步 `ImportGroup` 加完成门和 `SyncWaitor` 的托管等待路径。
- 导出同时存在 `IMVS_ExportGroupModule` 和 `IMVS_SyncExportGroupModule`，样例宿主的 `SaveAs` 使用同步导出入口。

这组证据把托管调用和 native 入口参数对齐了。native 实现、回调载荷以及异步导入完成事件仍未取得，因此没有把同步 API 的返回结构推断成嵌套 Group 的回调结果。
