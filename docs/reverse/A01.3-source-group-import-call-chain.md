`IMVSGroupTool.LoadIndependentGroup` 只转调 `VmSolution.LoadIndependentGroup`。独立 Group 路径先初始化临时方案，再调用 `mCollectionManager.ImportIndependentGroup(100000u, path, password, 0u)`，把返回模块名强制设为 `IMVSGroup`，创建托管模块，挂到 `VirtualPro`，写入文件路径和密码并加入模块集合。异常通过 `GetVmException` 重新抛出。

嵌套 Group 路径先检查完成门、父模块类型和 disposed 状态。文件路径存在时先调用 `IMVS_GetGroVersion`，低于 V4.0.0 直接拒绝，低于当前版本则要求 `CompatibleTool.exe` 及配置并执行隐藏的 VMGroup 转换。随后非复制路径注册 `RootOperation`，保存 `importGroupModuleSet`，按父类型调用 `mCollectionManager.ImportGroup`，将完成门置为 false 后等待 `SyncWaitor`。回调产出的 `importedGroupModule` 被设置 Parent、文件路径和密码，并按条件登记 `ModuleUnRedoOperation`，最后清理暂存字段并返回。

错误路径只确认了错误码格式化、失败提示和日志记录。Server 回调如何填充 `importedGroupModule`、完成门的真实线程时序以及 native payload 解码仍是运行时未知项。本证据支持调用链恢复，不把未知部分实现为推测行为。
