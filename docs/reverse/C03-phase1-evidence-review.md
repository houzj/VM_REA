## 首批实施计划

执行记录见 [C03 同输入差分交付](C03-same-input-differential-20261110.md)。

1. **固定对照输入。** 记录原厂宿主、Blob DLL、直接 SDK 的版本和 SHA-256，以及同一图片、方案、节点参数和 ROI/Mask 初态。复核宿主与直接 SDK 两侧能否重现历史数值。若无法重现，先找出输入或环境差异。
2. **定位 SDK 调用前的第一处差异。** 在已注册的原厂流程中沿 `ProcessAlg` 核对活动分支、区域集合基数和 SDK Run 前的输入宽高、步长、像素格式及缓冲哈希。若走生成掩膜路径，记录候选入口 `IMVSBlobFindModu.dll+0x9C80` 的实际寄存器、第五栈参数和生成缓冲，和同输入的直接 SDK 路径逐项对照。
3. **核对结果投影。** 保存 SDK GetResult 的完整向量、BinaryImage/BlobImage 缓冲哈希及输出标志。记录首个可重复差异和对应调用边。若原厂流程未注册或关键缓冲不可读，记录失败位置，保持根因开放。
4. **按差异归属派工。** 涉及公共 ROI/订阅/结果回写合同的证据由 main 负责，工具专属行为形成插件线交接。只有定位到已证实的行为差异后才拟定代码变更，验收包括同输入差分与本地保存、重开回归。C01 历史复跑另需恢复测试工程及相同输入。
