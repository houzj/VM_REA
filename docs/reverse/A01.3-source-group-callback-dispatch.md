# A01.3 Group 回调分发与模型落地顺序

回调证据写入 `analysis/full-audit/batch1-20261107/A01/source-group-callback-dispatch-evidence.json`。

`CVmObjectBase` 将平台事件 792、793、800、801、802、824 分别解包为 Group 开始、结束、进度、模块 ID/GUID、接口文件和 UI 数据结构。`ModuleManager` 构造函数订阅这些事件，`TempVmSolution` 再把开始、进度、UI 数据和结束事件转接到 `VmSolution`。

结束载荷包含进程 ID、客户端类型、路径、错误码、新 Group ID 和新名称。`VmSolution` 的处理顺序已经由源码确认。它先构造公共结束事件并触发订阅者，只有错误码为零时才构造 `IMVS_MODULE_INFO`、调用 `AddModuleByInfo`、设置 Parent 和 Ready 通知，最后把 `mbImportGroupEndFlag` 设为 `true`。UI 数据回调只保存 Group ID 和解码后的名称。GUID 和接口文件事件目前只有分发链，未见同一处理器中的模型落地。

这补齐了 A01.3 的静态回调顺序和结构字段。回调线程、native 消息生产和成功运行时仍需 Server 证据。
