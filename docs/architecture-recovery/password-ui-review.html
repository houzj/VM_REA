方案密码窗口：声明、注册与状态效果

33个原件方法、22处挂接代码；注册代码确认、BAML映射候选和运行时激活分别记录，完整链未关闭。浏览器呈现未验收。

Constructors call InitializeComponent; original LoadComponent URI is encryption.xaml/decryption.xaml. Connector switch uses connectionId-1 and contains typed ldftn → delegate construction → event add for preview input, key, text change, paste CanExecute, and buttons.

Registration code is confirmed in original CIL. Local XAML declarations are matched as candidates by root type/event/handler and named field where available; two unnamed Encryption CommandBinding declarations stay ambiguous. Original BAML connection IDs and runtime activation are not confirmed.

Preview text uses ^[0-9a-zA-Z]*$; PreviewKeyDown handles Space. Paste CanExecute is explicitly true and Handled=true. TextChanged validation is wired to visible TextBox fields; PasswordBox does not gain that same TextChanged handler from these connectors.

Invalid visible text copies Changes and DelPasteText uses change[0], removes its AddedLength at Offset and repositions selection; it does not sanitize every change. Empty change-array, recursion, clipboard and WPF routing semantics remain unverified.

Eye toggle setters copy PasswordBox.Password to TextBox.Text on true and copy back only on false, switching visibility. Apply reads PasswordBox.Password; XAML has TwoWay Text declarations but actual binding retention/update order while visible is unverified.

Decryption OnKeyDown first calls base, then applies only for Key numeric 6 (Return in source) and OriginalSource is PasswordBox. It does not set Handled in this body. Encryption has no local OnKeyDown override in selected type metadata.

Encryption Apply checks nonempty and equality, then returns stored PasswordBox value with DialogResult=true; Cancel returns empty string with DialogResult=true. Decryption Apply invokes SDK CheckPassword, nIsCorrect=0 shows error, nonzero stores value and true; Cancel is false.

These types have no local closing handler/body. BaseWindow close/title-bar bodies are now recovered separately in base-window-review; original BAML selection and WPF nullable modal result internals remain open. No equivalence is inferred between Cancel and window close.
