﻿# N图像标定：独立工具线配置与数值接线

当前状态

本轮按工具清单独占 IMVSNImageCalibModu，没有把 N 点标定拆成多个并行分支。产品已新增公共配置模型、真实像素识别→批次求解→37个原厂输出、矩阵修正、模块文件导出及公共显示接线；工厂为 new NImagePlugin()，宿主注册由根线统一完成。没有设备测试，没有修改其他工作树，没有提交。

原厂证据

  • 直接复制原厂 IMVSNImageCalibModuAlgorithmTab.xml 为 Resources/NImageAlgorithmTab.xml，原始 SHA256 a83474fec309e81eaed70366ad813a2d5a06a02a8dcc9f12d398079e16e5c3c3。原文件直接声明基本参数、运行参数、结果显示三个 Tab；结果显示内链接公共 TextDisplayGroup。不是另造结果文本页。
  • 原厂 footer 只有生成标定文件、清除图像、确定。XML 没有执行、连续执行按钮；原有 NImageWindow 的这两个按钮不作为生产接入依据。
  • CanTriggerRun 仍由公共模型和 ToolConfigurationExecution 处理，不能因为没有执行 footer 就漏掉修改参数后的原厂触发行为。
  • HidePhysicInfoOperation 来自原厂控件源码；REA 静态证据仍为 ev_47d8fe724a3d57ef879aa778e0fb1e24e74df258e6f6f9266459af03c8e39ca6。原始 parser 动态记录继续保留于已有 UI evidence，静态分析不冒充桌面运行。
  • 默认标定板采用原厂AlgorithmTab的 0x7（生产配置初始化值）；受控模块裸构造的GetParam曾返回6，两者不是同一初始化阶段，不能把裸构造值当作打开配置后的默认值。
  • SetParam RVA 0x229d0：CalibPathName 的空路径被拒绝；它不会加载文件，也没有 SaveCalibPath 的 .xml 后缀处理。废弃的 GrayContrast、SubpixelWinAuto、SubPixelWindowSize 写入直接返回成功、不会影响算法；保留源隐藏字段。
  • ProcessAlg RVA 0x21450：可选调用原厂 MatrixFix，把算法矩阵、图像点、物理点依次交给修正工具。新受控 SDK 运行见 MatrixFix 原厂五案例，包含单位、仿射、透视、非单位 h8 和全零矩阵；全零矩阵也返回成功。
  • CareraMove 的模块字段 0x16104 仅出现在构造、Set/GetParam 和 WriteXmlData。保存函数 RVA 0x230e0 仅在恰好三张旋转图且方向关系有效时翻转文件 RotDirectionState，并通过该关系翻转 IsRightCoorA；其余旋转数保留 -999 关系，不改变矩阵。原厂12帧模块运行、两次保存均成功，确认方向和handedness分别由1变为-1，见 三旋转文件证据。这是受控实例的原厂方法调用，不是完整平台 Init。
  • 原厂 7cb4c0 的相邻旋转图匹配保留前图全部点：后图缺失网格 ID 使用最近格点、平均相邻格长和累计归一化轴外推。完整相邻点修正后，2/3/5旋转图中心和径向误差的15项官方SDK差分通过。
  • 原厂 7cf3f0 在仅旋转分支保留初始化的全零9元素矩阵，同时成功返回真实中心和误差。新鲜进程官方SDK的2/3/5张旋转图均确认该行为，不用单位矩阵伪造。

验证边界与剩余验收

生产入口为 NImagePlugin/NImageConfigurationProvider，不使用旧 NImageWindow。实际像素批次、跨流程同NodeId隔离、清图、次批清旧矩阵、真实XML、显示轨迹、取消和缺失修正点均有执行验证。数值阶段覆盖2/3/5旋转与9平移+0/2/3/5旋转的误差、机构误差、方向向量、离散最大索引及告警状态。相邻旋转缺点外推与公共归一化的源码修正解决了此前差异，没有按案例硬编码。7d12e0四图子集筛选的逆投影、sqrt和评分累加也改为原厂float顺序，218项仍通过；该评分修改单独不消除文件矩阵差异；真正消除项为后续完整float逆矩阵，两个实验没有混为一谈。

这些验证不代表所有原生条件完全一致：标定板识别是独立实现，任意畸变/裁切/噪声仍需扩大样本。此前168点板矩阵仅37/81分量位一致，三旋转文件h2差+0.0001025864超出原1e-4门槛；已追到共享7fcf60/7fd4e0世界归一化矩阵必须使用完整float伴随求逆，而不是数学等价的1/sw、wx/wy。四变体隔离验证后由根线接入公共核，当前板矩阵81/81及文件矩阵9/9 float位一致，原1e-4断言恢复，并新增位断言，未扩大门槛。参见完整float逆矩阵证据。RGB已补真实彩色原厂SDK差分：9图每通道不同，RGB24与76/150/30>>8生成的Mono8输出JSON完全一致，见 彩色运行证据。生产输入声明DataKind.Image并消费公共VisionCore.ImageColorConversion.ToMono8，不引用图像源工具私有实现。该证据仅覆盖已测彩色场景，原厂内部转换静态调用链仍未知。原厂桌面UI差分与用户手动验收仍需宿主启动。无设备测试。
