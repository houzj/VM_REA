J12 未关闭条件与下一探针

J12 状态：confirmed-current（存在普通流程实际同步 CPU 路径及可复验成本）＋ blocked-exact-evidence（缺当次或可重现受控实例的 UI 线程栈/等待链和分段时间线）。本线不擅自改动调度：在没有对原版 SyncExecuteOnce(..., bIsWait:false, ...) 的返回/回调生命周期与当前方案持有/取消语义做差分前，把整个执行器简单塞入 Task.Run 可能引入新的竞态或改变回调顺序。它是可优先修的结构性风险，不是这次用户事件的已证根因。

下一步由 main 单写入者在自有受控副本/实例加入测试宿主诊断：固定方案和 EXE SHA；UI Dispatcher 心跳记录间隔与线程 ID，给 doc.Changed、GraphValidator、RenderGraph（区分路由缓存命中/失效）、RefreshRight/ToBitmap、配置构造/提交、RunConfiguredTool 前后、scope.RunRequested/结果回调打起止时间；原样保存超阈值时间线。按空闲、文件夹事件、单次/连续运行、配置编辑分组。若重现，仅给受控进程取 UI 线程栈及等待链；对比在暂停点是否为本地计算、I/O、Native SDK、锁或 Dispatcher 等待。不能以“没有重现”宣称问题已修，也不能拿测试宿主结果冒充用户那次原进程定因。
