# 已接入工具的架构链路聚合审核

日期：2026-10-20。范围是当前 `src/VisionEditor/tool-catalog.json` 工作区快照中有 `ModuleId` 的 18 个工具和 `workflow.subprogram` Group；目录尚未映射的条目不算已接入工具。`HEAD` 目录仅有 16 个工具加 Group 的 17 个非空 ID；另两个 `vision.n-image-calibration`、`vision.camera-mapping` 来自已有**未提交**目录改动，因此本表把它们列为待核工作区对象，不称已交付基线。工具实现仍须按各自生产注册及源码复核。

## 先审一次的共享主链

主线只建立一份 `目录/注册→创建→配置宿主→端口/候选/连接/订阅→真实载荷校验→调度/SelfRun→结果/错误/释放→显示→保存/重开/撤销→Group 边界` 的代码级证据。每条边记录原始程序集/资源的精确成员或地址、当前生产消费者、负例和未知。某工具复用此证据时引用**具体边及证据版本**，只补该工具的端口、参数、资源、算法、输出和异常差异；共享边改变才回归受影响工具，不为每个工具重写一次相同框架报告。UI、后台和算法都在逐工具增量内；不能用共享宿主通过替代算法符合性。

| 线/唯一归属 | 聚合依据与所属工具 | 必须新增的差异证据 | 首条贯通链 |
|---|---|---|---|
| A 图像生产与像素消费（4） | 图像源 `vision.image-source`、多图采集 `vision.image-acquisition`、缓存图像 `vision.image-buffer`、图像二值化 `vision.image-binary`；共享 IMAGE 来源、帧格式、缓存/订阅与下游图像类型边 | 各来源的帧生命周期与像素格式；二值化配置 UI、五模式原生算法、Mask/ROI、失败/释放；多图来源的特有索引与同步 | 图像源→缓存/二值化→实际下游及 Group；RGB、Mono8、可选 Mask 正负例 |
| B 标定数据生成（6） | N点标定 `vision.n-point-calibration`、N图像标定 `vision.n-image-calibration`、标定板标定 `vision.calibration-board`、相机映射 `vision.camera-mapping`、映射标定 `vision.map-calibration`、畸变标定 `vision.distortion-calibration`；共享标定样本/图像输入、教学或拟合、标定结果输出合同 | 每种样本结构、坐标/精度、原始求解器/原生分支、专属编辑器事件、错误状态和产出格式；N点编辑耗时只归对应 UI 链 | 原始输入→标定结果→真实消费者；多图与设备分支缺证据时单列 |

四组共 `4+6+5+4=19`，每个有 ID 的目录项恰好有一个**审核归属**。跨组链由上游组提供带类型和哈希的交付证据，下游组只核其独有消费边；交叉验证不重复计算工具数或 J01–J12 闸门。原始资源/函数若供多组复用，主线统一索引和结论，发现反证后一次修订并列出受影响组。

## 审核顺序与关闭口径

1. 主线先冻结共享边的原版证据、当前源码和测试夹具；优先 A 的图像源→二值化及 D 的 Group 真消费，解决输入源、RGB/Mono8、可选 Mask 与卡顿的已知偏差。
2. 四线按依赖并行取独有成员/资源和实际调用路径；B 的标定结果格式交付后 C 再核消费差异。槽位不足时根线保留合流能力，空出的槽位续下一组，不重复派发仍在运行的任务。
3. 每个工具只在共享链引用有效、特有 UI/后台/算法及错误释放源码取齐、差异有责任方和自审核后，才标代码审核完成。原生深层函数未恢复则记录精确地址/缺口，不能用单夹具成功补全。人工/设备验收单列。
4. 逐轮只报告新关闭的**共享边或工具特有分支**，附证据路径和哈希；没有新增闭合不得因报告篇数增加百分比。旧框架实施指标 `41/96=42.71%` 单独报告，联合审核本身不改变其分子。

本表是审核路由和去重规则，不改变主线/`tool-plugins` 的文件所有权。跨项目需修订合同，先写 FCR，由用户决定插件合流；不操作另一工作树在制文件。
