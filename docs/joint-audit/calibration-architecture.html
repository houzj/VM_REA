标定加载：最关键的三条虚线

① SDK 派发

IMVS_SetParamValue 如何定位模块并调用 CMyAlgorithmManager::SetParam(FilePath)。两端已有原体，中段仍待取回。

② 动态输出通知

LoadFile 改变输出集合后，已加载的 VmModule.Outputs 如何获知并重建。

③ 旧 Group 订阅

原版刷新文件时，旧动态叶引用按对象、名称还是显式重绑处理。不能把“手动改名”的历史代码当成这个入口。

当前实测给出的警示

文件输出从 OldMatrix 改为 NewMatrix，旧订阅未自动改名：

  • 暖态：坐标系可保留上一轮矩阵，Group 仍显示 Success。
  • 冷态：矩阵未初始化，坐标系与 Group 失败。
  • 显式改 schema + 订阅后，撤销、重做、重开才按新叶运行。

因此“流程成功”不等于“本轮新文件已被消费”。查看 13 项探针

分工要跟随数据所有权

main：工具箱/图、连接与订阅验证、调度、owned Group、文档历史、方案生命周期与通用显示宿主。

tool-plugins：工具配置模型、专属 UI、参数/ROI、执行会话、算法、结果 DTO 和工具显示适配。

跨界合同先记入 FCR 台账；由用户决定合流。当前页没有修改插件工作树。

以后怎样才算一项追完

  1. 列出原版入口、控件事件、调用者与被调者。
  2. 追每个参数/订阅的字段读写、分支、SDK/原生处理。
  3. 追输出到显示、Group、历史、重开和释放。
  4. 把当前代码逐边映射；同输入做成功、失败、暖/冷、撤销/重开探针。
  5. 只有整条可审的链闭合才宣布工具代码级完成；缺体先取回，不以局部绿灯补全。
